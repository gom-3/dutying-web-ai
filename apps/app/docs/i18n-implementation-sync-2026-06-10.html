일본어/영어 국제화 구현 싱크

작성일: 2026-06-10 · 범위: apps/app 웹 프론트엔드 · 기준 브랜치: origin/develop

완료 범위

언어 리소스

ko, en, ja locale 구조를 확장하고 타입 기반 번역 키를 적용했다.

화면 전환

로그인, 회원가입, 온보딩, 듀티, 근무표 생성, 신청근무, 병동 설정, 프로필, 네비게이션 문구를 국제화했다.

모델/공유 레이어

toast, confirm, API fallback, export 파일명, 분석 이벤트 라벨, 프로필 alt, 병동 표시 fallback을 locale 기반으로 변경했다.

한국어 보존

기존 한국어 문구는 카탈로그의 ko locale 기준으로 유지하고, 관련 테스트는 한국어로 명시 고정했다.

2026-06-10 origin/develop 동기화

  • codex/i18n-origin-develop-sync worktree를 origin/develop 최신 기준으로 생성해 원본 dutying-web 작업 트리와 분리했다.
  • 최신 develop의 로그인 비밀번호 재설정, 온보딩 근무표 업로드, 병동 관리자 권한, 초기 근무표 확정 흐름을 보존한 상태에서 i18n 변경을 재적용했다.
  • 수동 locale 객체와 generated resource의 이중 타입 기준을 끊고, resources.generated.ts가 typed translation key의 기준이 되도록 변경했다.
  • 서버/LLM 검증 응답에서 내려오는 message_key, message_args를 @dutying/api 타입과 웹 표시 포맷터에 반영했다.
  • 충돌 파일은 모두 해소했으며 git diff --name-only --diff-filter=U 결과는 비어 있다.

2026-06-10 카탈로그 운영 전환

  • apps/app/i18n/catalog/messages.csv를 웹 번역 원본 카탈로그로 생성했다. 현재 웹 런타임 기준 1,688개 메시지를 보존한다.
  • apps/app/i18n/catalog/terms.csv를 추가해 병동, 근무표, 신청 근무, 확정 근무표처럼 반복되는 핵심 용어를 관리한다.
  • apps/app/src/shared/i18n/resources.generated.ts를 생성물로 두고, src/i18n.tsx는 이 generated resource만 읽도록 전환했다.
  • pnpm i18n:catalog:check는 중복 키, 필수 메타데이터, interpolation mismatch, 서버 메시지 표시 정책 누락을 검사한다.
  • pnpm i18n:export:web는 카탈로그에서 웹 런타임 리소스를 재생성한다. generated 파일을 직접 수정하지 않는다.
  • pnpm i18n:review는 번역 전문가가 한국어·영어·일본어를 대조할 수 있는 apps/app/i18n/review/i18n-review-board.html을 생성한다.
  • pnpm i18n:sync-server-errors는 Spring 서버의 messages_ko/en/ja.properties를 platform=server 행으로 카탈로그에 동기화한다.
  • 빈 문자열은 일부 UI 문장 조립에서 의도적으로 필요할 수 있어 emptyLocales에 명시한다. 명시되지 않은 빈 값은 검수 경고로 남긴다.

웹-서버 에러 계약 반영

  • 서버 에러 응답은 code, message, messageKey, displayPolicy, messageArgs, locale, requestId, traceId 구조를 기준으로 한다.
  • 웹 axios interceptor는 displayPolicy를 해석해 클라이언트 번역, 서버 localized text, debug-only fallback을 구분한다.
  • 웹·앱 공용 타입 계약을 위해 @dutying/api와 @dutying/api/error에서 에러 응답 타입을 공개한다.
  • JWT/security filter 레벨 에러도 서버의 공통 에러 응답 writer를 사용하도록 정리했다.
  • 서버 raw custom message는 한국어 locale에서는 보존하고, 영어/일본어 locale에서는 표준 message source 번역으로 fallback하도록 했다.

핵심 구현 결정

  • UI 컴포넌트는 useTypedTranslation으로 타입 안전한 키만 사용한다.
  • 훅/순수 모델처럼 React 훅을 쓸 수 없는 곳은 초기화된 i18n.t를 사용한다.
  • 일본어 기본 근무명 변경에 대비해 name === "오프" 비교를 isOff 플래그로 교체했다.
  • 날짜/시간/이름 정렬은 현재 언어의 locale을 사용해 일본어/영어 표시와 정렬 품질을 높였다.
  • 긴 영어/일본어 문구가 버튼, 카드, 모바일 랜딩 히어로에서 깨지지 않도록 줄바꿈과 overflow 안전 장치를 보강했다.
  • i18n 초기화는 document/localStorage가 없는 테스트·SSR 유사 환경에서도 안전하게 동작하도록 가드했다.

비즈니스/운영 고려

  • 한국어 사용자는 기존 화면과 플로우를 유지한다.
  • 일본어 사용자는 병동/근무/신청/설정 주요 업무 화면에서 영어 fallback 노출을 최소화했다.
  • API 요청에는 locale/service-region 헤더가 실려 서버 로그, 정책, 향후 국가별 기능 분리에 활용할 수 있다.
  • 문구는 기능 단위 namespace로 묶어 번역 검수, A/B copy 변경, 국가별 문구 정책 반영이 쉽도록 했다.

잔여 리스크

  • 스캐너 기준 한글 하드코딩은 0개지만, 실제 고객 데이터의 매우 긴 병동명/간호사명 조합은 출시 전 샘플 데이터로 추가 시각 QA가 필요하다.
  • 외부 API가 한국어 에러 메시지를 내려주는 경우에는 서버 국제화가 별도로 필요하다.
  • 일본 병원 현장 용어는 운영 검수 후 ja.ts 문구를 더 자연스럽게 다듬을 수 있다.
