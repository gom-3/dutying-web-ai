# 조절 요청 실패 안내

- 문제: 요청 처리 결과 검증 실패와 응답 오류 모두 같은 요청의 재시도를 권하고, FAILED 상태 전체를 재시도 대상으로 분류한다.
- 문구: 진행은 “바꾸고 싶은 내용을 확인하고 있어요”, 실패는 “요청을 처리하지 못했어요”로 안내한다. 근무표가 바뀌지 않았음을 알리고, 요청을 한 가지씩 나눠 수정하거나 표를 직접 수정할 수 있게 한다. 입력이 잘못됐다고 단정하지 않는다.
- 복구: MODEL_TIMEOUT만 같은 요청 재확인 버튼을 제공한다. 모델 응답 검증 실패·원인 미확인 실패는 요청 수정과 표 직접 수정으로 연결한다. 연결 오류의 원인을 일시적이라고 단정하지 않는다.
- 범위: 웹의 한국어·영어·일본어 문구 및 오류 복구 UI. 서버·LLM·DB·배포는 변경하지 않는다.
- 확인: 실패 종류별 버튼과 콜백, 요청 입력 보존, 자동 실행 방지, 기존 조절 화면 테스트를 로컬에서 검증한다.

## 검증 결과

- Vitest 관련 6개 파일, 320개 테스트 통과. 기존 React act 경고가 출력되지만 실패는 없다.
- `pnpm --dir apps/app exec tsc -b` 통과.
- `git diff --check` 통과.
- 서버 응답 오류 후 요청 입력 보존·수정창 포커스·자동 실행 방지, 해석 검증 오류 후 원문 복원, 시간 초과의 재확인 경로 검증.
- Flyway migration 없음. 운영 배포는 수행하지 않았다.
- Actions 중복 검증 비용을 피하기 위해 커밋에 `[skip ci]`를 사용한다. 외부 호스팅의 빌드 생략 여부를 뜻하지 않는다.
