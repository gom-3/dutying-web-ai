# 자동채우기·근무표 수정 안내 문구 통일

## 목적

근무표 준비·요청 확인·계산·결과·복원·저장·확정의 한국어 안내를 누구나 이해할 수 있는 말로 통일한다. 문구를 바꾸더라도 오류의 원인, 적용 여부, 보호할 근무, 버튼 동작, 저장·확정의 의미를 바꾸지 않는다.

## 기준

- 기능명: 자동채우기, 근무표 수정. 자동완성·자동 채우기·조절 표현을 혼용하지 않는다.
- 사용자 용어: 휴무, 근무 조건, 변경안, 칸, 기록. 해석·후보·셀·실행 계획·판본·해시 등의 내부 용어는 실제 상황을 설명하는 표현으로 바꾼다.
- 설명은 ~해요체, 요청은 ~해 주세요체. 버튼은 실제 동작을 나타내는 짧은 말로 쓴다.
- 실패는 확인한 사실 → 근무표 영향 → 가능한 다음 행동 순서로 안내한다. 모르는 원인을 입력 오류·조건상 불가능·일시 장애로 단정하지 않는다.
- 결과 확인과 새 계산, 표 반영과 최종 확정은 명확히 구분한다. 재시도의 성공을 보장하지 않는다.
- 간호사·날짜·인원·횟수 치환 자리와 번역 키, 요청/응답 코드, 상태값, 근무 코드는 보존한다. 실제 간호사·근무 이름은 바꾸지 않는다.
- 이미 명확한 라벨은 유지하되 모든 대상 문구를 검토한다. 다른 언어의 문구는 이 한국어 정리 작업에서 임의로 다시 번역하지 않는다.

## 범위와 검증

웹 AI 전용 한국어 번역과 자동채우기 화면 번역을 원본 카탈로그 및 기존 한국어 파일과 함께 갱신한다. 서버가 반환하는 고정 한국어 안내도 같은 기준으로 검토한다. LLM 프롬프트·응답 스키마·스케줄 계산·보호/승인 규칙을 바꾸지 않는다.

치환 자리 보존, 어려운 내부 용어 잔존, 카탈로그 일치, 기존 화면/모델 테스트, 타입 검사를 수행한다. 문구 변경과 실제 동작 변경을 구분하고 관련 문서에 변경 전후를 남긴다. Flyway migration 없음.

## 반영·검증 결과

- 자동채우기·근무표 수정 전용 문구와 함께 쓰는 근무 조건 화면을 포함해 한국어 1,164개를 검토했다. 앞서 조사한 원문 기준 379개를 개선하고, 명확한 785개는 유지했다. 코드 반영안 비교는 `client-schedule-copy-improvements-2026-11-01.html` 문서에 있다.
- 이전 문구와 현재 문구의 모든 치환 자리가 일치한다. 원본 카탈로그와 생성 번역을 함께 갱신했으며 다른 5개 언어의 기존 문구는 바꾸지 않았다. 번역을 다시 생성하면서 카탈로그에 이미 있었지만 생성 파일에 빠졌던 personalExclusionPreset 키가 함께 포함됐다. 구분한 계산 버튼에 영어·일본어를 추가했다.
- 재계산·요청 재확인·목록 다시 불러오기는 서로 다른 문구로 구분했다. 서버의 새 한국어 힌트와 예전 문구를 모두 같은 사유로 분류하도록 호환 처리를 추가했다.
- 근무표 화면·모델·번역 관련 99개 파일 및 새 힌트 호환 2개 사례 검증 완료. 기존 React act 경고는 있으나 남은 테스트 실패는 없다. TypeScript, 카탈로그 검사, 수정 파일의 Prettier, git diff 검사 통과.
- 보호할 근무, 입력 보존, 실행·반영·복원·확정 권한, API 상태, 스케줄 계산과 LLM 프롬프트는 변경하지 않았다. Spring과 LLM의 고정 한국어 안내는 별도 PR로 함께 정리한다. Flyway migration 없음.
- 비용 정책에 따라 커밋에 `[skip ci]`를 넣어 로컬 검사와 중복되는 Actions 실행을 피한다. 다른 호스팅 제공자의 빌드 생략을 뜻하지 않는다. 운영 배포는 수행하지 않았다.
