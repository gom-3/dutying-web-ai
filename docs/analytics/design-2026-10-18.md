# .ai 유입·활성화 측정 설계

## 확인된 문제

2026-10-18 gom3.official@gmail.com의 GA 계정 gom (276538360)에서 확인했다.

| 대상 | 확인된 상태 |
| --- | --- |
| 운영 .ai 웹 | GA4 G-94QM502EQF, Meta Pixel 225085720489207, Cloudflare Insights 로딩 |
| 기존 dutying-web | 속성 394593452, 스트림 5847022598, URL www.dutying.net, 측정 ID G-94QM502EQF. 최근 48시간 수신 활성, 향상된 측정 꺼짐 |
| dutying-ai | 속성 551586530. 최초 확인 시 웹 스트림 없음 |
| .ai 앱 | Android 스트림 15500007523, iOS 스트림 15500030482. 최근 48시간 수신 없음. Flutter에는 Firebase Core/Messaging만 있고 Analytics 패키지 없음 |

.ai 웹이 레거시 .net 속성으로 전송되고 있어 새 속성에서 웹 실적을 확인할 수 없었다. 과거 데이터는 394593452에서 hostname 필터로 분리해야 하며 신규 속성으로 자동 이동하지 않는다. 최초 열었던 개인 계정의 신규 측정 화면은 공식 계정 접근 상태를 나타내는 것이 아니었다.

## 외부 설정에 적용한 변경

551586530에 `Dutying AI Web` 생성: URL https://www.dutying.ai, 스트림 16150940090, 측정 ID **G-WT44BR53VN**. 기존 .net 태그와 결합하지 않았다. 향상된 측정은 끄고 코드에서 필요한 이벤트만 전송한다. 레거시 속성·스트림은 변경하지 않는다. 새 스트림 생성은 웹 배포 및 실제 수신 완료를 의미하지 않는다.

## 최소 코드 변경

1. .ai 운영 호스트만 GA/Meta를 전송한다. 개발·프리뷰·알 수 없는 호스트·.net을 제외한다.
2. 새 .ai 측정 ID를 기본값으로 사용한다. 배포 환경의 레거시 `VITE_GA_TRACKING_ID`는 의도적으로 무시한다. 다른 .ai 스트림을 지정할 때만 `VITE_AI_GA_TRACKING_ID`를 사용한다.
3. GA 초기화의 `send_page_view`를 false로 두고 실제 라우터에서 표준 `page_view`를 한 번 보낸다. 별도 history 인스턴스는 제거한다. 정적 랜딩도 초기화 후 동일 이벤트를 전송한다.
4. page_location은 origin/path와 허용된 UTM·광고 클릭 ID만 포함한다. 토큰·이메일 등 임의 query/hash는 제외한다. UTM 값은 영문·숫자·공백·`_.~-`로 200자 이내여야 한다. query/hash만 바뀌면 추가 조회로 세지 않는다.
5. `web_cta_click`, `app_store_click`은 클릭이며 설치/가입으로 간주하지 않는다. 기존 이벤트 이름은 유지한다.
6. GA4 Data API 집계를 로컬 대시보드 HTML/JSON으로 저장한다. 오늘 제외 최근 28일과 이전 28일, 속성 시간대, hostname 필터, 기간 사용자 집계를 사용한다. API 인증 전에는 미조회로 표시한다.

## 대시보드와 AI

유입·활성·캠페인·이벤트·데이터 품질을 구분한다. 광고비/매출/앱 설치가 없는 상태에서 CAC/ROAS나 통합 퍼널을 만들지 않는다. 현재 대시보드의 AI 브리프는 출처·시간대·품질 제한이 포함된 집계 JSON 복사이며 자동 LLM 해석은 아니다.

GA Ask Advisor는 기존 속성에서 자연어 탐색을, PostHog AI는 제품 분석 및 대시보드 작성을 지원한다. 초기에는 기존 GA4를 바로잡고 중복 SDK를 늘리지 않는다. 읽기 전용 Data API 인증 및 1회 정상 집계 검증 후 매일 자동 갱신과 주간 요약을 구성한다. 이 변경에는 스케줄 설치를 포함하지 않는다.

## 검증과 남은 작업

운영/개발 호스트 경계, 레거시 ID 무시, UTM 보존/민감 query 제외, 첫 진입/화면 이동/뒤로가기, CTA destination, 정적 랜딩 hydration, 보고서 필터/기간/페이지네이션/오류/HTML 주입 방어를 테스트한다. 운영 배포 후 새 스트림의 DebugView/실시간 수신을 확인해야 한다. 앱 SDK 연결과 Search Console/광고/매출 연동은 아직 수행하지 않았다. DB 변경/Flyway migration 없음.
