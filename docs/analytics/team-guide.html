현재 범위

Google Analytics·Search Console 읽기 전용 조회는 검증했습니다. 새 이벤트는 코드 배포 이후부터 수집됩니다. Meta는 브라우저 조회까지 가능하며 API 연결은 완료하지 않았습니다. 광고비·결제·유저별 연결을 검증하지 않아 CAC/ROAS나 웹·앱 합산 사용자 수를 확정하지 않습니다. 예약 작업은 사용하지 않습니다.

역할별로 무엇을 보나요?

역할확인할 질문의사결정과 기준
PO / PM“최근 30일·1년·월별을 비교해 유입·가입·첫 근무표 확정의 변화와 다음 실험을 알려줘.”사용자 기반 순차 퍼널·활성화·코호트 재방문. 표본과 수집 범위를 먼저 확인하고 우선순위와 성공 기준을 정합니다.
디자이너“소스·기기·랜딩별로 어떤 CTA가 눌리고, 가입 과정에서 어디를 추가 관찰해야 하는지 알려줘.”CTA 클릭은 의도이며 설치·가입이 아닙니다. 집계만으로 화면의 원인을 단정하지 않고 사용성 검증 가설을 만듭니다. 세션 녹화·개별 사용자의 화면 재생은 연결돼 있지 않습니다.
개발자“새 성공 이벤트가 운영에 들어오는지, 개발 트래픽·중복·인증 경유가 섞이지 않았는지 확인해줘.”API 성공 이후만 발행. DebugView·실시간·API 집계를 순서대로 검증하고 이벤트 사전과 수집 버전을 함께 관리합니다.

볼 수 있는 화면

  • AI 대화: 이 환경의 Google Analytics 연결과 통합 조회 도구로 질문별 데이터를 확인합니다. 팀원은 자신의 GA 권한과 AI 연결이 필요합니다. 이 컴퓨터의 인증이 다른 팀원에게 자동 공유되지는 않습니다.
  • 로컬 웹 집계 화면: 저장소에서 생성한 artifacts/analytics/index.html. 최근 30/90/180/365일, 월별, 웹·앱 서비스별, 기기·운영체제별로 방문과 사용 행동을 비교합니다. 의미 있는 관찰·수집 공백·실제 관측된 이벤트를 먼저 확인합니다. 검색 집계도 포함하지만 Meta·광고비·매출은 미연결입니다. 생성 시점의 집계이며 로컬 서버에서 최신 데이터 가져오기로 갱신합니다.
  • Google Analytics: 새 .ai 속성 551586530의 보고서·탐색·DebugView. 과거 .ai 웹 실적은 기존 속성 394593452에서 .ai hostname으로 필터링합니다.
  • Search Console: sc-domain:dutying.ai의 검색어·페이지·노출·클릭.
  • Meta Business Suite: dutying_official 도달·상호작용. 해당 자산 권한이 필요합니다.

로컬 분석 화면 주소는 http://127.0.0.1:8795/ 입니다. 현재 팀 공용으로 호스팅된 통합 대시보드는 없습니다. 이 HTML 가이드는 저장소에서 내려받아 브라우저로 열 수 있습니다. 실제 지표 파일과 인증정보는 저장소에 커밋하지 않습니다.

지표를 읽는 기준

항목의미와 주의점
사용자 / 세션 / 이벤트각각 측정된 사람·방문·행동 발생 횟수입니다. 일별·채널별 사용자를 더해 전체 사용자라고 부르지 않습니다.
가입sign_up. 저장 API 성공 후 기록합니다. 웹은 현재 비밀번호 가입 경로만 보장하며 소셜 가입은 서버의 신규 가입 신호가 필요합니다.
병동 생성 / 근무표 확정ward_created / schedule_confirmed. 성공 횟수이며 첫 활성화는 사용자별 첫 발생·순서로 별도 계산합니다.
소개 완료앱 tutorial_complete는 소개 화면 완료이며 병동 설정 완료가 아닙니다.
앱 설치·웹 전환스토어 클릭을 설치로 간주하지 않습니다. 기존 모바일 앱과 .ai 앱은 streamId로 분리하며 웹·앱 사용자는 중복 제거가 검증되기 전 합산하지 않습니다.
기간 / 품질GA는 속성 시간대, Search Console은 미국 태평양 시간·확정 데이터입니다. 최근 데이터 지연, 임계값, 샘플링, 잘린 행과 낮은 표본을 표시합니다.

개발자 검증 및 유지보수

  1. 이벤트 사전에서 성공 조건·허용 매개변수·분석 범위를 확인합니다.
  2. 웹 shared/util/growth-analytics.ts, 앱 core/analytics/growth_analytics.dart를 사용합니다. 이름·연락처·자유 입력·토큰·병동 ID·근무표 내용을 보내지 않습니다.
  3. 웹 배포 후 첫 진입·SPA 이동·가입·병동 생성·확정/게시를 확인합니다. 실패 응답에서는 성공 이벤트가 없어야 합니다. dev·preview는 측정하지 않습니다.
  4. 앱 릴리즈 후 공식 Firebase 앱과 streamId의 실제 수신을 확인합니다. iOS·Android를 각각 검증합니다.
  5. 새 웹 스트림의 수신이 확인되면 상세 AI 조회 대상을 새 속성으로 전환합니다. 과거·신규 데이터를 합칠 때 중복과 전환일을 남깁니다.
  6. UTM은 영문 소문자·숫자·밑줄로 통일합니다. 예: utm_source=instagram&utm_medium=social&utm_campaign=2026_q4_launch. 광고는 paid_social로 구분합니다.
