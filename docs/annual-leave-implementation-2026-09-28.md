# 연차 관리 구현 결과 (2026-09-28)

제품 기준은 `annual-leave-management-requirements-2026-09-27.md`입니다. 서버/프런트를 각각 `codex/annual-leave-management` 브랜치에 구현했습니다. DB 접속·스키마 적용·운영 배포는 수행하지 않았습니다.

## 사용 흐름

1. `/make`의 **표시 설정 → 연차**를 켜면 이 근무표의 연차 분류를 합산합니다. 남은 연차를 입력하지 않아도 됩니다. 표시를 꺼도 병동의 서버 집계 설정은 바뀌지 않습니다.
2. `근무설정 > 연차 관리`에서 관리를 시작하면 사람별 사용·예정·남은 일수를 확인합니다. 시작 일수는 빈칸으로 두거나 개인별/여러 명 붙여넣기로 입력할 수 있습니다.
3. 이미 미래 승인분이 빠진 숫자를 입력할 때는 포함된 날짜를 대조합니다. ‘기준을 모르겠어요’를 고르면 확인 필요 상태로 둡니다.
4. 확정·재확정·확정 근무 수정 시 자동 반영합니다. 초안은 예정 결과만 미리 보고, 신청근무만으로는 차감하지 않습니다.
5. 사람별 ‘수정’은 연차 변경 입력을, ‘내역’은 저장된 기록 조회를 바로 엽니다. 모달에는 ‘연차 수정 / 변경 내역’ 전환 버튼을 두지 않고 목록에서 선택한 화면만 엽니다. 모달 제목에 수정/변경 내역을 표시합니다. 기록 취소는 선택한 기록과 사유를 같은 팝업에서 확인한 뒤 저장하며, 취소하지 않으면 내역으로 돌아갈 수 있습니다. 사유와 작성자 식별 정보를 보존합니다.
   - 팝업 제목·닫기는 스크롤해도 고정하고, 목록의 안내 툴팁은 팝업이 열리면 제거합니다.
   - 근무표 반영은 연·월별 한 항목으로 묶습니다. 합계는 누적 변경 이력을 더하지 않고 기존 월별 조회 API의 최종 날짜별 사용량으로 구합니다. 날짜별 직접 처리를 포함하고, 오늘까지의 사용량과 미래 사용 예정량을 구분합니다. 페이지를 추가로 불러와도 같은 월은 중복되지 않습니다.
   - 월 항목의 ‘날짜별 보기’는 날짜·상태·일수를 한 목록으로만 표시합니다. 기준 안내 문구와 중복되는 ‘연차 변경 기록 N건’ 영역은 표시하지 않습니다. 현재 사용량이 없는 날짜의 실제 취소는 같은 목록에 한 번만 남깁니다. 단순 0일·반복 기록만 있는 월은 숨기고 원본 DB 기록은 삭제하지 않습니다.
   - 현재 집계 시작일 이전 월은 보존된 변경 기록을 낮은 행으로 표시하고, 0일로 오인할 현재 합계는 표시하지 않습니다. 기록 행의 기본 높이는 32px이고 터치 조작 영역은 44px입니다. 관리 중단 시 내역만 조회하며, 서버 API·DB 계약은 그대로 사용합니다.
   - 항목 상단에는 배지와 적용일/월, 하단 왼쪽에는 사유·상세 버튼, 오른쪽 아래에는 일수를 배치합니다. 부여·조정의 증감량은 부호를 표시합니다. 취소 기록은 0일 대신 취소 상태를 표시하고, 작성자·기록 시각·확정본은 ‘기록 정보’에서 펼쳐 봅니다.

사용한 연차는 근무표에 연차 분류로 표시하고 확정하여 집계합니다. 개인 수정 화면의 날짜별 직접 처리 입력은 제거했습니다. 기존 날짜별 직접 처리 이력의 조회·취소와 서버 호환성은 유지하며 저장된 기록을 삭제하거나 무시하지 않습니다.

## 개인 수정 화면 간소화

- 추가·빼기·수정을 `남은 연차 조절` 하나로 합칩니다. 현재 남은 일수로 시작하고 `− / +`로 한 번에 1일씩 조절하거나 최종 숫자를 직접 입력합니다. 소수점 3자리, 0일, 음수 연차를 유지합니다. 처음 남은 일수가 없는 사람은 기존 초기 등록으로 시작합니다.
- 상단에 `현재 남은 연차 / 사용 예정` 요약 박스를 항상 표시합니다. 수정 중에는 요약 박스의 남은 일수를 `15일 → 18일`로 표시하고 `→ 18일`만 보라색으로 강조합니다. 변경값이 없거나 내역을 보는 동안에는 저장된 일수만 표시하며, 입력 아래의 별도 비교 박스는 두지 않습니다. 값이 같으면 저장하지 않습니다. 입력 숫자는 항상 최종 남은 일수입니다. API `SET_BALANCE`로 전송해 서버가 차이를 계산하고 증감 이력을 남깁니다. 기존 추가·차감·조정 이력과 취소 기능은 보존합니다.
- 조절 결과를 저장한 날의 남은 연차로 확정합니다. 기존 `SET_BALANCE`처럼 오늘까지의 일수를 대조한 것으로 기록하며, 사용량을 추가로 기록하거나 예정분을 중복 차감하지 않습니다. 날짜별 사용량은 근무표에서 연차로 표시합니다. 개인 화면의 `날짜별 연차 처리`와 `어떻게 변경할까요?` 드롭다운은 제거합니다.
- `다음 확인일`은 조절 화면에 표시하지 않습니다. 기존 미래 확인일은 유지하고 이미 도래한 날짜는 비워 보냅니다. 초기 등록과 관리 설정의 확인일 기능은 유지합니다. DB/API 스키마 변경은 없습니다.
- 남은 연차 조절의 `수정 이유`는 선택 입력입니다. 빈칸 또는 공백만 입력하면 작업명인 `연차 조절`을 자동 사유로 보내 기존 서버의 필수 문자열 계약을 유지합니다. 초기 등록·기록 취소의 사유 계약은 그대로 유지합니다.

`APP_ANNUAL_LEAVE_ENABLED` 기본값은 false입니다. DBA 승인 → Flyway 스키마 적용 확인 → 서버/프런트 연동 확인 → 서버 플래그 활성화 → 병동별 관리 시작 순서입니다. **플래그 false가 Flyway 자동 적용을 막지는 않습니다.** 서버 배포 전에 DBA 문서를 검토해야 합니다.

## 연차 일괄 추가

- 목록 체크박스와 필터 내 전체 선택으로 활성 근무자를 고릅니다. 남은 연차 미입력/재시작 필요 대상은 선택할 수 없습니다. 필터 변경 시 선택을 초기화합니다.
- `연차 일괄 추가`에서 각자 받을 일수(양수, 소수점 3자리)와 선택 사유를 입력하고 개인별 기존→변경 일수를 확인합니다. 별도 휴가 계정이 아닌 현재 남은 연차에 합산합니다.
- 기존 `POST /nurses/{nurseId}/entries`의 `GRANT`를 대상별로 호출합니다. 각자의 서로 다른 잔여량을 덮어쓰지 않고 같은 증분을 더합니다. 새 서버 API/DB 컬럼/마이그레이션은 없습니다.
- 묶음 ID는 `bulk_<UUID 32자리>`이며 대상별 requestId는 `<묶음 ID>_<nurseId>`입니다. 기존 `details_json.requestId`에 영속 저장되어 개인 이력에서 `일괄 추가` 배지와 공통 처리번호를 확인합니다. 사유/처리자/시각은 기존 원장에 기록됩니다.
- 대상별 트랜잭션이므로 일부만 완료될 수 있습니다. 결과를 개인별로 표시하고 완료 대상은 건너뜁니다. 응답 유실은 같은 requestId·날짜·일수·사유로 재시도하여 서버 멱등 처리를 사용하며 최신 version만 갱신합니다. 진행 상태는 병동별 sessionStorage에 저장해 같은 탭 새로고침 후 이어갑니다.
- 취소는 기존 개인별 기록 취소 기능을 사용합니다. 묶음 전체를 한 번에 취소하는 별도 API/화면은 이번 범위에 포함하지 않습니다.

### 우측 더보기 메뉴 및 일괄 차감

일괄 추가·빼기, 여러 명 초기 입력, 관리 설정을 우측 상단 `⋯` 메뉴로 모았습니다. 선택 인원은 메뉴 옆에 표시하며 선택 전 일괄 동작은 비활성화합니다. 메뉴는 방향키·Escape·외부 클릭·Tab 이동을 지원합니다.
일괄 빼기는 기존 `SETTLEMENT` API에 **양수 차감량**을 보내 서버가 음수 원장으로 기록합니다. 사용한 연차는 바뀌지 않습니다. 추가와 동일한 공통 처리번호·개인 기록·부분 재시도 정책을 적용합니다. 저장된 재시도 작업의 `kind`를 고정해 새로고침 후 추가/차감이 뒤바뀌지 않으며, 이전 버전의 kind 없는 작업은 GRANT로 해석합니다. 음수 연차는 기존 정책대로 허용하고 미리보기에서 안내합니다. DB 구조 변경은 없습니다.

- 개인 상세와 계산 안내에서 기존 REVIEW_REQUIRED / VALIDITY_UNKNOWN 알림을 노출하지 않는다.

- 집계 시작일과 연차 사용량·남은 일수 계산은 유지한다.

### 오늘 기준 남은 연차 등록
- 기존 TSV 붙여넣기 화면을 이름별 숫자 입력 목록으로 교체. 미등록/재시작 대상의 활성 근무자만 표시한다.
- 오늘 사용분까지 반영한 일수를 입력하며 빈칸은 전송하지 않고 0일은 등록한다. 날짜와 변경 이유 입력을 제거하고 등록 사유는 자동 기록한다.
- TODAY_INCLUDED 기준을 API에 추가. startedOn 당일 사용량은 중복 차감하지 않고 다음 날부터 차감한다. 당일 수동 수정/추가/빼기는 정상 적용한다.
- DB 컬럼 추가 없음. 기존 데이터/기준의 동작은 유지하며 서버와 프런트엔드 동시 반영이 필요하다.

### 차감 일수 직접 수정
- 관리 설정에서 모든 연차 유형과 현재 차감 일수를 바로 보여준다. 날짜·유형 선택·추가·삭제 UI를 제거하고 숫자만 수정한다.
- 변경한 유형만 `effectiveFrom: null`의 현재 기준으로 저장한다. 변경하지 않은 예약 기준은 보존하며, 예약된 기준을 수정하는 행에는 대체 안내를 표시한다.
- 확정 기록은 유지한다. 새 배정/유형 변경/취소 후 재배정에는 현재 기준을 적용하며 미리보기도 서버와 동일하다.
- 0~10일/소수점 세 자리, 공백 입력, 중복 저장, 버전 충돌을 검증한다. DTO 날짜 nullable 변경은 서버와 동시 반영해야 한다.
- 서버 상세 설계와 DBA 인계 문서에 기록. DB 스키마 변경 없음.

### 분류별 차감 유형 선택 (관리 모달)
- 기본 목록은 ANNUAL_LEAVE 분류만 노출. 기존에 별도 저장한 휴무 규칙은 재진입 시 계속 표시한다.
- 공통 드롭다운으로 병동의 OFF/OTHER_LEAVE/isOff 유형을 추가한다. 새 휴무 규칙 기본값은 0일이며, 0.5일 등 명시한 경우만 차감한다. classification/근무유형 자체를 변경하거나 생성하지 않는다.
- 추가한 유형 제거는 차감 규칙만 제거한다. 이미 확정된 차감 기록은 보존한다.
- 근무명·분류·작은 일수 필드를 행으로 배치하며 다른 설정 페이지로 이동하지 않는다.
