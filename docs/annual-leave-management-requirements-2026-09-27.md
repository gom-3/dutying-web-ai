# 근무설정 > 연차 관리 — 조사 및 제품 요건 제안

작성일: 2026-09-27. 용어 수정: 2026-09-28. 상태: 제품 검토용 제안. 이번 작업은 조사·요건 정의이며 기능 구현이나 배포를 포함하지 않는다.

후속 구현 결과: [연차 관리 구현 결과](annual-leave-implementation-2026-09-28.md). 아래 본문은 조사 당시 요건 제안을 보존한 기록입니다.

## 1. 추천 방향

**개인별 시작 시점 남은 연차 + 확정 근무표의 연차 사용량 + 날짜별 예외 사용·관리자 증감 이력**으로 구성한다. 사용량 조회만 원하는 병동은 남은 연차를 입력하지 않아도 된다.

관리자가 병원에서 확인한 남은 연차를 입력하면, 그 이후 확정한 근무표를 기준으로 남은 연차를 계산한다. 추가 부여, 서비스 밖 사용, 정산은 같은 장부에서 처리한다. 법정 발생일수를 자동 산출하는 기능은 후속으로 둔다.

첫 화면에서 해야 할 일은 세 가지다.

1. 사용량만 볼지, 남은 연차도 관리할지 선택한다. 사용하지 않으면 기존 근무표를 그대로 쓴다.
2. 남은 연차도 관리한다면 집계 시작일과 사람별 시작 시점 남은 연차를 입력하고, 미래 사용 예정분이 이미 빠진 숫자인지 확인한다.
3. 이후 연차 근무는 자동 집계하고, 예외가 있는 날짜나 병원에서 확인한 남은 연차가 바뀐 사람만 수정한다.

복잡한 병원별 운영 방식은 여러 정책 모드보다 입력값과 이력으로 수용한다. 자동화하지 않는 사례는 아래에 수동 처리 범위를 명시한다.

재검토 결론: 연차 분류만 세는 방식에는 누락이 있다. OFF로 표시한 연차, 외부에서 승인된 예정분, 남은 연차 유효기간, 부분 근무, 기능 중단·재개를 보완해야 한다. 이 문서의 첫 버전은 **병원이 확인한 일수의 기록·대조 도구**이며, 모든 병원의 시간제 휴가·발생·만료·급여 규칙을 자동 처리하는 제품은 아니다.

## 3. 반드시 분리할 개념

| 개념 | 질문 | 관리 위치 |
| --- | --- | --- |
| 개인별 남은 연차 | 이 사람의 연차가 얼마나 남았는가? | 새 연차 장부 |
| 월 휴무 수 | 이번 달 휴무 목표에 어떤 근무유형을 포함하는가? | 기존 휴무 정책 |
| 신청근무 | 어떤 날에 어떤 근무를 원했는가? | 기존 신청근무 |
| 확정 배정 | 실제로 확정된 근무표에서 무엇으로 배정했는가? | 확정 근무표 |
| 유급 여부·유급 시간 | 급여상 어떻게 취급하는가? | 해당 정책·근무유형. 연차 차감일수와 별개 |

예: 월 목표 휴무가 10일이고 `OFF 8일 + 연차 2일`인 경우, 연차를 휴무 수에 포함하면 휴무 집계 10일, 제외하면 8일이다. **어느 쪽이든 개인 연차 사용은 2일**이다. 포함 여부가 해당 운영의 법적 적정성을 보증하지 않는다.

유급휴가 전체를 연차로 세지 않는다. 경조휴가·병가·대체휴무·교육·야간 후 회복일은 유급이거나 쉬는 날이라는 이유만으로 연차를 차감하지 않는다.

## 4. 법정 발생 계산을 첫 버전에서 미루는 이유

근로기준법 제60조는 출근율·근속기간에 따라 발생일수를 달리 정하며, 출근으로 보는 기간과 사용기간도 규정한다. 입사일뿐 아니라 실제 출근·휴직 등의 자료가 필요하다. 병원의 추가 약정 휴가까지 고려하면 전원에게 15일을 넣는 방식은 적절하지 않다. [현행 근로기준법 제60조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0060&lsiSeq=283457&urlMode=lsScJoRltInfoR)

입사일 기준과 회계연도 기준 운영에 차이가 있다는 점도 공식 상담에서 확인된다. 첫 버전은 병원이 확인한 부여량과 남은 연차를 입력받는다. [고용노동부 상담](https://1350.moel.go.kr/rtmview.do?id=1000303512)

연차는 근로자가 청구한 시기에 부여하는 것이 원칙이며, 특정 근로일을 연차로 대체하는 제도에는 근로자대표와의 서면 합의 요건이 있다. 따라서 제품은 관리자가 확인한 배정을 기록하되, 휴무 부족이나 인력 과잉을 이유로 OFF를 자동 전환하지 않는다. 단순 관리자 메모·클릭을 법적 동의로 취급하지 않는다. [제60조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0060&lsiSeq=283457&urlMode=lsScJoRltInfoR), [제62조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0062&lsiSeq=283457&urlMode=lsScJoRltInfoR)

## 5. 화면과 기본 사용 흐름

### 5.1 위치

사용자 화면의 기본 표현은 **‘남은 연차’**로 통일하고 숫자에는 ‘일’을 붙인다. 설명·계산 요건에서 단위를 강조할 때는 ‘연차 잔여 일수’를 쓸 수 있다. 주요 문구는 ‘남은 연차 입력’, ‘연차 일수 조정’, ‘남은 연차 수정’, ‘사용한 연차’, ‘사용 예정 연차’로 정한다. ‘남은 연차 수정’은 확인된 최종 일수를 입력하는 기능이며, ‘연차 일수 조정’은 추가·차감 작업의 통칭이다.

`근무설정 > 연차 관리` 탭을 추가한다. 탭의 중심은 설정 폼보다 사람별 현황표다. 정책은 상단 ‘관리 설정’에서 접어 둔다. 근무표의 사람별 요약에서도 연차 사용량과 예정 반영 후 남은 연차를 볼 수 있게 한다.

현황표 예시 — 모두 가상 수치, 사용량은 집계 시작일부터 오늘까지:

| 이름 | 사용 | 사용 예정 | 현재 남은 연차 | 예정 반영 후 남은 연차 | 작업 |
| --- | ---: | ---: | ---: | ---: | --- |
| 김간호 | 3 | 2 | 7 | 5 | 조정 · 내역 |
| 이간호 | 1 | 2 | 1 | -1 | 조정 · 내역 |
| 박간호 | 2 | 1 | 미입력 | 미입력 | 남은 연차 입력 · 내역 |

현재 남은 연차 옆에는 기준일과 최근 병원 자료 대조일을 표시한다. 연도 필터를 바꿔도 전체 남은 연차가 리셋되지 않는다. 시작일 이전 사용량을 모르면 ‘올해 총 사용’이라고 표시하지 않고 실제 집계 범위를 보여준다.

### 5.2 처음 시작

- 병동 공통 집계 시작일을 한 번 선택한다. 중간 입사·전입자는 개인 시작일을 별도로 둘 수 있다.
- 사람별로 **시작일 당일 사용을 반영하기 전 남은 연차**를 입력한다. 기본값은 빈칸이다. `0`은 확인된 0일, 빈칸은 모름이다.
- ‘총 부여 − 이미 사용’ 입력 보조를 제공할 수 있으나, 계산 결과를 같은 시작 시점 남은 연차로 저장한다. 별도 운영 모드를 만들지 않는다.
- 여러 사람 선택 후 같은 값 입력과 표 붙여넣기를 지원한다. 기존값 덮어쓰기는 대상·변경 전후를 보여준 후 한 번에 저장한다.
- 표 붙여넣기는 구성원 식별자로 대조하고 동명이인·매칭 실패·중복 행을 표시한다. 이름만 같은 사람에게 자동 반영하지 않는다.
- 남은 연차를 모르는 사람도 시작할 수 있다. 사용량은 집계하고 남은 연차는 ‘미입력’으로 둔다.
- 기존 `ANNUAL_LEAVE` 유형을 집계 대상으로 제시한다. 유형이 없으면 연차 유형 만들기로 연결한다. 분류가 누락된 구 근무유형은 이름만으로 추정하지 않고 확인 대상으로 표시한다.

입력 화면에는 ‘9월 30일까지 사용을 반영한 남은 연차 → 10월 1일부터 집계’처럼 경계를 보여준다. 병원 자료의 남은 연차가 무엇을 반영했는지 ‘기준일까지 사용만 / 미래 승인분까지 / 모르겠음’으로 확인한다.

- 입력한 일수에 미래 승인분까지 반영되어 있다면, **이미 차감된 예정 내역을 대조**하여 시작 시점 남은 연차를 환산한다. 예: 병원에서 확인한 남은 연차 5일에 미래 2일이 이미 반영되어 있으면 현재 기준 7일과 예정 2일로 기록하여 예정 반영 후 남은 연차 5일을 유지한다.
- 미래 2일은 서비스 안의 확정 배정 또는 날짜가 있는 외부 승인 기록과 연결한다. 서비스에 있는 미래 연차 전부를 무조건 더하는 방식은 금지한다.
- 포함 여부나 내역을 모르면 ‘대조 필요’로 보관하고, 정확한 사용 가능한 연차 일수를 계산한 것처럼 표시하지 않는다.
- ‘총 부여 − 이미 사용’ 보조 입력과 이후 ‘남은 연차 수정’에도 같은 기준 확인을 적용한다.

### 5.3 관리자의 증감

버튼은 ‘연차 추가’, ‘연차 차감’, ‘남은 연차 수정’으로 제공한다. 내부 기록은 모두 증감 이력으로 통일한다.

| 조작 | 예 | 기록 의미 |
| --- | --- | --- |
| 연차 추가 | 신규 발생 +1, 추가 부여 +3 | 부여량 증가 |
| 연차 차감: 근무표 밖 사용 | 외부에만 기록된 사용 0.5 | 사용일이 도래하면 사용량 증가 및 남은 연차 감소. 미래 승인분이면 예정에 반영 |
| 연차 차감: 정산 | 병원 확인에 따른 소멸·수당정산 -2 | 사용량은 그대로, 남은 연차만 감소 |
| 남은 연차 수정 | 시스템 5일 → 병원 확인 7일 | +2 보정. 이전 5일을 지우지 않음 |

- 수량, 적용일, 사유 분류를 입력한다. 보정·정산·기타에는 짧은 메모를 요구한다.
- 행위자, 기록 시각, 적용일, 전후 남은 연차, 출처를 보존한다. 잘못된 조정은 원본 삭제 대신 취소 이력을 남긴다.
- ‘남은 연차 수정’은 사용 예정분을 빼기 전 **현재 남은 연차**를 맞춘다는 것을 명시한다.
- 첫 버전에서 부여는 발생한 날에 등록한다. 미래의 예상 발생량을 현재 남은 연차에 미리 포함하지 않는다.
- ‘근무표 밖 사용’은 사용일과 확인 출처를 연결하며 과거 사용·미래 승인 모두 기록할 수 있다. 같은 사용이 근무표에 나중에 들어오면 기존 기록과 연결·대체한다. 임의 보정은 사용일수로 집계하지 않는다.
- 남은 연차가 등록된 사람에게 부여·보정·정산을 허용한다. 남은 연차 미입력 상태에서도 날짜가 있는 사용·예정은 기록할 수 있지만, 잔여 0에서 시작했다고 추정하지 않는다.

### 5.4 선택 사용과 `/make`

처음부터 세 가지 관리 모드를 고르는 복잡한 설정 화면을 만들지 않는다. 사용자가 필요한 만큼 켜는 흐름으로 제공한다.

| 원하는 수준 | 사용자 행동 | `/make` 표시 |
| --- | --- | --- |
| 사용하지 않음 | 아무것도 켜지 않음 | 현재 근무표 유지. 남은 연차 열·관련 알림 없음 |
| 사용량만 확인 | 보기 옵션에서 ‘연차 사용량’ 켜기 | 이 근무표의 연차 일수. 초안이면 작성안임을 명시. 남은 연차 입력 요구 없음 |
| 남은 연차도 관리 | 근무설정에서 연차 관리 시작, 확인된 사람부터 남은 연차 입력 | 작성안의 연차량과 반영 후 잔여. 클릭하면 확정·예정·작성안 차이와 내역 확인 |

- ‘이 근무표 연차 2일’은 현재 화면의 작성안 집계다. ‘사용 완료 2일’로 표현하지 않는다. 여러 연차 유형과 부분 사용량을 합산한다.
- 남은 연차 미리보기는 이 달의 기존 확정분을 작성안으로 대체하고, 다른 달 확정분과 외부 승인분은 유지한다. 다른 달 예정분을 포함한 값에 ‘이번 달 말 잔여’라는 이름을 붙이지 않는다.
- 개인의 ‘열 숨기기’와 병동의 ‘관리 중단’을 구분한다. 열을 숨겨도 시작한 장부의 집계는 계속된다. 병동 관리 시작·중단은 권한 있는 관리자만 가능하다.
- 관리 중단 시 종료 기준일을 남겨 이력을 보관하고 이후 숫자는 현재 남은 연차로 표시하지 않는다. 재개 시 새 기준일·시작 시점 남은 연차를 대조하며 기존 예정분을 연결하여 중복 반영을 막는다. 기능을 켤 때 누락 기간을 임의로 0 사용으로 처리하지 않는다.
- 공유·인쇄·내보내기에는 타인의 남은 연차와 조정 사유를 기본 포함하지 않는다. 개인 화면에서 보이는 정보가 그대로 공개되지 않도록 한다.

## 6. 계산 규칙

### 6.1 현재와 예정

`S`는 개인 집계 시작일, `T`는 병동 기준 오늘이다. 한국 병동은 Asia/Seoul의 날짜를 사용하고 다국가 지원 시 병동 시간대를 명시한다.

```text
현재 남은 연차(T)
  = 시작 시점 남은 연차
  + S~T까지 적용된 추가 부여·보정·정산의 순증감
  - S~T까지의 유효 연차 사용량

사용 예정
  = T 이후 현재 유효한 확정 배정·외부 승인 기록의 연차량

예정 반영 후 남은 연차
  = 현재 남은 연차 - 사용 예정
```

유효 사용량은 근무유형에서 계산한 기본량에 날짜별 예외를 적용한 값과 근무표 밖 사용을 중복 제거한 결과다. 수동 사용은 한 번만 뺀다. 구현에서 모든 기록을 부호 있는 원장 항목으로 합산할 경우 다시 사용량을 중복 차감하지 않는다.

예: 10월 1일 시작 시점 남은 연차 7일, 이후 추가 부여 +1일, 오늘까지 사용 2일, 앞으로 확정된 연차 3일이면 현재 남은 연차는 6일, 예정 반영 후 남은 연차는 3일이다.

‘사용’은 확정 배정·외부 확인 기록의 사용일이 오늘까지 도래했다는 뜻이며, 실제 출퇴근이나 인사팀 최종 정산을 검증했다는 뜻은 아니다. 집계 출처와 기준일을 표시한다. 미래 발생·소멸을 자동 예측하지 않으므로 예정 반영 후 남은 연차는 **현재 등록된 남은 연차 기준**이다. 예정 사용일이 확인된 기간을 넘으면 숫자와 별도로 ‘해당 기간 남은 연차 확인 필요’를 표시하고 사용 가능 판정을 하지 않는다.

### 6.2 근무표와 신청근무

| 상태 | 장부에 반영하는가? |
| --- | --- |
| OFF 신청 | 반영하지 않음 |
| 연차 신청·미확정 요청 | 신청량만 별도 표시 가능. 사용·예정에서 제외 |
| 작성 중 초안·AI 후보·임시저장 | 장부 불변. 초안 결과만 미리보기 |
| 유효한 확정 근무표의 과거·오늘 연차 | 사용량 반영 |
| 유효한 확정 근무표의 미래 연차 | 사용 예정 반영 |
| 병원에서 승인됐지만 아직 근무표에 없는 연차 | 관리자가 날짜·출처를 확인하여 외부 예정으로 등록. 단순 신청과 구분 |
| 확정 후 연차→OFF 변경 | 해당 사용 또는 예약을 취소 |
| 확정 후 OFF→연차 변경 | 해당 사용 또는 예약을 추가 |

확정된 달을 다시 편집할 때는 마지막 유효 확정본을 기준으로 계산한다. 초안 미리보기는 기존 확정분을 빼고 새 초안분으로 **대체한 결과**이며, 두 근무표를 더하지 않는다. 재확정 시 같은 날짜의 차이만 반영한다.

단순히 편집 화면을 다시 열거나 단계 상태를 `IN_PROGRESS`로 바꾸는 것으로 기존 사용·예정을 환급하지 않는다. 확정 배정의 명시적 취소·재확정에서만 변경한다. 이미 도래한 사용일의 취소는 사유를 기록하는 과거 정정으로 처리한다.

### 6.3 집계할 근무유형

- 기본 자동 집계는 `classification === ANNUAL_LEAVE`를 기준으로 한다. 이름, 약자, 색상, `isOff`, `isCounted`, 유급 시간만으로 연차 여부를 판단하지 않는다.
- 기본은 연차 셀 1개당 1일이다. 같은 분류의 여러 근무유형은 합산한다.
- 고급 설정에서 근무유형별 차감량을 명시적으로 설정할 수 있게 한다. 설정은 적용일부터 효력이 있으며 이전 차감 기록을 다시 해석하지 않는다.
- 12시간 교대라는 이유만으로 자동으로 1.5일을 차감하지 않는다. 병원이 사용하는 차감 단위를 확인해 입력한다.
- 휴일·주말이라는 이유만으로 연차 셀을 집계에서 제외하지 않는다. 교대근무의 근로일은 달력상 평일과 같지 않다. 관리자가 확정한 실제 연차 배정을 기준으로 한다.
- 설정에서 연차로 분류한 유형은 ‘유급휴가 전체’와 구분되도록 안내한다. 경조사 등 다른 휴가는 `OTHER_LEAVE`에 둔다.

**날짜별 예외:** 근무표에 OFF로 표기하지만 실제로 연차를 쓴 날은 해당 셀 또는 날짜에서 ‘연차 처리’를 선택하고 차감량·사유를 남길 수 있다. 셀에 `OFF · 연차 1일`처럼 표시하여 숨은 차감을 만들지 않는다. 모든 OFF를 일괄 연차로 간주하는 설정은 제공하지 않는다.

- 예외는 그날의 기본 차감량을 대체한다. 연차 기본 1일을 0.5일로 수정하면 총 0.5일이며 1.5일이 아니다. 같은 날짜 여러 부분 사용은 내역을 연결해 합산하되 자동 기본량을 다시 더하지 않는다.
- 전일 OFF를 연차로 처리할 때 월 휴무 계산에도 연차의 집계 정책을 적용해야 한다. 기존 휴무 정책이 유형 ID 기반이므로, 예외에 기준 연차 유형을 연결하여 그 유형의 포함·제외를 따른다. 표기 OFF 때문에 연차 제외 병동의 휴무 수가 부풀려지면 안 된다.
- 별도 여름휴가를 연차에서 차감하는 등 확인된 예외도 이 기록으로 처리할 수 있다. ‘여름휴가’라는 이름만으로 자동 차감하거나 별도 휴가의 잔여 일수와 합치지는 않는다.
- 근무를 변경하거나 다른 달로 복사할 때 예외가 조용히 따라가면 안 된다. 연결된 배정이 달라지면 유지·변경·취소를 확인하고 전후 이력을 남긴다.
- 야간 근무의 다음 날 연결 표시는 새로운 연차 사용이 아니다. 달력 셀 수 대신 연결된 실제 휴가 사용일·사용 기록을 기준으로 중복을 막는다.

### 6.4 반차·시간 사용의 범위

남은 연차·증감 수량은 0.5일, 0.25일, 0.125일 등 소수를 손실 없이 처리하도록 고정소수점으로 보관한다. 8시간을 모든 근로자의 하루로 하드코딩하지 않는다. 시간 단위 운영은 취업규칙 등 개별 기준을 고려해야 한다. [고용노동부 반차·시간 단위 상담, 2026-03-16](https://1350.moel.go.kr/rtmview.do?id=1000320016)

현재 서버는 `ANNUAL_LEAVE`를 휴무·인원 집계 제외로 고정한다. 따라서 **근무+반차를 단순히 연차 분류로 바꾸면 실제 근무가 사라지는 문제가 있다.**

첫 버전은 병원이 확인한 부분 일수를 사용일과 연결한 예외 기록으로 처리할 수 있다. 기존 근무 셀은 유지하며 연차 사용 표시를 연결한다. 이때 해당일에 ‘근무시간·인력 확인 필요’를 표시하고, 기존 D 셀 하나가 온전한 1명 근무를 보장한다고 안내하지 않는다. 부분 시간대별 인력 산정과 자동 배치는 후속 범위다. 복합 근무 셀을 구현하기 전까지 전일 휴무 셀 하나를 근무+반차의 대체 모델로 쓰지 않는다.

시간·분으로만 관리하고 일수 환산 기준도 사람별·기간별로 달라지는 병동은 첫 버전의 완전 지원 대상이 아니다. 시간 장부, 근로시간 변경 이력, 환산·반올림 기준이 있어야 처리할 수 있다. 병원이 확인한 일수로 대조할 수 있는 경우에만 일수 장부를 사용한다.

## 8. 마이너스, 자동 배정, 변경 이력

- 음수는 기록 가능한 상태로 둔다. 과거 사용이나 병원에서 확인한 남은 연차를 입력하지 못하게 막지 않는다.
- 기본은 **연차 부족 안내 후 기록 가능**이다. ‘음수 기록 가능’은 해당 사용의 적법성이나 선사용 승인을 뜻하지 않는다.
- 미래 배정으로 음수가 되면 확정 화면에서 대상자·초과량을 표시한다. 현재 이미 음수인 사람과 미래 예약 때문에 음수가 될 사람을 구분한다. 아직 발생량을 확인하지 않은 미래 기간에는 ‘등록량 기준 부족·해당 기간 확인 필요’로 안내하고 실제 권리가 부족하다고 단정하지 않는다.
- 연차가 부족하다고 자동으로 OFF·무급휴가·결근으로 바꾸지 않는다.
- AI는 인력·오프 수를 맞추기 위해 연차를 새로 만들지 않는다. 관리자에게 반영된 연차 입력·신청을 고정 조건으로 전달하고 유지한다. 연차 사용을 최소화·최대화하는 솔버 기능은 이번 범위 밖이다.
- OFF↔연차 전환은 대상 날짜와 남은 연차 영향을 보여준다. 신청과 다른 분류로 바꾸거나 확정된 배정을 정정하면 사유를 남긴다.
- 근무표 수정과 같은 내용을 다시 ‘연차 -1’로 입력하도록 요구하지 않는다. 장부에서 원인이 된 근무표 셀로 이동할 수 있어야 한다.

## 9. 연도 변경과 외부 자료 대조

첫 버전의 장부는 시작일부터 이어진다. ‘2026년’은 통계 필터이며 자동 리셋 기준이 아니다. 1월 1일에 일괄 15일 부여, 자동 소멸, 음수 초기화를 하지 않는다.

남은 연차 입력 시 병동 기본 다음 대조일을 함께 확인하고 사람별 변경을 허용한다. 1월 1일은 제안값일 뿐, 모든 연차의 만료일로 간주하지 않는다. 알고 있는 부여·만료 등 더 이른 변동일이 있으면 그 날짜를 확인 경계로 삼는다. 유효기간을 모르면 ‘유효기간 미확인’으로 둔다.

대조일이 지난 뒤뿐 아니라 **그 경계를 넘는 미래 근무표를 작성할 때도** ‘해당 기간 남은 연차 확인 필요’를 표시한다. 예: 12월까지 확인된 5일로 다음 1월 연차 2일을 배정하면, ‘3일 사용 가능’이라고 확정하지 않는다. 사용량과 등록량 기준 참고 계산은 볼 수 있지만 해당 기간 사용 가능 여부는 미확인이다. 표시를 없애기 위해 아직 발생하지 않은 연차를 현재에 미리 더하도록 유도하지 않는다.

새해에는 관리자가 병원 자료와 대조해 추가 부여·정산을 일괄 기록하거나 남은 연차를 수정하는 작업을 한다. 예를 들어 -2일에 새 부여 15일을 추가하면 13일이다. 병원에서 선사용을 정산한 후 남은 연차 13일을 전달했다면 이를 다시 15일 부여로 해석하지 않고 ‘남은 연차 수정 13일’을 사용한다.

기한이 다른 여러 부여분을 자동으로 먼저 차감하거나 소멸시키는 기능은 포함하지 않는다. 이 운영이 많은 고객이 확인되면 부여 건별 발생일·만료일·사용 연결을 갖춘 다음 단계로 확장한다.

월말 대조 시 실제 사용 여부와 병원에서 확인한 남은 연차를 함께 확인할 수 있게 한다. 연차일에 호출되어 출근한 경우처럼 확정표와 실제 사용이 달라졌다면 원래 배정을 정정하거나 날짜별 실제 사용량을 수정하고 사유를 남긴다. 자료가 없는 달은 사용 0일로 확정하지 않는다. 마감한 자료를 정정해도 원본·대조 당시 숫자는 보존한다. 급여 마감 연동과 잠금 규칙은 후속 범위다.

## 10. 이력·권한·정합성 요건

1. 장부의 사람 키는 이름·팀·앱 계정 연결 여부가 아니라 병동 구성원 식별자다. 앱을 연결하지 않은 간호사도 관리한다. 다른 병동으로의 이동은 자동 합산하지 않는다.
2. 시작 시점 남은 연차, 수동 기록, 근무표에서 반영된 사용을 구분해 저장한다. 저장 이후 시작값을 직접 덮어쓰는 대신 정정 이력을 남긴다.
3. 근무표 사용에는 사람·근무일·유형 ID·차감량·확정 버전·행위자를 연결한다. 같은 확정본의 재처리나 재시도로 중복 차감하지 않는다.
4. 같은 사람·날짜가 여러 팀 근무표에 나타나면 단순 합산하지 않고 하나의 유효 배정을 확인한다. 충돌은 관리자에게 표시한다.
5. 기존 유형의 이름·분류·차감량을 바꿔도 이미 확정된 사용량을 자동 변경하지 않는다. 확정 당시 값과 적용 정책을 보존하고, 과거 변경은 영향 미리보기와 정정 이력으로 처리한다.
6. 근무유형 보관·삭제, 구성원 비활성화 후에도 과거 사용·남은 연차 내역을 조회할 수 있어야 한다.
7. 수동 사용이 있는 날짜에 연차 배정을 가져오면 중복 여부를 확인하여 연결·대체한다. 해결하지 않은 충돌이 있는 남은 연차는 정확한 값으로 표시하지 않는다.
8. 시작일 전 근무표가 바뀌면 시작 시점 남은 연차를 자동 재계산하지 않는다. 필요하면 관리자가 연차 일수 조정을 한다. 시작일 이후 과거 정정은 현재 남은 연차에 반영하고 최근 병원 대조값과의 차이를 알린다.
9. 동시 수정은 버전 검증으로 충돌을 감지한다. 두 관리자가 같은 남은 연차를 각각 덮어쓰지 않는다. ‘남은 연차 수정’도 서버 최신값과 대조한다.
10. 서버 저장값이 기준이다. 브라우저 localStorage는 남은 연차의 저장소가 될 수 없다. 저장 실패·동기화 실패 시 정확한 남은 연차처럼 표시하지 않는다.
11. 1차는 병동 관리 권한이 있는 사용자만 증감·설정을 수행한다. 일반 구성원에게 공개할 때는 본인 남은 연차·본인 이력으로 범위를 제한한다. 타인의 상세 조정 사유를 공유 근무표에 노출하지 않는다.
12. 과거 정정·권한 변경·대량 입력은 조회 가능한 감사 이력을 남긴다. 별도 직원 승인 워크플로는 첫 버전에 요구하지 않는다.
13. 웹 확정 외 직접 수정·이관 등 유효 배정을 바꾸는 경로도 동일한 반영 규칙을 따른다. 개인 캘린더의 독립적인 편집이나 OCR 추정만으로 병동 장부를 변경하지 않는다.
14. 사용 근거인 확정 스냅샷을 보관·삭제해도 장부 근거가 사라지면 안 된다. 근거를 보존하거나 삭제를 제한하며, 파일 삭제를 휴가 취소로 취급하지 않는다.
15. 최초 남은 연차에 이미 반영한 사용, 외부 승인 기록, 확정 배정, 날짜별 예외를 연결한다. 날짜가 같다는 이유만으로 서로 다른 부분 사용을 삭제하거나 중복 사용을 그대로 더하지 않는다.
16. 자료 누락·충돌·유효기간 미확인은 남은 연차의 확인 상태로 관리한다. 숫자 0이나 정상 표시로 대체하지 않는다. 화면·내보내기에서도 기준일과 확인 상태를 함께 전달한다.

| 서버 `ShiftWorkflowStatus.java`, `ScheduleSnapshot.java`, `ScheduleAuthoringService.java` | `CONFIRMED`, 확정 스냅샷·시각·작성자 존재 | 확정 처리와 사용 기록 연결 가능. 별도의 연차 원장 연동은 필요 |
| 서버 `ScheduleAuthoringService.publishSnapshot`, `WardShiftController` | 확정 스냅샷 저장 경로와 `WardShiftService`를 호출하는 개별·일괄 수정 경로가 별도로 존재 | 실제 사용 여부·권한·동기화 관계를 추적하고 모든 유효 배정 변경을 장부에 연결 |
| `apps/app/src/features/shift-editor/ui/complex-view/shift-calendar/shift-calendar-row.tsx` | 근무유형별 셀 개수와 OFF 수 집계 | 소수·날짜별 예외·여러 연차 유형을 합산할 연차 전용 계산 필요. 일반 셀 개수 그대로 재사용 불가 |

구현 전에 웹 확정·재확정, 앱/기존 API 직접 수정, 초기 근무표 이관 등 실제 쓰기 경로를 모두 대조해야 한다. 프런트의 단계 번호나 ‘빈칸 없는 근무표’ 추론만으로 연차를 반영하지 않는다. 유효 확정 배정의 변경을 서버에서 한 경로로 장부에 연결한다.

이번에 읽은 코드에서 연차 분류와 휴무 집계는 확인했으나, 개인별 남은 연차·증감 원장은 확인되지 않았다. 분류 개수 표시만 추가하는 작업으로 전체 요건이 해결되지는 않는다.

최소 데이터 개념은 병동 집계 설정·운영 기간, 개인 시작 시점 남은 연차·대조 정보, 수동 부여/사용/조정 기록, 확정 배정에서 파생된 사용 기록과 날짜별 예외다. 외부 승인 내역과 자동 반영 내역을 연결할 식별자가 필요하다. 대규모 범용 규칙 엔진이나 별도 신청 결재 시스템을 먼저 만들 필요는 없다.

## 13. 다음 검증에서 확인할 가설

출시 범위를 확정하기 전 기존 이용 병동 중 서로 다른 운영 방식의 관리자에게 다음을 확인한다. 이번 조사에서 인터뷰를 수행한 것은 아니다.

1. ‘마이너스’가 미사용 오프 적립, 오프 초과 사용, 연차 선사용 중 무엇을 뜻하는가?
2. 관리자가 확인하는 남은 연차는 미래 확정 연차를 이미 차감한 값인가?
3. 연차 부여·소멸·이월의 최종 기준 자료는 인사팀, 엑셀, 병동 장부 중 무엇인가?
4. 확정 이후 연차를 변경할 때 어느 시스템을 먼저 수정하는가?
5. 근무+반차·시간 연차·2교대의 차감량 차이가 얼마나 자주 발생하는가?
6. 자동 발생 계산보다 남은 연차 입력과 월 사용 집계만으로 업무가 해결되는가?

이 답변에 따라 후속 자동화를 정한다. 첫 버전의 성공 기준은 설정 옵션 수가 아니라, 관리자가 자신의 병동 남은 연차를 재현하고 다음 근무표의 연차 부족을 설명할 수 있는지다.
