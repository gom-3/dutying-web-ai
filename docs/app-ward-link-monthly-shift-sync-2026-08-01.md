# 앱 병동 연동 월별 근무표 싱크

작성일: 2026-08-01  
대상: 앱 홈탭/내 근무표, 병동 연동 후 근무표 갱신

## 핵심 요약

병동 연동이 완료되면 서버는 **연동한 날짜부터가 아니라, 연동이 일어난 달 전체**를 병동 근무표 기준으로 개인 근무표(`account_shift`)에 반영한다.

예시:

- 5월까지 A병동 근무가 개인 근무표에 저장되어 있음
- 6월 15일에 B병동 연동 완료
- 홈탭/내 근무표에서 5월을 조회하면 기존 5월 근무가 남아 있음
- 홈탭/내 근무표에서 6월을 조회하면 B병동에서 복사된 6월 근무가 내려오는 구조

즉, 앱은 병동 연동일을 기준으로 직접 날짜를 자르지 말고, 서버가 내려주는 월별 개인 근무표를 그대로 표시하면 된다.

## 현재 서버 동작

병동 연동/승인 흐름에서 서버는 현재 날짜의 `year/month`를 계산한 뒤, 해당 월의 병동 근무를 개인 근무표에 복사한다.

관련 서버 흐름:

- 대기 간호사 신규 승인: `WaitingNurseAcceptService.approve`
- 대기 간호사 기존 근무자와 연동: `WaitingNurseAcceptService.connect`
- 후처리 계정 병동 연결: `WaitingNurseController.connectAccount`
- 실제 개인 근무표 반영: `LinkService.createAccountShiftThisMonth`

반영 단위:

- `LocalDate.now()` 기준 현재 월
- 일 단위 아님
- 6월 15일 연동이면 6월 1일-6월 말일까지 같은 월 기준

과거 개인 근무표 삭제 여부:

- 병동 연동 시 과거 `account_shift`를 삭제하는 로직은 없다.
- 따라서 이전에 직접 입력한 개인 근무표도 남는다.
- 이전 병동 연동으로 이미 개인 근무표에 복사된 과거 근무도 남는다.

## 앱 홈탭 조회 기준

홈탭/내 근무표는 아래 개인 근무표 API를 기준으로 표시한다.

```http
GET /accounts/{accountId}/shifts?startDate=YYYY-MM-DD&endDate=YYYY-MM-DD
```

응답에는 날짜별 근무 상세가 포함된다.

- `accountShiftTypeIdList`: 날짜 순서의 근무유형 ID 목록
- `accountShifts`: 날짜별 표시 정보 목록
  - `date`
  - `accountShiftTypeId`
  - `shortName`
  - `name`
  - `color`
  - `workStartMinute`
  - `workEndMinute`
  - `classification`

앱에서는 가능하면 `accountShifts`의 날짜별 상세 정보를 우선 사용한다.

## 앱에서 해야 할 갱신

병동 연동이 완료되거나, 대기 요청이 승인되어 계정 상태가 `LINKED`가 되면 앱은 아래 데이터를 다시 조회해야 한다.

1. 현재 계정 정보

```http
GET /accounts/me
```

또는 앱에서 사용 중인 계정 정보 v2 API.

2. 현재 월 개인 근무표

```http
GET /accounts/{accountId}/shifts?startDate={이번달 1일}&endDate={이번달 말일}
```

3. 필요하면 근무유형 목록

```http
GET /accounts/{accountId}/shift-types/v1
```

연동 직후 앱 로컬 캐시가 남아 있으면 홈탭에 이전 값이 보일 수 있으므로, 연동 성공 후 현재 월 근무표는 반드시 재조회한다.

## 병동 탭 근무표와 홈탭 근무표 차이

병동 탭의 확정 근무표는 가능하면 v2 API를 사용한다.

```http
GET /wards/{wardId}/shift-teams/v2/{shiftTeamId}/duty/mobile?year=YYYY&month=M
```

이 API는 최신 확정 스냅샷(`schedule_snapshot`) 기준으로 병동 근무표를 내려준다.

반면 홈탭/내 근무표는 `account_shift`에 저장된 개인 근무표 사본을 조회한다.

따라서 병동 탭 v2와 홈탭이 항상 같은 원본을 직접 보는 것은 아니다. 홈탭은 병동 연동/게시/동기화 시점에 개인 근무표로 복사된 값을 본다.

## 주의할 점

현재 서버는 과거 근무 row를 보존하지만, 개인 근무표 응답에는 `sourceWardId`, `sourceWardName`, `linkedFromMonth` 같은 병동 이력 메타데이터가 없다.

그래서 앱은 현재 응답만으로 "이 날짜의 근무가 A병동에서 온 것인지, B병동에서 온 것인지"를 명확히 구분할 수 없다. 홈탭에서 필요한 표시가 단순 근무 코드(D/E/N/O 등)라면 현재 응답으로 가능하지만, 과거 월에 "A병동 근무" 같은 병동명 표시까지 필요하면 서버 응답 필드 추가가 필요하다.

또 하나의 서버 측 주의점:

- 현재 병동 연동 시 개인 근무표로 복사하는 원본은 최신 확정 스냅샷이 아니라 legacy `ward_shift` 쪽이다.
- 병동 확정표가 v2 스냅샷에만 최신으로 존재하고 `account_shift`로 다시 동기화되지 않으면, 홈탭이 병동 탭 v2와 다를 수 있다.

앱에서 방어할 수 있는 부분:

- 연동 성공 후 현재 월 개인 근무표 재조회
- 월 이동 시 항상 서버에서 해당 월 범위 재조회
- 병동 탭은 v2 확정 근무표 API 사용
- 홈탭은 병동 연동일 기준으로 앱에서 임의 삭제/초기화하지 않기

## 기대 시나리오

### 5월 A병동, 6월 B병동

1. 5월 A병동 근무가 `account_shift`에 저장된다.
2. 6월 15일 B병동 연동이 완료된다.
3. 서버가 6월 B병동 근무를 `account_shift`에 upsert한다.
4. 앱이 5월을 조회하면 기존 5월 데이터가 내려온다.
5. 앱이 6월을 조회하면 6월 데이터가 내려온다.

### 병동 연동 전 직접 입력한 개인 근무

1. 사용자가 5월에 개인 근무를 직접 입력했다.
2. 6월에 병동 연동이 완료됐다.
3. 서버는 6월만 병동 근무로 반영한다.
4. 5월 개인 입력 데이터는 삭제되지 않는다.

## 앱 QA 체크리스트

- 병동 연동 후 홈탭 현재 월을 재조회했을 때 새 병동 근무가 보이는가?
- 이전 월로 이동했을 때 기존 개인/이전 병동 근무가 남아 있는가?
- 병동 연동일이 월 중간이어도 해당 월 전체가 새 병동 기준으로 보이는가?
- 홈탭과 병동 탭 v2가 다를 경우, 홈탭이 `account_shift` 사본을 보고 있다는 점을 기준으로 서버 동기화 여부를 확인했는가?
- 앱이 연동 전/후 로컬 캐시를 임의로 지우거나 월별 데이터를 덮어쓰고 있지 않은가?
