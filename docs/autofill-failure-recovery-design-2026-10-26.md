# 자동채우기 실패 후 고정 확인으로 이어가기

사용자에게 다음 행동 없이 일반 실패와 ‘표로 돌아가기’만 보여주지 않는다.
원인이 구체화되지 않은 GENERATE 입력 검토 실패 뒤에는 실패 이력을 남기고,
같은 대화 아래에 고정 확인 단계를 한 번 연다. 안내는 더 고정하도록 유도하지
않고 ‘유지할 근무만 고정하고, AI가 바꿔도 되는 근무는 고정을 풀기’로 한다.

- 현재 실패가 활성 상태이고 사용자가 다른 작업을 시작하지 않은 경우만 전환한다.
- 전환은 표/고정/규칙을 변경하지 않는다. 빈 표에서도 명시적 재실행 버튼을
  눌러야 실행한다. 폴링·재렌더·닫고 다시 열기로 자동 재실행하지 않는다.
- 고정 확인은 기존 표 클릭/신청 보호/일괄 고정/되돌리기 기능을 재사용한다.
  ‘모두 고정하기’는 ‘입력한 근무 모두 고정하기’로 범위를 명시한다.
- 버튼은 ‘다시 자동채우기’, ‘입력한 근무 모두 고정하기’(대상 있을 때),
  ‘근무 조건 확인하기’. 조건을 열면 준비를 일시 중단한다.
- 전부 고정된 표도 검토를 열어 잠금을 풀 수 있지만, 빈 편집 대상이 없는
  상태에서는 생성 버튼이 계속 비활성화된다.
- 권한/횟수 차단, 구성원 설정 복구, 구체적인 충돌 근거, 검증된 동의 후보와
  수정 제안은 기존 전용 복구 경로를 유지한다. ADJUST에는 적용하지 않는다.
- 이전 달/요청 확인은 앞선 실패 시도에서 완료했다. 이 복구 전환은 고정
  확인만 다시 열며, 새 결과 생성은 여전히 서버의 모든 검증을 거친다.

회귀: 일반 INFEASIBLE 실패 뒤 한 번만 준비, 빈 표 자동 재시도 방지,
고정 토글 후 새 입력 전송, 신청 보호·일괄 고정·되돌리기, 명시적 재실행,
오래된 실패/차단/동의·진단 경로 미간섭, 한국어/영어/일본어 문구.

## 검증

대화 저장 방식과 기존 대화 방식 모두 연결했다. 관련 4개 테스트 파일 259개가
통과했고, 이후 기존 제어문자 검사를 동일한 문자 코드 비교로 바꾼 뒤
실패 분류·준비 UI 42개를 다시 통과했다. 타입 검사와 변경 파일 lint를 확인한다.
로컬 실제 컴포넌트 미리보기에서 안내·3개 선택지·전체 고정 시 비활성화와
되돌리기를 확인했다. 서버 계약/DB/Flyway 변경과 운영 배포는 없다.
