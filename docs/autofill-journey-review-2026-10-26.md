# 자동채우기 실패 후 사용자 여정 점검

## 판단

실패 문구 뒤에 확인 버튼만 다시 보여주는 것으로는 복구가 끝나지 않는다. 사용자가 현재 보호 범위를 이해하고, 표와 조건 설정에서 수정한 다음 같은 준비 단계로 돌아올 수 있어야 한다. 자동채우기 재실행은 마지막 확인 버튼에서만 시작한다.

| Before                                                                                 | After                                                                                   | Why                                             |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------- |
| 고정 수정 후 조건 설정으로 이동하면 선택을 원복한다.                                   | 고정 선택을 현재 초안에 유지한 뒤 조건 설정으로 이동한다.                               | 사용자가 직접 고친 내용을 다음 시도에 반영한다. |
| 모두 고정한 상태에서 닫으면 툴바의 전체 고정 검사 때문에 준비 단계로 재진입할 수 없다. | 중단한 준비 단계를 우선 재개하고 고정을 해제할 수 있게 한다.                            | 실행 차단과 수정 화면 진입을 분리한다.          |
| 작은 화면에서 사이드바가 표를 가리지만 “표에서 눌러 주세요”라고 안내한다.              | 명시적인 표 편집 버튼으로 사이드바를 접고, 표 위에 선택 완료/선택 취소 동작을 제공한다. | 고정 선택 모드와 복귀 경로를 보이게 한다.       |
| 고정 확인에서 보호 범위가 불명확하고 키보드로 셀에 진입할 수 없다.                     | 수량 요약, 요청 보호 설명, 셀의 이름·날짜·근무·고정 상태와 키보드 이동을 제공한다.      | 변경 범위와 수정 방법을 확인할 수 있게 한다.    |

## 상태와 동작

- 닫기/표에서 고정 편집: 준비를 일시 중단하고 고정 선택 모드 및 원본 스냅샷을 유지한다. 표에서 선택 완료를 누르면 기존 질문으로 돌아온다. 같은 질문이나 스냅샷을 중복 생성하지 않는다.
- 선택 취소: 이번 준비 단계에서 바꾼 고정만 원복한다. 원래 근무와 신청근무는 유지한다. 생성 요청은 보내지 않는다.
- 근무 조건 확인: 현재 고정 선택을 초안에 유지하고 준비 화면을 접는다. 화면 전환 시 정리 함수가 선택을 되돌리지 않도록 스냅샷을 소비한다. 조건 확인 후 자동채우기를 누르면 확인 단계부터 이어 간다.
- 페이지를 떠나는 일반 동작에서도 사용자가 바꾼 고정을 유지한다. 새 대화를 명시적으로 시작하는 동작은 기존 계약대로 미확인 준비 선택을 초기화한다.
- 고정 수와 신청근무 수는 중복 계산하지 않는다. 빈칸의 오래된 보호 플래그는 보호된 배정으로 세지 않는다. “AI 변경 대상”은 빈칸과 보호되지 않은 배정 전체다.
- 고정 선택 표의 셀은 하나의 Tab 진입점과 방향키/Home/End 이동을 제공한다. Enter/Space로 고정을 전환한다. 신청근무와 빈칸은 탐색 가능하지만 전환하지 않는다. 일반 근무 편집의 키보드 동작은 유지한다.
- 실패 원인이 확인된 충돌 검토, 제약 완화 동의, 미확인 실행의 상태 조회, 성공 결과 확인 흐름은 기존 전용 경로를 유지한다. 같은 조건 재시도는 성공 보장이 아니므로 자동 실행하지 않는다.

## 검증

부모 화면 회귀 테스트로 고정 편집 → 닫기 → 재개, 전체 고정 → 닫기 → 해제, 조건 화면 이동/언마운트 후 고정 보존, 선택 취소, 명시적 확인 전 실행 없음, 질문 중복 없음, 요청 보호를 확인한다. 실제 캘린더 테스트로 키보드 이동·고정 상태·신청근무 보호를 확인한다. 실제 컴포넌트를 사용하는 합성 데이터 미리보기에서 작은 화면의 표 진입 및 복귀를 확인한다. 운영 데이터와 실제 AI 요청은 사용하지 않는다.

## 한계

이 변경은 프런트엔드 복구 흐름 개선이다. 원인 불명 실패가 모두 해결됐거나 같은 조건의 재시도가 성공한다고 주장하지 않는다. 생성기와 진단의 완전성은 별도 회귀 증거가 필요하다. DB와 API 계약 변경은 없다.

## 재진입 시 이력 보존

| Before                                                                         | After                                                            | Why                                      |
| ------------------------------------------------------------------------------ | ---------------------------------------------------------------- | ---------------------------------------- |
| 같은 표에 재진입하면 준비 질문·응답 및 기존 사이드바의 실패 이력이 초기화된다. | 인증 주체·병동·근무팀·년월별로 준비 단계와 대화 기록을 복원한다. | 이미 확인한 내용과 실패 맥락을 유지한다. |

- 서버 대화의 요청·실행 기록은 기존 서버 조회를 유지한다. 화면에서만 관리하던 준비 메시지와 버튼 응답을 보충 저장한다. 기존 사이드바의 해석·실패·결과 기록도 브라우저 저장소에 유지한다.
- 저장 범위는 일반 계정/병동 관리자 계정 구분 + 계정 ID + 병동 + 근무팀 + 년월이다. 같은 숫자의 일반 계정과 관리자 계정도 섞이지 않는다. 인증 주체를 확인할 수 없으면 저장하지 않는다.
- 다른 화면으로 갔다 돌아오거나 새로고침해도 기록을 읽는다. 준비 중이었다면 중단 상태로 복원하고, 실행 중 떠났다면 결과 미확인 안내를 남긴다. 복원은 생성·해석·결과 적용을 실행하지 않는다. 과거 해석/결과의 실행 버튼도 되살리지 않는다.
- 대화 기록에서 과거 근무표를 현재 초안에 자동 적용하지 않는다. 현재 표 데이터는 기존 편집기/서버 경로를 따른다. 명시적 새 대화는 기존 초기화 동작을 유지한다.
- 수정 준비 도중 화면을 떠난 경우, 복원한 준비 질문은 이력으로만 보여주고 수정 요청을 다시 검토하게 한다. 메모리의 수정 실행 약속이 사라진 것을 전체 생성 요청으로 대체하지 않는다.
- 수정 기능이 열리지 않은 계정도 생성 결과와 대화 이력은 볼 수 있다. 수정 실행 권한은 기존대로 제한한다.
- 저장이 차단되거나 용량이 부족하면 현재 화면은 유지하고 실제 저장 실패 안내를 표시한다. 준비 기록과 기존 사이드바의 기기 간 동기화는 이번 브라우저 저장 방식에 포함되지 않는다. 서버 저장분은 기존 동작대로 조회할 수 있다.

## 흐름별 확인 범위

| 상황                         | 이어지는 행동                                          | 확인 방법                                             |
| ---------------------------- | ------------------------------------------------------ | ----------------------------------------------------- |
| 고정/신청근무가 있는 표      | 보호 범위 확인 → 표 편집 → 선택 완료 → 실행 확인       | 실제 부모 화면 회귀 테스트 + 375px 실제 컴포넌트 검토 |
| 원인 불명 생성 실패          | 실패 이력 유지 → 고정/조건 수정 → 명시적 재시도        | 신규 및 기존 사이드바 회귀 테스트                     |
| 검증된 충돌 또는 제약 완화안 | 기존 날짜·간호사·고정 배정 검토 및 동의 경로           | 기존 전용 실패/동의 테스트 유지                       |
| 실행 결과 미확인             | 기존 서버 상태 조회 유지, 기존 화면 실행은 미확인 안내 | 중단 실행 및 재진입 회귀 테스트                       |
| 성공 결과                    | 결과 검토와 근무표 확정 단계 구분                      | 기존 결과/확정 회귀 테스트 유지                       |
| 같은 표 재진입               | 이전 질문·응답·실패 이력 복원, 자동 실행 없음          | 언마운트/재마운트 및 계정·년월 격리 테스트            |

모바일의 기존 반높이 준비 시트는 질문과 수정 버튼을 동시에 보여주기 부족했다. 고정 확인 단계는 전체 높이로 보여주고, 명시적인 표 편집 버튼으로 시트를 접어 표 전체를 사용한다. 표 편집 안내는 좁은 화면에서 세로로 배치한다.

## 검증 결과

- 근무표 관련 82개 테스트 파일, 1,053개 테스트 통과. 재진입 시 질문/실패 응답 보존, 계정/월 격리, 중단 실행의 자동 재요청 방지, 수정 준비의 전체 생성 오인 방지, 권한 제한 계정의 이력 열람을 포함한다.
- TypeScript 검사와 프로덕션 빌드 통과. 변경한 TypeScript 파일 ESLint 및 포맷 검사 통과.
- 합성 데이터로 실제 준비/사이드바/캘린더 컴포넌트를 데스크톱과 375×812 화면에서 확인했다. 키보드로 고정 해제 → 신청근무로 이동 → 변경 차단 → 확인 단계 복귀 시 수량 유지, 전체 고정 시 실행 차단을 확인했다. 부모 화면 전환은 위 회귀 테스트로 검증했다.
- 운영 AI 호출/데이터 수정/배포 없음. Actions는 승인된 비용 제한에 따라 실행하지 않고 로컬 검증을 사용한다.
