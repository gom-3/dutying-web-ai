# 자동 채우기 진행상황과 입력 잠금

## 문제

진행 상황 보기가 `isAiExecutionDismissed`를 켜고, 사이드바가 열리면 로딩 오버레이도 렌더링하지 않는다. 이 표시 상태가 캘린더와 키보드 입력 잠금까지 해제해 계산이 끝난 것처럼 보이고 편집을 허용한다.

## 변경

- 진행 상황 보기는 사이드바를 열면서 로딩 오버레이를 유지한다. 닫아 둔 계산의 진행상황을 다시 열 때도 두 화면을 함께 복원한다.
- 사이드바가 열리면 기존 오버레이의 데스크톱 우측/모바일 하단 여백을 사용한다.
- 근무표 셀, 지난달 근무, 행 순서, 키보드/붙여넣기 입력은 실행 및 완료 애니메이션 중에 잠근다. 간호사 정보 단계로의 이동은 기존 단계 이동 잠금을 유지한다.
- 로딩창을 명시적으로 닫고 계산을 계속해도 계산 중 편집 잠금은 유지한다.
- 잠금은 현재 실행 콜백 수명에만 연결한다. 과거 실행 상태 표시나 진행상황 열기로 새 잠금을 만들지 않는다. 실패·취소는 즉시 해제하고 성공은 보이는 완료 애니메이션 뒤 해제한다. 숨긴 상태에서 완료되면 보이지 않는 애니메이션 잠금을 남기지 않는다.
- 서버 잠금/API/DB 변경 없음. Flyway migration 없음.

## 검증

실제 키 바인딩을 사용하는 페이지 테스트로 진행상황/사이드바/로딩창의 공존, 숨김 뒤 재열기, 계산 중 입력 차단, 성공·실패·취소 후 입력 재개와 과거 상태 재열기를 확인한다. 기존 오버레이 테스트와 페이지 테스트, 타입 검사 및 빌드를 로컬에서 실행한다.

## 로컬 검증 결과

- 자동 채우기/조절 페이지, 실제 대화 사이드바, 진행상황, 오버레이, 실행 도크: 6개 파일 325개 테스트 통과.
- 페이지 단계 이동/제약조건 진입 보호: 18개 테스트 통과.
- `pnpm type-check`, `pnpm --dir apps/app exec vite build`, 변경 TS/TSX 4개 파일 ESLint 및 `git diff --check` 통과.
- 테스트의 기존 React `act` 경고와 빌드의 청크 크기 경고가 남아 있다. 실제 운영 화면 검증 및 배포는 이 작업 범위에 포함하지 않았다.
- Actions 중복 검증을 피하기 위해 로컬 검증 후 커밋에 `[skip ci]`를 사용한다. 다른 호스팅 제공자의 빌드 생략을 의미하지 않는다.
