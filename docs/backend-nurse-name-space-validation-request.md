# 백엔드 요청: 간호사 이름 공백 허용

## 배경

온보딩에서 간호사를 등록한 뒤 병동 생성/근무자 등록 API를 호출할 때, 간호사 이름에 띄어쓰기가 포함되면 백엔드 유효성 검사에서 실패합니다.

현재 프론트 온보딩 기본 이름과 엑셀 파싱 결과에는 `신규 간호사 1`, `Nurse 1`처럼 공백이 포함될 수 있습니다. 실제 사용자도 이름/식별용 별칭에 공백을 입력할 가능성이 있어, 백엔드 이름 검증에서 공백을 허용해 주는 처리가 필요합니다.

## 현재 오류

```json
{
  "code": "INVALID_TYPE_VALUE",
  "message": "파라미터 타입이 올바르지 않습니다.",
  "errors": [
    {
      "field": "name",
      "message": "이름은 한글, 영문, 숫자만 입력 가능합니다."
    }
  ]
}
```

발생 API 예시:

```http
POST /wards/{wardId}/shift-teams/{shiftTeamId}/nurses
```

## 요청 사항

간호사 이름 `name` 검증 규칙에 일반 공백 문자를 허용해 주세요.

권장 규칙:

```regex
^[가-힣A-Za-z0-9 ]{1,20}$
```

권장 처리:

- 앞뒤 공백은 `trim` 처리합니다.
- 이름 중간의 일반 공백은 저장/응답에서 보존합니다.
- 줄바꿈, 탭 등 제어성 whitespace는 허용하지 않습니다.
- 전체가 공백인 값은 기존처럼 invalid 처리합니다.

## 영향 API

아래 API의 `name` 또는 `nurseNames[]` 검증에 동일하게 반영이 필요합니다.

- `POST /wards/{wardId}/shift-teams/{shiftTeamId}/nurses`
- 간호사 수정 API의 `name` 필드
- `POST /wards` 요청의 `shiftTeams[].nurseNames[]`
- 온보딩/병동 생성 후 간호사 seed 과정에서 사용되는 간호사 생성 로직

## 예시

허용되어야 하는 값:

```text
홍 길동
신규 간호사 1
Nurse 1
Kim Nurse 2
```

계속 거부되어야 하는 값:

```text
홍@길동
Nurse_1
   
홍
```

## 완료 기준

- `name: "신규 간호사 1"`로 간호사 생성 시 `400 INVALID_TYPE_VALUE`가 발생하지 않습니다.
- 생성된 간호사 조회 응답에서 이름이 `"신규 간호사 1"`로 유지됩니다.
- `/member` 근무자 관리 화면에서 공백 포함 이름이 그대로 표시됩니다.
- 기존 한글/영문/숫자 이름 검증은 그대로 유지됩니다.

## 프론트 임시 대응

현재 프론트는 백엔드 400을 피하기 위해 저장 직전에 공백을 제거하는 임시 방어 로직을 둘 수 있습니다. 다만 이 방식은 사용자가 입력한 이름을 훼손하므로, 백엔드에서 공백 허용이 반영되면 프론트 정규화 로직은 제거하고 원본 이름을 저장하는 방향이 적절합니다.
