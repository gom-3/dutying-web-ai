2026-11-03 · Web + Spring · develop 반영용 · 운영 미배포

원인과 변경

  • 직접 실행 UI가 서버의 확인 토큰을 버렸습니다. 이제 이번 실행의 후보와 원본 입력을 유지하고, 동의한 후보만 반영합니다.
  • 현재 초안 위에 과거 확정본의 고정값을 덮어썼습니다. 사용자가 제출한 OFF·빈칸·고정 해제를 유지합니다. 누락 셀의 기본값과 수락된 신청근무 보호는 유지합니다.
  • 자동으로 열리던 대화 수정 소개 모달과 반복적인 포괄 안내를 제거했습니다.
  • 표·규칙이 바뀌거나 시간이 지나면 이전 후보는 사용할 수 없습니다. 설정 변경 후에는 새 계산으로 진행합니다.

FE 확인 항목

  1. 자동채우기 후 충돌 후보가 있으면 동의 버튼이 나타나고, 확인 전 표는 그대로인지 확인합니다.
  2. 동의 요청에 conflictReviewToken과 conflictConfirmed=true가 담기며 원본 초안·판본·요청이 유지되는지 확인합니다.
  3. 수동 편집·조건 변경 후 이전 후보를 바로 적용할 수 없는지 확인합니다.
  4. 확정본에서 고정되었던 근무를 직접 OFF로 수정한 경우 최신 OFF가 다음 엔진 입력에 남는지 확인합니다. 수락된 신청근무는 기존 보호 정책을 따릅니다.
