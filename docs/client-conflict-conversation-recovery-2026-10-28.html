자동채우기 충돌 후 대화 복구

2026-10-28 · Web 수정 · DB/Flyway migration 없음

원인과 변경

충돌 확인 상태에서 공통 복구 행동을 숨기고, 기존 자동채우기 경로의 충돌 모달은 사이드바보다 낮은 화면 계층에 있었다. 요청 바꾸기도 입력창을 열지 않고 사이드바만 다시 열었다.

  • 기존 충돌 확인 컴포넌트를 실패 말풍선 안에 연결한다. 원인·규칙·날짜·인원 근거와 선택지가 같은 대화에 표시된다.
  • 후보가 없어도 실패 기록에는 표시용 근거를 남긴다. 동의 토큰은 표시용 실패 객체에 복사하지 않는다.
  • 조건 확인하고 다시 채우기는 기존 준비 흐름으로 연결한다. 조건 저장 자체로는 실행하지 않으며, 재실행은 기존 채우기 방식을 유지한다.
  • 요청 바꾸기는 입력창을 복원한다. 상세가 없으면 확인하지 못했다고 명시하며, 상세 없는 후보 적용은 차단한다.
  • 최신 실행이 실패하면 안내를 닫아도 대화의 확정 버튼을 숨긴다. 후속 정상 성공은 기존 확정 흐름으로 이어진다.
  • 만료·초안 변경·중복 제출 차단은 유지하며 새 실행 시 이전 후보를 제거한다.

검증

모델·충돌 목록·동의·공통 실패·legacy 대화 78개, 사이드바 집중 3개, legacy 설정 수정 2개 통과. 별도 초기 집중 회귀 90개도 통과했다. 타입 검사, 변경 TypeScript ESLint, diff 검사를 완료했다. 테스트는 합성 API 응답과 실제 컴포넌트 DOM 통합 기준이며 실제 서비스 배포·엔진 생성 검증은 수행하지 않았다.

FE 확인 포인트

  1. 충돌 결과의 날짜·근무·대상·설정값을 확인한다.
  2. 설정 직접 수정 → 저장 → 조건 확인하고 다시 채우기 → 기존 준비 확인 → 재실행으로 이어지는지 확인한다.
  3. 요청 바꾸기 → 입력창에서 조건 변경 → 확인 후 실행을 확인한다.
  4. 실패·누락 상세·만료 상태에서 대화의 근무표 확정 버튼이 없는지 확인한다.
  5. 고정·승인된 배정을 유지하고, 정상 후속 성공 이후 확정 흐름이 복귀하는지 확인한다.

관련 세션의 기존 상세 표시·stale 복구 구현을 재사용했으며, 해당 세션의 변경을 중복 구현하거나 배포하지 않았다.
