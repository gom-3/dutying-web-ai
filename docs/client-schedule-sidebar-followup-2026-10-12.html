근무표 사이드바 2차 검토

2026-10-12 · 기존 PR #57 추가 개선

첫 검토는 기능별 성공/실패와 문구에 집중했어요. 이번에는 클릭 이후 응답을 기다리는 동안의 편집·선택 변경, 기존 결과 재개, 저장 요청 관리까지 연결해서 확인했어요. 더 이상 개선점이 없다는 의미는 아니며, 아래는 코드와 테스트로 근거를 확인한 범위예요.

우선순위상황문제개선근거
높음계산 결과를 받는 동안 수동 편집결과 조회 전에는 변경 여부를 확인했지만, 조회가 끝난 뒤에는 확인하지 않아 새 편집을 덮어쓸 수 있었어요.적용 직전에 편집 버전을 다시 확인해요. 바뀌었으면 결과를 보관하고 현재 표를 유지해요.수정 전 재현 실패 → 수정 후 통과
높음이전 결과로 이어 쓰기 재개처음 전환할 때 보호해도, 다시 이어 쓰는 동안 동기화를 기다리면 같은 문제가 생겼어요.동기화가 끝난 뒤 다시 확인해요. 기다리는 중 고친 표는 유지하고, 전환하지 않았다고 안내해요.재개 중 추가 편집 회귀 테스트
높음제안을 선택한 뒤 만료·조건 변경처음 제안 버튼을 누를 때만 확인했어요. 최종 실행 전에는 오래된 제안이 서버까지 넘어가 불필요한 실패가 생길 수 있었어요.실행 직전에 최신 대화를 조회하고 표 버전·해석·조건·유효 시간·검증 상태를 다시 확인해요. 만료 이유를 안내하고 계산은 보내지 않아요.만료·조건 변경·버전 변경 거절, 유효한 제안 실행
높음저장 요청 수정 후 다른 항목 선택수정 대상 ID가 남아 다른 항목을 선택하고 저장해도 이전 요청이 덮어써졌어요.다른 항목 선택·새 요청·전송·삭제 시 수정 대상을 정리해요. 기존 항목 수정은 별도 버튼 이름으로 알려 줘요.수정 전 재현 실패 → 수정 후 통과. 명시적인 수정도 통과
보통입력 오류의 다음 행동글을 줄이거나 요청을 고쳐야 하는데 결과 다시 확인하기가 표시돼 해결되지 않는 버튼을 누르게 했어요.입력 오류에는 무관한 조회 버튼을 숨겨요. 미확인 실행은 계산 중에도 같은 결과를 다시 조회할 수 있어요.로컬 오류 분류 및 만료 제안 화면 확인
보통새 요청에 남는 이전 선택 상태이전 결과 재개 버튼이나 선택 제안·수정 대상·의견 입력 상태가 다음 요청에도 남을 수 있었어요.새 요청/정상 전환 시 이전 작업 상태를 함께 정리해요. 처리 중에는 저장 요청 버튼으로 입력을 바꾸거나 제안 취소를 오해하지 않게 막아요.기존 새 요청/전환 회귀 검사 유지

  • 오래된 제안: “표나 조건이 바뀌었거나 제안의 유효 시간이 지났어요. 최신 요청으로 다시 수정해 주세요.”
  • 새 저장: “자주 쓰는 요청으로 저장하기” / 기존 항목 변경: “저장한 요청 수정하기”

검증 범위

관련 35개 파일 384개 테스트 통과. 마지막 문구/저장 요청 수정 구분 후 75개 집중 테스트, 타입 검사, 변경 소스 린트도 통과했어요. 첫 두 문제는 수정 전 테스트에서 실제 실패했고 수정 후 통과했습니다.

기존 서버의 만료·승인 검증을 대체하지 않아요. 프런트엔드에서 불필요한 요청과 잘못된 행동 안내를 줄이는 개선이에요. 모델/알고리즘/API 형식/DB 변경과 운영 배포는 없습니다.

완료라고 단정할 수 없는 범위

실제 병동 사용자의 요청 표현, 실제 생성 결과의 품질, 장시간 연결 중단과 여러 기기의 동시 편집은 이번 로컬 검사만으로 보장할 수 없어요. 이런 부분은 운영 검증이 끝난 것으로 표시하지 않습니다.
