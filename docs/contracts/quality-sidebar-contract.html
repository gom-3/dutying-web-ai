전후 품질 요약 계약: quality-sidebar-v1

엔진 응답의 engineResult.qualitySidebar에 추가된다. GENERATE·ADJUST·REPAIR의 공통 반환 경계에서 부착한다. 기존 status, traceStatus, changedCells, qualityMetrics, qualityStatus와 기본 목적함수는 변경하지 않는다. UI와 Spring 연결은 이 계약을 읽는 별도 작업이다.

기계 계약: JSON Schema. 합성 예제: 6개 JSON 예제. 기준 모델: src/services/quality_sidebar_contract.py. 엔진 어댑터: src/services/quality_sidebar_response.py.

항상 존재하는 구조

필드의미

개인별 지표

모든 간호사에 아래 6개 metricId가 고정된 순서로 존재한다. 각 항목은 metricId, unit, kind, betterDirection, before, after, delta, change를 제공한다. before/after/delta는 모두 {state, value, reasons}. KNOWN이면 유한 숫자와 빈 reasons, UNKNOWN이면 null과 1개 이상의 사유 코드다. 0은 측정된 0이며 UNKNOWN의 대체값이 아니다.

metricId단위/좋은 방향계산과 해석
offTargetDeviationdays / LOWER개인 OFF 목표 [min,max] 밖 거리. 실제 solver에 전달한 전체 목표 구간을 qualityOffTargetRangesByNurse로 보존해 양쪽 평가에 동일하게 사용한다. 퇴근일 NIGHT_CONTINUATION은 현행 월 OFF 집계 계약에 따라 포함한다. 전체 목표가 없으면 UNKNOWN; worst 상위 5명 요약으로 나머지 목표를 추정하지 않는다.
nightDeviationshifts / LOWER동일 자격·고정 휴가 기반 가용일 집단에서 야간 수와 집단 평균의 거리. 단독/야간 불가 집단은 UNKNOWN. 야간 횟수 자체의 증감이나 법적 야간 상한을 뜻하지 않는다.
fragmentationRateratio / LOWER가용 구간의 O-W-O 및 W-O-W 패턴 수 / 비교 기회 수. 고정된 불가피 패턴과 승인 휴가 구간은 제외한다. 기회 0건이면 UNKNOWN.
minimumRecoveryHourshours / HIGHER현재 근거에서 관찰된 실제 근무 사이 최솟값. 근무 시각 또는 전이 근거가 없으면 UNKNOWN. 이전·다음 달 경계가 미상인 경우 전이 최솟값이 계산되더라도 global unknownReasons에 경계 누락을 표시한다.
preferenceSatisfactionRateratio / HIGHER자격·날짜·고정 셀 충돌을 제외한 유효 요청 중 만족 비율. 요청 0건은 UNKNOWN이다. 모든 요청의 전역 실현 가능성 증명은 아니다.
changedCellscells / LOWER완전한 원본 대비 다른 코드의 셀 수. kind=CHANGE_COST이며 나머지는 QUALITY. 변경 비용은 개인별 변화·harm에는 포함하지만 observedRelation의 품질 우열에는 포함하지 않는다. 원본이 불완전하면 UNKNOWN.

delta = after − before이며 소수점 8자리로 반올림한다. HIGHER 지표는 음의 delta가 손해다. change는 IMPROVED/WORSENED/UNCHANGED/UNKNOWN이다. harm.maxWorsening은 손해 방향 변화량의 절댓값이고, 비교 가능한 사람 중 손해 0이면 0, 비교 가능한 사람 0이면 null이다. netDelta는 비교 가능한 사람의 원시 delta 합이며 서로 다른 단위의 합 또는 단일 품질 점수로 사용하지 않는다. 비교 가능 인원과 UNKNOWN 인원도 반드시 함께 읽는다.

엔진 연결과 안전

원본은 request.cells, 후보는 원본에 response.changedCells를 적용한 표다. 두 완전한 표를 evaluate_draft의 공용 최종 hard gate로 평가한다. 목표 구간·자격·요청·fixed·전월 컨텍스트는 같은 입력을 사용한다. 원본이 불완전하면 후보만 평가하고 before/delta는 UNKNOWN. 수락된 무변경 응답은 실제 원본을 후보로 평가할 수 있다. 거절된 숨김 후보는 after가 UNKNOWN이다.

품질 요약의 실패는 기존 생성/조절/거절을 500으로 바꾸지 않는다. 예상 가능한 진단 입력 ValueError/TypeError/KeyError는 UNKNOWN 요약으로 변환한다. 서버·개발 오류 전체를 blanket 처리하지 않는다. 후보 재검증·비교는 solver/LLM/DB 호출 없이 수행하며 무변경이면 동일 평가를 재사용한다. 응답에는 표 전체, 이름, 프롬프트, 원본 규칙을 복제하지 않는다.

BLOCKED인데 observedRelation이 CANDIDATE_BETTER인 합성 예제가 있다. 이는 측정된 일부 품질은 개선됐지만 후보가 수락되지 않았다는 뜻이다. Web/Spring은 이 값으로 엔진 상태를 승격해서는 안 된다. 비어 있는 기존 품질 점수, 평균 개선, 단일 netDelta로 개인 손해나 UNKNOWN을 숨기지 않는다.

호환성과 검증

새 소비자는 contractVersion을 확인하고 JSON Schema로 별도 필드를 검증할 수 있다. 기존 engineResult는 확장 가능한 dictionary이므로 OpenAPI의 전체 engineResult를 제한된 새 모델로 바꾸지 않았다. 비호환 필드 의미·이름·단위 변경은 새 contractVersion을 사용하며 예제·schema·테스트를 함께 갱신한다.

tests/unit/test_quality_sidebar_contract.py는 순변화 -3에 숨은 개인 손해 +6, 빈 원본의 null delta, 숨긴 거절 후보, 변경 비용 분리, 컨텍스트 불일치, 잘못된 진단 입력, KNOWN/UNKNOWN 상태 불변식 및 엔진 status/changedCells 보존을 검사한다. 기존 draft patch·adjust corpus 계약 테스트 98개 통과. 배포, Web, Spring 및 기본 목적함수 변경 없음.
