대화형 자동완성 구현 및 연동

2026-10-03 설계 06을 기준으로 서버와 Web에 구현한 초기 릴리스입니다. 기존 자동완성과 수동 스냅샷은 유지합니다.

활성화

서버 환경변수 DUTYING_SCHEDULE_CONVERSATION_ENABLED=true로 활성화합니다. 기본값은 false이며 workspace의 conversationEnabled가 Web 경로를 선택합니다. Flyway V54가 다섯 개 테이블을 추가합니다. 이번 작업에서는 배포하거나 DB에 적용하지 않았습니다. 배포 시 애플리케이션의 Flyway 자동 적용 후 history와 실제 스키마를 확인해야 합니다.

실행 흐름

개인별 월 대화를 만들고 현재 초안을 동기화합니다. 자동완성은 EMPTY_ONLY가 기본이며 REBUILD_UNLOCKED는 명시적 확인이 필요합니다. 조절은 요청 해석 → 확인 카드 수정 또는 확인 → 실행 순서입니다. 이전 제안과의 관계는 사용자에게 추가·교체·초기화로 명시하도록 하며 자동 대화 의도 분류기는 이번 구현에 포함하지 않습니다. 해석 모델에는 이번 발화만 보내며 이전 구조화 조건은 서버가 명시적 관계에 따라 합칩니다. 전체 대화 기록을 AI 입력으로 보내지 않습니다.

API

공통 경로는 /wards/{wardId}/shift-teams/{shiftTeamId}/schedule입니다.

  • POST/GET conversations, GET conversations/{id}: 개인 대화 생성·목록·상세
  • PUT conversations/{id}/draft: revision 기반 초안 동기화
  • POST conversations/{id}/interpretations, PUT conversations/{id}/interpretations/{interpretationId}: 해석·편집 확인
  • POST conversations/{id}/operations, GET conversation-operations/{operationId}: 멱등 실행·복구 조회
  • GET result-versions/{versionId}, POST conversations/{id}/branches: 읽기 전용 과거 표·새 대화 분기
  • GET/POST conversation-preferences, PUT/DELETE conversation-preferences/{id}: 명시적으로 확인한 개인 요청 관리

기록과 보호

대화는 소유자에게만 노출하며 결과 버전은 권한 있는 동일 병동·팀에서 조회합니다. 결과 셀·행 순서·조건은 불변 버전으로 저장하며 기존 수정 가능 스냅샷의 10개 제한에 연결하지 않습니다. 미리보기는 현재 표를 변경하지 않으며 이어서 작성은 새 대화를 생성합니다. 행 순서를 숙련도 신호로 보존합니다.

실행은 revision과 조건 hash를 확인합니다. 실행 중 표가 바뀌면 결과를 기록하되 현재 초안을 덮어쓰지 않습니다. 같은 idempotencyKey 재시도는 같은 요청의 기존 실행을 돌려줍니다. RESULT_READY는 저장된 결과로 최종화를 재시도합니다. 장시간 결과가 확인되지 않은 실행은 UNKNOWN으로 표시하고 자동 재계산하지 않습니다. 저장하지 못한 엔진 결과는 자동 재현할 수 없으므로 운영에서 결과 확인이 필요합니다.

이번 실행의 조절 조건은 월별 설정이나 학습 선호로 암묵적으로 저장하지 않습니다. 저장한 개인 요청은 입력에 제안하고 사용자 확인 없이 적용하지 않습니다. 기존 생성기가 지원하지 않는 활성 OFF_GOAL/GOAL이 있으면 생성 요청을 거절하고 조절 사용을 안내합니다.

검증과 출시 확인

서버 관련 서비스·권한 경계 테스트와 빌드, Web 새 대화 및 기존 자동완성 화면 테스트와 타입 검사·빌드를 검증했습니다. 실제 MySQL migration 적용, 인증된 브라우저와 실 LLM을 연결한 종단 간 실행, UNKNOWN 운영 복구, 장기 결과 보관량 정책은 배포 전 확인이 필요합니다. 엔진의 기존 workspace 조회를 재사용하므로 모든 실행 메타데이터를 단일 원자적 스냅샷으로 준비하는 엔진 재구성은 포함하지 않습니다.
