# 충돌 후 대화 복구

최신 develop의 충돌 상세·동의 컴포넌트를 재사용한다. 별도 세션의 stale 비교 수정은 복제하지 않는다.

- conflictReview의 설명·규칙·날짜·인원 근거를 실패 기록에도 보존한다. 동의 토큰은 실패 설명에 복제하지 않는다. 상세가 없으면 원인을 확인하지 못했다고 명시한다.
- 충돌 확인에서도 설정 수정·요청 수정·조건 확인 후 다시 채우기를 제공한다. 생성 재시도는 기존 준비 흐름을 사용한다. 동의 후보 적용과 재생성을 구분하고, 만료 토큰 재사용·자동 실행은 금지한다.
- 최신 실행 실패는 안내를 닫아도 확정 버튼을 노출하지 않는다. 정상 성공 후에는 기존 확정 동작을 유지한다. 과거 실패가 새 성공을 막지는 않는다.
- legacy 실패에서도 상세·복구 선택지를 유지한다. 기존 공통 충돌 동의 UI가 포함된 경우 상세 목록 중복은 피한다.
- 검증: 원인 표시, 상세 누락, 만료 후보, 조건 수정 후 재시도, 요청 입력 복원, 실패 후 확정 숨김 및 성공 후 복귀를 집중 회귀로 확인한다. DB/schema 변경 없음.

기존 legacy 충돌 modal은 z-index 200, 사이드바는 1400이었다. 모달을 제거하고 같은 ConstraintConflictReview를 실패 말풍선 안에 렌더한다. 요청 바꾸기는 단순히 사이드바만 여는 대신 입력창을 복원한다. 새 실행 시작 시 이전 pendingConflict를 제거한다.
