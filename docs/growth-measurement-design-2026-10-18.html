웹·앱 성장 측정 설계

2026-10-18. GA 권장 sign_up/login/tutorial_complete와 제품 성공 이벤트를 구분한다. LLM은 집계 JSON·이벤트 사전·소스 상태를 읽고 근거/가설/다음 실험을 구분한다.

웹은 운영 .ai 호스트만 수집하고, 가입 API 성공·병동 생성 성공·근무표 확정 성공 이후 기록한다. 기존 UI 클릭은 전환으로 취급하지 않는다. 앱은 Firebase Analytics를 추가하며 운영 릴리즈에만 수집한다. 로그인/가입/소개 완료를 기록한다. 환자·간호사 이름, 연락처, 토큰, 병동 ID, 근무표 내용은 보내지 않는다.

구/신 속성과 앱 streamId를 분리한다. 기존 앱 수치는 .ai 앱 수치가 아니다. 새 이벤트는 배포 이후만 존재한다. signup→ward_created→schedule_confirmed는 사용자 기반 순서 퍼널로 계산하며 단순 이벤트 수를 나누지 않는다. GA와 검색 통계 시간대 차이 및 확정 데이터 지연을 표시한다.

외부 광고비는 연결 검증 전 비용·ROAS를 추정하지 않는다. 인스타그램 도달과 웹 사용자를 동일 인물로 합산하지 않는다. 예약 작업은 사용하지 않는다.

근거: GA 권장 이벤트, Flutter 이벤트, GA MCP

검증 및 반영 상태

웹 관련 테스트 140개, TypeScript 검사, 운영 빌드 통과. 기존 AI 화면 테스트 6개는 기본 5초 제한을 초과했으나 20초 제한 재실행에서 61개 전체 통과했다. 신규 분석 모듈 및 변경한 인증/등록 모듈 lint 통과. 기존 대형 화면의 변경하지 않은 줄에는 기존 스타일 오류가 남아 있다. 실제 Google MCP 집계 조회 성공. 새 AI 속성의 sign_up/ward_created/schedule_confirmed 주요 이벤트 등록 완료. 서비스 코드 배포 및 Meta 외부 연결은 아직 완료되지 않았다.
