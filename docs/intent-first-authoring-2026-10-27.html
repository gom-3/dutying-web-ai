의도 우선 근무표 작성 · Web

2026-10-27. .ai Web의 협상된 intent-first-v1 경로다. 공통 DESIGN.md §7과 합성 contract-examples.json을 기준으로 구현했다. 복제한 공통 fixture는 apps/app/src/pages/make-shift/model/__tests__/fixtures/intent-first-v1.json이다.

실행과 적용

  • workspace의 기능 flag와 지원 버전을 모두 확인한다. 기존 서버와 미지원 사용자는 기존 계약을 유지한다.
  • 최신 revision/context/sourceVersion, 유효한 plan/deadline, 서버의 autoExecutable이 모두 맞을 때 해석한 일회 요청을 추가 확인 없이 실행한다. scope·severity의 기존 설문 경로를 새 요청에 끼워 넣지 않는다. OPERATION 기본값과 명시 ROSTER 조건은 서버가 해석한다.
  • 최종 top-level authoringOutcome을 사용한다. engine의 metadata만으로 새 표를 반영하지 않는다. VERIFIED Python+Spring, 보호 PASS, completeTarget, exact 절 충족과 APPLIED receipt/result version을 검사한다. approvable은 별도이며 사람의 최종 확정 권한을 바꾸지 않는다.
  • 후보 patch는 candidate.changedCells에서만 읽는다. 독립 diff에 표시하며 현재 표에 merge하지 않는다. 선택 시 원래 token/digest/sourceOperation/sourceVersion을 보내고 새 해석이나 solve를 요청하지 않는다.
  • EXACT+REVIEW는 전체 후보를 검토한 뒤 같은 후보를 적용한다. 적용 후에도 REVIEW=UNVERIFIED, requestState=NEEDS_REVIEW를 유지해 정성적 충족을 성공으로 꾸미지 않는다.

경고와 복구

  • 기존/개선/해결/신규/악화 위반은 서버의 좌표별 delta 그대로 공개한다. Web에서 위반 총수만으로 비교하거나 동의 범위를 확대하지 않는다. 작은 양보/기승인 양보는 다시 확인하지 않는다.
  • 적용 후 경고를 표에 유지하며 source version으로 한 번에 취소할 수 있다. 수동 편집이나 현재 server version이 달라졌으면 취소를 차단한다. 대화/결과 기록은 지우지 않는다.
  • 후보 만료 시 실행만 무효화한다. 같은 owner/ward/team/year/month의 기존 composer와 기록 키, 서버 대화 및 진행 요청을 유지한다. admin 진행 요청도 실제 owner ID로 격리한다.
  • UNKNOWN/BUSY/불가능 증명/이미 만족/개선 없음/부분 개선/정성 검토를 구분한다. 정상 완료 no-change는 version을 전진시키거나 undo를 만들지 않는다.

증거와 한계

집중 component/state/API 테스트, 타입 검사, lint, production build 및 합성 로컬 CUA 화면을 검증한다. 합성 fixture와 mock conversation API를 사용한 테스트는 실제 Spring→Python solver 통합 또는 모델 품질/운영 지연 검증이 아니다. 공통 QA 세션이 실제 서버·솔버·원본 사고의 재현과 end-to-end deadline을 별도로 검증해야 한다. 유료 모델 호출, push/PR/merge/배포는 수행하지 않는다.
