# 근무유형 약자 변경 시 미확정 근무표 호환 설계

## 원인

- 확정 근무표와 서버 스냅샷은 셀을 `wardShiftTypeId`로 저장하므로 약자를 바꿔도 같은 근무유형을 새 약자로 표시한다.
- `/make`의 브라우저 임시저장은 셀을 약자 문자열로만 저장한다.
- 현재 재진입 마이그레이션은 저장된 약자가 현재 목록에 없으면 서버 기본 셀로 치환한다. 미확정 셀의 서버 기본값은 `null`이므로 로컬에만 있던 배정이 빈칸으로 소실된다.

## 변경

1. 편집 문서에 당시의 `wardShiftTypeId`와 약자 매핑을 함께 저장한다.
2. 재진입 시 저장 당시 ID를 현재 근무유형 ID와 연결해 새 약자로 변환한다.
3. 매핑이 없는 구버전 드래프트는 기본 근무 약자(`D/E/N/O`)의 classification을 이용해 유일한 기본 근무유형으로 변환한다.
4. 이미 잘못된 마이그레이션으로 빈칸이 저장된 드래프트는 적용된 편집 이력의 마지막 셀 값을 복구 후보로 사용한다.
5. 변환 후에는 현재 매핑으로 임시저장을 갱신해 이후 약자 변경도 ID 기반으로 처리한다.

## 안전 조건

- 저장 당시 ID가 현재도 존재할 때만 일반 약자 변경을 자동 변환한다.
- 구버전 기본 약자 복구는 classification과 교대제가 일치하고 대상이 유일하거나 기본 근무유형으로 식별될 때만 수행한다.
- 사용자가 실제로 비운 셀은 편집 이력의 마지막 값도 `null`이므로 복구하지 않는다.
