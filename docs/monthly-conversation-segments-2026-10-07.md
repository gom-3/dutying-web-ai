# 월별 대화 유지와 실행 구간

## 의도와 확인한 결함

병동·근무팀·월 안에서 요청과 결과가 계속 남아야 한다. 현재 화면은 목록의 첫 대화만 열고, '새 채팅'과 과거 결과의 '이어서 작성'이 별도 대화를 만들기 때문에 저장된 이전 기록을 가린다. 자동완성/조절 결과 카드에는 종류가 있으나 몇 번째 실행인지와 다음 요청의 경계가 약하다.

## 변경 계약

- 현재 사용자 권한/대화 소유권은 유지한다. 타 작성자의 대화 공유는 이번 범위가 아니다.
- 새 요청과 과거 표에서 이어서 작성은 같은 conversation에 SEGMENT_START 이벤트를 추가한다. 현재 표 또는 선택한 표를 검증한 작업 버전(내용이 같으면 기존 불변 버전 재사용)을 사용하며 과거 turn/operation/version은 변경하지 않는다.
- 새 구간은 revision을 증가시키고 미확정 해석 참조를 초기화한다. 병동의 저장된 조건과 고정근무는 그대로다. RUNNING/RESULT_READY/UNKNOWN 실행 중에는 구간 전환을 거절한다.
- 기존 API /branches는 하위호환을 위해 유지한다. 새 화면은 /segments를 사용한다. DB 변경/Flyway migration은 없다.
- 이전 구현에서 이미 나뉜 같은 월의 대화는 '이전 대화 기록'에 모두 남기고 펼쳐 조회한다. 요청/결과는 읽기 전용이며 과거 결과 조회/비교는 가능하다. 전체 원문을 LLM에 전달하지 않는다.

## 화면

상단 '새 요청'은 기록을 비우지 않는다. 누르면 현재 표를 기준으로 시작하는 구분선을 남기고 입력 선택지를 다시 보여준다. 일반 메시지와 구분선은 시각적으로 다르게 한다.

자동완성 1회차 · 완료 → 변경 칸 수, 그때 표 보기/전후 비교 → 완료 안내까지 같은 구간 → 다음 사용자 요청 바로 앞에 '자동완성 1회차 이후 · 추가 요청' 구분선.

조절 1회차 · 완료 → 같은 결과 행동 → 다음 요청 앞에 조절 회차 구분선. 명시적 '새 요청' 구분선이 있으면 중복 구분선을 만들지 않는다.

실패/실행 중/결과 확인 필요를 완료로 표시하지 않는다. 명시적으로 새 요청을 시작할 때 '여기서부터 새 요청 · 현재 표 기준'을 보여준다. 달력과 예시/확인/실행 흐름은 유지한다.

## 검증

서버: 같은 ID와 과거 기록 유지, 선택 표 복사, revision/권한/월 범위 검사, 진행 중 실행 거절, 구간 이전의 해석 실행 차단.

웹: 새 구간 뒤 이전 요청/결과/비교 버튼 유지, 재열기 복원, 자동완성/조절 각각 회차·상태·경계 표시, 과거 대화 조회는 재실행/표 변경 없음, 현재 구간 예시·추가 요청의 이전 조건 연결 확인. 합성 월별 미리보기에서 여러 실행 및 새 요청을 확인한다.

## 로컬 검토 화면의 기록 유지 보완

같은 검토 주소를 새 탭으로 열면 합성 대화와 결과 버전이 초기화되어 이전 자동완성 카드가 사라지는 문제를 재현했다. 제품의 서버 조회와 별개로 검토 화면의 저장 방식이 빠져 있었다.

로컬 합성 검토 화면에서만 장면별로 대화·작업 결과·전후 버전을 브라우저에 보관하고, 새로고침/새 탭에서 복원한다. 읽기 요청으로 빈 상태를 저장하지 않으며, 테스트 초기화는 저장 기록도 지워 독립성을 유지한다. 제품의 고객 데이터 저장 방식은 변경하지 않는다. 복원 후 자동완성/조절 결과·회차·비교 버튼, 실제 이전/이후 표를 확인한다.
