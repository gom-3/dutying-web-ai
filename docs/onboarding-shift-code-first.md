# 온보딩 근무 유형: 약자 우선 표시

## 문제와 결정

원본 근무표의 `V` 같은 코드를 `기타 휴가`라는 이름보다 뒤에 보여주면 자동으로 붙인 설명을 병동이 정의한 확정 이름으로 오해하기 쉽다. 엑셀 범례에서 가져온 실제 설명도 있어, D/E/N/O 외 이름을 모두 추정이라고 단정하지 않는다.

- 표의 첫 입력 열을 약자로, 다음 열을 근무명으로 바꾼다. 헤더·행·키보드 이동 순서를 함께 바꾸고 기존 너비를 각 필드에 맞춘다.
- 표 위 안내: 약자를 기준으로 확인하고, D/E/N/O 외 근무명은 자동으로 붙인 임시 설명일 수 있으므로 병동의 이름과 유형으로 확인/수정하도록 안내한다.
- 이 안내를 근무명 입력의 접근 가능한 설명에도 연결한다. 두 입력에 명시적인 열 이름을 연결한다.
- 근무표에서 추출한 값·유형 매핑·API·DB 저장 계약은 바꾸지 않는다. 사용자가 수정한 이름을 추정으로 단정하는 행별 배지는 추가하지 않는다.

## 검증

2026-11-14: 근무 유형/온보딩 화면 테스트 58개 통과. 3교대와 혼합 교대의 헤더·입력 DOM 순서, 이름 안내 연결, V의 임시 설명 안내 및 이름 수정 동작을 확인했다. `pnpm run type-check`, 번역 카탈로그 검사(errors/warnings 없음), 변경 파일 ESLint 통과. 기존 입력값과 저장 계약은 유지한다. 운영 배포 및 실제 운영 화면 검증은 미실시다.

## 미확인 항목 시각화

2026-11-14 추가 설계: `mappingStatus` 미확정 행만 옅은 앰버 배경과 왼쪽 선, 아이콘 및 `V · 확인 필요` 상태 문구로 강조한다. 행 안에 근무명·유형 확인 안내를 함께 두고 표 위에 남은 개수를 표시한다. 사용자가 유형을 선택해 CONFIRMED가 되면 강조와 개수가 즉시 갱신된다. 이름만 편집하면 유형 확인은 여전히 필요하다. 새 확인 버튼이나 저장 상태는 도입하지 않는다. 자동으로 매핑된 기본 근무와 확인한 사용자 정의 근무는 강조하지 않는다.

색만으로 상태를 전달하지 않는 [GOV.UK Tag](https://design-system.service.gov.uk/components/tag/)와 짧은 상태/남은 작업을 보여주는 [Task list](https://design-system.service.gov.uk/components/task-list/) 가이드를 적용한다. 미확정 행의 기존 필수 유형 선택 검증은 유지한다.

검증: 미확정 → 이름 수정(미확정 유지) → 유형 선택(강조 해제)의 상태 전이 및 기존 온보딩을 포함한 59개 테스트 통과. 타입·번역 카탈로그·변경 파일 ESLint 통과. 로컬 Chrome 1280px 모형 화면에서 미확정 2개 행 강조, 수평 넘침 없음과 레이아웃을 확인했다. 운영 배포/운영 사용자 세션 확인은 미실시다.
