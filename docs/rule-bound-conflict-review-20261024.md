# 조건 편집 중 모순 안내

사진에서 같은 RN·월·모든 근무·개인별 범위에 최소21/최대20이 함께 설정됐다. 실행 후 사용자에게 다시 설정을 찾으라고 하는 대신 편집 화면에서 두 조건을 바로 연결한다.

선택된 HARD SHIFT_COUNT_PER_PERIOD의 동일 대상/근무/기간/집계 범위만 비교한다. HARD 최대5와 SOFT 최대4는 충돌이 아니다. 다른 대상·기간은 합치지 않는다. 설정을 자동 삭제/변경하거나 실행을 새로 차단하지 않는다. 모든 조건 충돌의 완전 탐지는 이 변경의 범위가 아니다. 생성 품질 및 19일 연속 근무의 근본 원인과는 구분한다.

검증: 최소21/최대20, EXACT 불일치, 정상 범위, HARD/SOFT, 대상/집계 분리, 비활성 조건 제외.

## 사진 해석과 범위
- 실패 화면의 기존 표에는 OFF가 들어 있다. 19일은 새 생성 요청의 가능 근무/고정 근무를 기준으로 한 진단이며, 기존 표시 표가 19일 연속이라는 뜻이 아니다.
- 필수 최대5일 + 선호 최대4일은 정상적인 우선순위 표현이다.
- 이번 화면 보완은 모순을 일찍 찾도록 돕는다. 가능 근무 설정을 임의로 바꾸거나 19일 연속 근무를 적절한 결과로 보증하지 않는다.
- 이전 배포의 DTO 변환 오류 수정과 별개의 추가 개선이다.

## 검증
- 충돌 계산 및 실제 조건 편집 컴포넌트 94 tests 통과.
- 최소/최대 조건으로 이동하는 버튼, 정상 범위, HARD/SOFT 분리, 대상/기간/집계 분리 검사.
- TypeScript 검사 통과. 사용자 근무표/운영 조건 변경 없음.
