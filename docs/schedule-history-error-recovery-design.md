# 저장된 대화 오류에서 요청 재확인

- 과거 로컬 `feedback:error` 메시지의 본문은 남기되, 가장 최근의 미해결 오류 카드에 `요청 다시 확인하기`를 제공한다. 오류 문구나 언어를 문자열 비교해 분기하지 않는다.
- 오류 이전의 최신 요청/계획을 같은 대화 구간에서 찾는다. 이후 새 사용자 요청, 구간 분리, 접수된 실행 기록이 있으면 과거 오류를 새 계산의 진입점으로 사용하지 않는다. 실행 중/미확인 접수 상태에는 요청 복원 대신 기존 결과 확인 흐름을 유지한다.
- 버튼은 원문을 편집 입력창에 복원하고 재검토만 연다. 해석/계산/확정 API를 자동 호출하지 않는다. 입력 중인 문장은 보존한다.
- draft 동기화 이후 latestInterpretationId가 비어도 오래된 interpretationId에 의존하지 않고 최신 revision으로 요청을 재검토한다.
- 과거 오류 복구 중 사이드바의 근무표 확정 후속 동작을 숨긴다. 기존 표와 결과 기록은 유지한다.
- API/DB 변경 및 Flyway migration 없음. 기존 대화 기록과의 호환성을 유지한다.

## 검증

- 관련 193개 테스트 및 전체 298개 파일, 3,082개 테스트 통과(기존 3개 skip).
- TypeScript, 변경 제품 코드 ESLint, Prettier, release:verify, build:app, diff whitespace 검사 통과.
- 원격 중복 CI 없이 개발계 자동 배포로 전달하며, 기존 오류 카드의 요청 복원 UI를 확인한다. 실제 해석·계산·확정은 smoke test에서 실행하지 않는다.
