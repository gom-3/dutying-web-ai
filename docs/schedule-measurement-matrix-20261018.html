산출할 수 없는 지표와 필요한 분모

일반 GA에는 흐름/시도 ID, 병동, 팀, 교대 유형을 넣지 않는다. 준비 시작 클릭 수가 추가돼도 해석→확인→실행→표시→적용→확정의 같은 시도와 연결되는 분모는 없다. GA 세션 안에서도 반복 생성·조절·새로고침·직접 확정이 섞일 수 있으므로 전체 이탈률/전환율/불만율을 계산할 수 없다. 기존 신호 comparison_open, regeneration_selected, outcome_recheck, feedback_open/sent는 행동 신호다. 의견 전송도 서버 접수 성공이며 실제 불만의 확인/해결을 뜻하지 않는다.

서버 journey/대화 원장은 권한 있는 소유자·범위/버전별 분석에 활용할 수 있지만 준비 전 단계는 없고 표시/적용 receipt는 best effort다. 병동·팀별 분모는 서버 이벤트 기록 범위에서만 정의해야 하고, 교대별 차이는 현재 GA에 없으며 별도 권한 있는 코호트 정의/집계가 필요하다. 표본 수·결측률·기간·버전·미완료 관찰기간과 신뢰구간을 함께 제시해야 한다. 이 문서는 실제 운영 건수나 효과 크기를 산출하지 않는다.

이번에 보완한 최소 누락

기존 GA helper에 preparation_started/preparation_paused 두 enum만 추가했다. 원문·간호사·키·scope·소요시간·새 식별자는 추가하지 않았다. 기존 서버 API와 journey 이벤트 타입은 그대로다. SDK 실패 격리와 개발/프리뷰 전송 차단을 유지한다. 이 두 이벤트가 전체 단계 분모를 해결했다고 주장하지 않는다.

복구 검증의 경계

단위/컴포넌트 검증은 Vitest/jsdom과 mocked conversation API를 사용했다. 브라우저 검증은 Vite의 report-recovery 합성 scene에서 실제 reload를 수행했다. 합성 adapter는 첫 신고를 메타데이터만으로 접수한 뒤 응답을 유실시키고, 같은 키 재전송의 접수 수가 1건인 것을 보여준다. 실서버 인증·HTTP·DB/outbox 통합은 이 검증에 포함되지 않으며 운영 replay/유료 LLM도 호출하지 않았다. 실제 통합 검증 세션에서 최종 head와 백엔드 PR #225를 함께 검증해야 한다.
