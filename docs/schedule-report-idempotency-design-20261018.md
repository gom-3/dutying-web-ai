# 신고 재시도 멱등성·세션 복구 설계

2026-10-18. 프런트엔드 PR #86은 #85(6a10a514) 위에 쌓인 후속 변경이다. 이번 세션 복구 보강 기준선은 e3aa45b3, 확인한 origin/develop은 ca363418이다. 전용 worktree에서 작업하며 타 세션 저장소는 읽기만 한다.

## 문제와 확인한 계약

기존 api.report는 {operationId,note}를 보내 {incidentId}를 받는다. 응답 유실 후 재시도는 서버 접수가 이미 저장됐는지 모른다. 백엔드 PR #225의 8059e046 DTO/controller/문서에서 선택 필드 idempotencyKey(1~80자, `[A-Za-z0-9_-]+`), 기존 응답, 필드 누락/null의 기존 동작을 확인했다. FE는 네 번째 선택 인자만 추가하며 기존 세 인자 호출 본문을 보존한다. UUID를 사용하고 execute의 키와 섞지 않는다. 서버 note 정규화는 기존 ClientReportSanitizer이고 FE는 기존 trim 전송을 유지한다.

이전 서버 호환은 기존 두 필드 DTO, unknown-field 강제 설정/사용자 ObjectMapper 미발견, 로컬 Spring Web 6.0.9/Jackson 2.15.0 기본 builder로 확인했다. 추가 필드가 포함된 합성 LegacyReport JSON에서 FAIL_ON_UNKNOWN=false와 기존 값 보존을 확인했다. 운영 인스턴스 설정/배포 검증은 아니며 이전 서버가 키를 무시하면 중복 방지는 제공되지 않는다.

## 세션 복구 설계 (구현 전에 기록한 보강 판단의 최종 정리)

e3aa45b3의 메모리 전용 방식은 remount/새로고침을 넘는 키 보존을 충족하지 못했다. 신고 전송 전에 sessionStorage에 버전, scope SHA-256, UUID, salted 내용 SHA-256, 생성 시각만 저장한다. 내용 digest는 scope digest·UUID·trim note의 JSON에 SHA-256을 적용한다. note·이름·토큰·스케줄 원문은 저장하지 않는다. 메모리에는 현재 입력이 있을 수 있지만 세션 저장/analytics로 원문을 보내지 않는다.

범위는 계정 또는 관리자 principal ID(wardAdminAccountId), principal 모드, 권한(isManager 또는 미확인), 병동·팀·년월·conversation·operation 전부를 포함한다. 순서를 고정한 scope를 hash한 키로 그 범위만 읽는다. 다른 범위의 저장소를 열거하지 않는다. 소유자 또는 일반 계정의 권한을 모르면 세션 복구와 키 재사용을 하지 않아 미확인 소유자끼리 키가 섞이지 않게 한다. 서버 권한 검증을 대체하지 않는다.

같은 탭에서 24시간 내 같은 범위·동일 trim 원문을 재입력하면 이전 키를 복구한다. 재시도해도 최초 시각을 갱신하지 않는다. 메모리 키도 같은 기한으로 만료된다. 버전·UUID·digest 형식·scope 불일치, 손상, 미래 시각, 만료는 복구하지 않는다. 활성 UI에서 내용이 달라지면 이전 실패 액션을 무효화한다. 공백 trim만 달라지면 기존 전송 내용이 같으므로 키를 유지한다.

명시적 ‘취소’와 성공은 해당 액션을 끝내고 기록을 정리한다. 새로고침·remount·단순 화면 이동은 종료가 아니다. 성공은 요청 당시 pending scope의 키만 정리해 응답 대기 중 계정 변경이 다른 범위의 기록을 지우지 않게 한다. 이전 요청의 늦은 완료도 새 액션의 다른 키를 지우지 않는다. 언마운트된 컴포넌트의 늦은 성공 응답은 세션 기록을 지우거나 성공 UI/GA를 갱신하지 않는다. 새 컴포넌트가 같은 키로 재확인한 뒤 정리한다. 취소 버튼에는 새로 작성할 때 새 신고가 된다는 안내를 붙인다. 새로고침 뒤 원문은 복원하지 않고 사용자가 재입력한다.

storage 접근/get/set/remove 또는 WebCrypto digest 실패는 신고 전송·입력·analytics를 실패시키지 않는다. 식별된 범위의 동일 마운트 재시도에는 메모리 키를 유지한다. 실패한 전송의 입력에는 재시도 정보를 저장하지 못하면 새로고침 없이 재시도하라는 안내를 표시한다. 삭제만 실패하면 종료 tombstone을 쓰고, 종료된 키는 메모리에서도 배제한다. 삭제·쓰기 모두 고장난 저장소의 remount 후 정리는 보장할 수 없다. 이 경우 성공 응답을 실패로 바꾸지 않고 한계를 명시한다. 오래된 메타데이터는 해당 scope 접근 시 또는 탭 세션 종료 시 제거된다.

## APPLIED·관측 범위

서버 APPLIED는 실행 당시 서버 draft 상태이며 브라우저 현재 표 적용 증거가 아니다. 실행 시점 문구를 유지하고 응답 유실·새로고침·수동 편집·과거 결과 보기에서 현재 표 적용을 단정하지 않도록 검증한다. 생성/조절/실제 표 적용 로직은 변경하지 않는다.

기존 GA helper에 preparation_started/preparation_paused enum 두 개만 추가한다. paused는 이탈/불만이 아니다. 새 원문·키·식별자·duration/flow ID는 보내지 않는다. 서버 journey 타입/API는 확대하지 않는다. 전체 단계의 같은 시도 분모가 없어 전체 이탈률/전환율/불만율은 산출 불가다. 코드별 가능/불가는 schedule-measurement-matrix-20261018.html에 정리한다. 성능/전환율 향상을 주장하지 않는다.

## 검증·원복·적용

단위: 범위 변경, 만료/손상, 저장소/해시 장애, 성공/취소/늦은 정리. 컴포넌트: mocked API 접수 후 응답 유실, remount와 재입력, 같은 키와 합성 접수 1건, 저장 실패 시 입력·재시도 보존. 브라우저: 별도 로컬 origin의 report-recovery 합성 scene에서 실제 reload와 재입력을 확인한다. 합성 adapter/저장소를 사용하며 실서버 인증·HTTP·DB/outbox 통합 증거로 주장하지 않는다. 운영/유료 LLM/replay를 호출하지 않는다.
