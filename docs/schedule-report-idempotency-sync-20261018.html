결과와 경계

전송 전 sessionStorage에 UUID·scope digest·내용 digest·생성 시각·버전만 기록한다. 계정/관리자 ID·권한·병동·팀·월·대화·실행의 어느 항목이 달라도 다른 키다. 같은 탭에서 24시간 내 같은 trim 내용을 재입력하면 기존 키를 복구한다. 원문 입력은 복원하지 않는다. 성공·의도적 취소는 정리하고 새 신고로 시작한다. 저장/해시 장애 시 입력과 전송을 유지하며 새로고침 복구가 불가능함을 안내한다. 삭제 실패는 종료 마커로 보완한다. 모든 저장 조작이 실패한 뒤 reload까지 정리를 보장할 수는 없다.

실행 키·실제 표 적용·확정 코드는 바꾸지 않았다. 서버 APPLIED를 브라우저 현재 적용 증거로 보지 않는 기존 문구 검증을 유지한다. GA에는 preparation_started/preparation_paused 두 enum만 보강했다. 단계별 연결 분모·duration·병동/교대 메타데이터는 없으며 전체 이탈률/전환율/불만율을 계산할 수 없다.

실제로 수행한 검증

  • 보강 전 신고/sidebar/GA 기준선: 4개 파일 79개 통과.
  • 중간 키 관리 19개 및 신고·결과 안내 집중 30개 통과. 이후 정리의 삭제·쓰기 동시 실패 시 종료 키 배제를 추가 검증했다.
  • 중간 관련 회귀 6개 파일 127개 통과 후 최종 128개 묶음을 실행했다. 최종 묶음은 127개 통과, 기존 240셀 화면 테스트 1개가 로컬 30초 제한을 초과했다. 단독 기본 설정 재실행도 30초를 넘겼다. 당시 호스트 load average 22.8이었다. 소스의 제한은 변경하지 않고 기존 DUTYING_UI_REVIEW_TIMEOUT_MS=60000 설정으로 단독 재실행해 약 21초에 통과했다. 제한 소스는 바꾸지 않았다. 최종 head 전체 CI는 완료 보고/PR에 기록한다. 이는 UI 처리 속도 측정치가 아니며 원인을 호스트 부하로 단정하지 않는다.
  • TypeScript 검사, 변경 소스/테스트 ESLint, diff 공백 검사. 기존 일부 테스트의 getComputedStyle pseudo-element/act 경고는 테스트 실패와 구분한다.
  • 실제 브라우저: 첫 신고가 합성 접수 1건을 저장한 뒤 응답만 유실 → 페이지 reload → 빈 입력에 같은 note 재입력 → 성공 → 접수 1건 유지. 375px 입력·취소 안내와 키보드 초점 복귀도 확인했다.
