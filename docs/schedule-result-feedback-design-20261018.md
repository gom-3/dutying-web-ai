# 결과 이해와 실행별 의견 연결 개선

기준: origin/develop ca363418, 2026-10-18. 소유 범위: 웹 프런트엔드만.

## 근거와 가설

AiConversationSidebar는 각 실행을 순서대로 보여주지만, 공통 신고 버튼은 마지막 완료 실행 ID를 선택한다. 사용자가 이전 결과를 비교한 뒤 신고하면 다른 실행과 연결될 수 있다. 결과별 신고 버튼과 회차 표시로 대상을 명시한다. 서버 보고 계약은 기존 POST conversations/{id}/reports {operationId,note}를 그대로 사용한다. 새 대화 설치 시 열린 신고 입력은 초기화한다. 실패 시 입력은 보존한다. 신고 열기 후 입력에 초점을 옮기고 취소 시 원래 버튼으로 되돌린다.

실행 결과의 변경 수는 changedCells의 길이로 표시하되, 서버가 반영하지 않은 결과를 현재 표의 변경으로 표현하지 않는다. 성공한 계산 결과에만 표시하며 저장/확정과 구분한다. 기존 필수 규칙 검토와 정상 확인 절차는 유지한다.

## 범위와 보호 조건

일반 분석에는 고정된 행동 enum만 전송한다. 요청/응답/간호사 이름/병동 ID/실행 ID/신고 원문은 포함하지 않는다. SDK 실패는 기능에 영향을 주지 않는다. 기존 schedule journey의 DISPLAYED/APPLIED/UNDONE 계약과 멱등 키는 유지한다. 서버 이벤트 확장은 하지 않는다. 신규 일반 분석 신호는 비교 열기, 재생성 선택, 결과 재확인, 의견 입력 열기/전송 성공으로 한정한다. 모두 행동 신호이며 불만의 증거로 간주하지 않는다. 준비 이탈과 해석 재시도는 현재 서버 journey 계약 밖이므로 후속 계약 검토 대상으로 남긴다.

고정 근무·신청근무·행 순서·전달 근무·수동 편집·응답 유실 복구·새로고침 복원·저장과 확정은 기존 구현 및 관련 회귀 테스트로 검증한다. 실행/스케줄 변경 로직은 수정하지 않는다.

## 측정과 불확실성

운영 기준선은 수집하지 않았다. 전환율·성능 개선을 주장하지 않는다. 합성 fixture에서 변경 전 신고 대상 선택과 수정 후 실행별 연결을 확인한다. 후속 분석은 비교/재확인/재생성/신고 행동 수를 각 단계 도달 세션 수로 나누고, 배포 전후 동일 기간·동일 계측 정의로 비교한다. 분모는 기존 서버 journey의 유효 표시/준비 도달 집계가 있을 때만 사용하고, 해당 단계 분모가 없으면 클릭 수만 보고한다. 현재 enum 전용 일반 분석은 병동/교대 구분이 불가하므로 그 차이를 추정하지 않는다. 병동/교대별 분모 및 불확실성 분석은 권한 있는 서버 journey 집계가 필요하다. 차이의 신뢰구간과 표본 수를 함께 보고하고, 반복 클릭·새로고침·네트워크 문제를 불만으로 해석하지 않는다.

## 검증과 원복

기존 관련 테스트를 먼저 실행하고, 실행별 신고 대상·실패 입력 보존·대화 전환 초기화·키보드 초점·변경 수/미반영 표시·계측 장애 격리를 추가 검증한다. 합성 로컬 브라우저에서 좁은 화면과 키보드를 확인한다. 유료 LLM 및 운영 replay는 호출하지 않는다. 문제 발생 시 이 PR 커밋을 revert하면 기존 UI와 계측으로 복귀한다. 서버/DB 변경 의존성은 없다.

## Self-review

| Before | After | Why |
| --- | --- | --- |
| 공통 신고가 마지막 완료 작업을 자동 선택 | 각 결과에서 신고를 열고 작업 종류와 회차를 표시 | 이전 결과 의견의 잘못된 실행 연결 방지 |
| 전송 직후 비활성 버튼에 초점 복귀 시도 | 전송이 끝나 버튼이 활성화되면 복귀 | 키보드 위치 보존 |
| 결과에서 변경 규모 안내 없음 | 계산 변경 수, 실행 시점 작성본, 미반영 상태를 구분 | 이후 수동 편집/별도 확정과 혼동 방지 |

전송 중 중복 클릭/취소/입력 변경을 막고 실패 시 입력을 유지한다. 다른 신고로의 전환은 현재 신고를 취소한 뒤 가능하다. 입력 초점 이동은 열릴 때만 실행하며, 비교 모달을 열거나 비동기 작업이 끝날 때 모달 초점을 빼앗지 않는다. 결과 실행·동기화·검증·복구 로직은 수정하지 않았다. 테스트 파일의 기존 부분 변경은 동일 ESLint/Prettier 규칙 적용만 포함한다.
