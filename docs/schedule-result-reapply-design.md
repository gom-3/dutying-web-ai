# 근무표 결과 재적용과 대화 기록 유지

- 결과 카드는 저장된 결과 버전을 가리키며 히스토리 복원·수동 편집·되돌리기에 의해 결과 설명과 변경 내역이 바뀌지 않는다. 현재 적용 상태는 별도로 표시한다.
- 기존 대화 draft 동기화 API로 원본 cells, rowOrder, carryOverCells를 복원한다. AI 실행·새 대화·새 구간·확정/게시는 하지 않는다. DB/Flyway migration 없음.
- 재적용은 현재 편집을 교체한다는 확인을 거친다. 현재 편집은 먼저 sync로 보존하며 revision 충돌과 실행 중 작업을 차단한다. 비동기 요청 중 표가 변경되면 로컬 표를 덮어쓰지 않는다.
- 재적용 직전 draft의 versionId도 저장해 되돌리기가 중간 수동 편집으로 돌아가게 한다. 재적용한 결과와 draft의 연결은 로컬 대화 기록에 보관하고 전체 표 signature가 같은 경우에만 적용 중으로 판단한다. 다시 되돌리면 연결은 자동으로 비활성화된다.
- 히스토리 불러오기는 작업 표와 검증 결과만 변경하며 기존 생성 이력과 피드백은 유지한다. 이후 실행은 변경된 표를 동기화하고 조건을 다시 검토한다.
- 근무팀 960의 데이터는 수정하지 않으며 실제 운영 재현 여부는 구현 검증과 구별한다.

## 확인한 원인

`commands.init()`은 store.reset()으로 conversationEnabled 등의 workspace 기능 플래그도 지운다. 히스토리 복원에 이 함수를 사용하면 사이드바 transport가 바뀐다. `restoreSnapshotDoc()`으로 대체해 기능 플래그와 대화를 보존한다. 행 인덱스 기반 편집 undo는 복원 경계에서 초기화하며, 대화 결과의 되돌리기는 저장된 원본 버전을 사용한다.

## 검증 결과

- 관련 5개 테스트 파일, 214개 테스트 통과.
- TypeScript `tsc -b` 통과. 변경된 제품 코드와 편집기 명령 테스트 ESLint 통과. 기존 sidebar 테스트 파일의 변경 밖 스타일 위반 33건은 유지.
- 운영 배포·실제 근무팀 960 데이터 변경 없음.
