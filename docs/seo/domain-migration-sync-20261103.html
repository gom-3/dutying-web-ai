듀팅 SEO·AEO 개선 및 도메인 이전 점검

2026-11-03 · gom-3/dutying-web-ai · 기준 origin/develop b7942dfb · 작업 브랜치 codex/seo-domain-migration-20261103

.net → .ai 영구 리다이렉트는 작동한다. 구글에는 기존 도메인의 대표 URL 선택이 아직 남아 있다. 새 도메인의 브랜드·공개 콘텐츠·색인 범위를 개선했으며, 운영 main 승격과 외부 제공자 배포는 별도 단계다. 순위 상승이나 AI 답변 인용을 보장하지 않는다.

검색 기준선

Search Console의 최종 웹 검색 데이터, 미국 태평양 날짜 2026-10-01~10-30. 도메인 이전 전후를 분리한 실험이 아니므로 원인을 수치 하나로 단정하지 않는다. query/page 분해는 익명·소량 데이터를 생략할 수 있고 평균 순위는 사용자마다 고정된 검색 순위가 아니다.

.net에서 ‘간호사 근무표 자동 프로그램’은 114회 노출·7클릭, ‘간호사 근무표 짜기’는 30회 노출·6클릭이었다. 새 가이드는 실제 유입 의도에 맞춰 준비 정보·자동 생성 과정·검토 방법을 설명한다.

공개 응답과 구글 색인 확인

  • https://www.dutying.net/ → https://www.dutying.ai/: HTTP 308.
  • www.dutying.ai/: HTTP 200, canonical이 www.dutying.ai/이며 robots 허용. 구글 선택 canonical도 동일하고 색인 PASS. 마지막 수집 2026-11-03 05:42 한국 시간.
  • www.dutying.net/: 구글 마지막 수집 2026-10-30 20:31 한국 시간. 사용자 canonical은 .ai였지만 구글 canonical은 아직 .net이었다. 이 결과는 검사 당시 색인 스냅샷이며 현재 HTTP 응답과 다를 수 있다.
  • docs.dutying.ai/: URL 검사에서 ‘Google에는 아직 알려지지 않은 URL’. 사이트맵 등록만으로 모든 페이지의 색인을 보장하지 않는다.
  • www 및 docs 사이트맵은 이미 등록되어 있고 수집 errors/warnings가 0이었다. 사이트맵 API의 indexed=0을 전체 색인 0으로 해석하지 않았다. 홈 URL 검사는 실제 PASS였다.

Search Console 주소 변경 실행

기존 로그인 목록에서 두 도메인의 확인된 소유자 계정으로 접근했다. sc-domain:dutying.net → sc-domain:dutying.ai는 구글의 홈페이지 리다이렉트·소유권 사전 검사를 통과했고, 이동 확인 후 ‘현재 사이트를 이전 중입니다 / 시작일 2026년 11월 3일’ 상태를 확인했다. DNS나 서비스 배포는 변경하지 않았다.

주요 유입 주소인 https://www.dutying.net/도 별도로 이전을 신청하려 했으나 필수 검사에서 ‘페이지를 가져올 수 없습니다’로 막혔다. 소유권 검사는 통과했다. www 신청은 접수되지 않았다. 일반·Googlebot·Google-InspectionTool 사용자 에이전트의 공개 요청은 모두 정상 308을 받았다. 이 확인은 실제 구글 크롤러 네트워크의 접근을 증명하지 않으며 원인은 확정하지 않았다. 같은 검사를 반복하거나 308 자체가 원인이라고 단정하지 않는다. Vercel 제공자 설정·DNS/IPv6·실제 구글 fetch 결과를 후속 확인해야 한다.

수정 내용

영역변경
브랜드와 검색 메타데이터한국어 제목을 ‘듀팅 | 간호사 근무표 자동 생성·교대근무 관리’로 정리. 초기 HTML과 번역 원본·생성물·브라우저 제목을 동기화했다. Organization, WebSite, WebPage, SoftwareApplication 식별자를 연결하고 ‘듀팅’과 ‘Dutying’을 같은 브랜드로 명시했다.
색인 범위6개 언어의 실제 랜딩만 앱 sitemap에 포함. 로그인·인증 후 도구·정책 SPA는 noindex, follow로 제공하고 홈 hreflang·제품 JSON-LD를 복제하지 않는다. 정적 앱 경로 canonical은 자체 주소로, 동적 앱 셸에는 잘못된 canonical을 넣지 않는다.
공개 도움말홈·시작하기·모바일 캘린더·FAQ의 개발 초안 설명을 실제 사용자 안내로 바꾸고, ‘간호사 근무표 자동 생성 가이드’를 추가했다. 웹 가이드 7개에는 고유 설명을 추가했다.
발견과 연결6개 언어 랜딩 footer에서 한국어 가이드와 FAQ로 연결하며, 다른 언어의 링크에는 한국어 문서임을 명시한다. 문서별 self-canonical, WebPage, BreadcrumbList를 제공한다.
개발·미리보기운영 도메인이 환경변수로 들어가도 Cloudflare 비-main 브랜치와 Vercel 비-production 환경은 noindex. 문서의 preview sitemap을 없애고 robots를 차단한다.
재검사pnpm run verify:seo로 빌드 HTML·사이트맵·구조화 데이터를, pnpm run audit:seo로 운영 HTTP 응답을 읽기 전용 검사한다. 공개 감사는 배포 전 미반영 항목을 실패로 보고하는 것이 정상이다.

검증 결과

  • 앱 production 빌드, 문서 production 빌드 통과.
  • 앱 43개 HTML 경로와 공개 문서 12개: canonical·robots·고유 제목/설명·JSON-LD·sitemap 검증 통과.
  • 앱·문서 preview 빌드를 실제로 생성해 전체 HTML noindex, robots 차단, sitemap 없음 검증 통과. 운영 URL이 환경변수에 들어간 상황도 포함했다.
  • 언어·랜딩·hydration·인증 레이아웃 관련 테스트 79개, 초대 프리뷰 worker 테스트 24개 통과.
  • 앱·문서 타입 검사, 수정 랜딩 ESLint, 번역 catalog 검사, 수정 코드 Prettier 및 git diff --check 통과.
  • 브라우저에서 새 가이드의 본문·표·탐색 메뉴를 확인했다. 로컬 검사이며 실제 운영 배포 증거와 구분한다.

배포·비용 범위

기존 변경과 로컬 ahead 커밋이 있는 원래 worktree는 건드리지 않았다. 최신 develop의 별도 worktree에서 작업했다. develop에는 Web CI의 pull_request/workflow_dispatch만 있으며 이 작업으로 불필요한 PR·Actions 재실행은 만들지 않는다. main의 최근 커밋에는 Cloudflare Pages의 dutying-web-ai, dutying-landing, dutying-docs 성공 체크가 있어 세 프로젝트 연동을 확인했다. Cloudflare 대시보드는 로그인 상태가 없어 실제 프로젝트별 빌드 설정·새 배포 상태를 직접 검증하지 못했다. [skip ci]만으로 외부 빌드가 생략된다고 주장하지 않는다.

통합 대상은 origin/develop이며 운영 main·DNS·리다이렉트 제공자 설정은 변경하지 않는다. 승인 예산·플랜·러너·.net 서비스는 변경하지 않는다. 배포 승격은 기존 릴리즈 절차로 수행하고 제공자 커밋과 공개 URL을 함께 확인해야 한다.

남은 운영 항목과 측정

  1. www.dutying.net의 Google 주소 변경 사전 검사 실패를 해결한 뒤 별도 이전을 접수한다. 루트 도메인 접수 성공을 www 접수 성공으로 해석하지 않는다.
  2. 검증한 변경을 운영 www와 docs에 배포한 뒤 공개 감사와 구글 URL 검사를 수행한다. 새 가이드는 현재 운영에서 404인 것이 배포 전 기준선이다.
  3. .net 영구 리다이렉트를 최소 1년 유지하고 구글봇이 이전 URL을 수집할 수 있게 둔다. 검색 삭제 도구나 .net robots 전면 차단으로 이전을 대체하지 않는다.
  4. 기존 .net 리다이렉트에서 /login?next=%2Fmake의 쿼리 문자열이 사라지는 것을 확인했다. 현재 .ai 코드 밖의 제공자 설정이므로 별도 수정 대상으로 남겼다.
  5. 네이버 Search Advisor와 공식 스토어·소개 페이지·프로필의 이전 .net 링크를 .ai로 갱신하는 계정 작업이 필요하다. 스토어의 기존 앱과 새 ai.dutying.app을 혼동하지 않는다.
  6. 배포 후 2~4주 구간을 기준선과 비교한다. 소유자 역할은 웹/마케팅 담당자. 핵심 지표는 .ai 브랜드 클릭·노출, ‘간호사 근무표 자동 프로그램/짜기’의 .ai 노출, 새 가이드 색인 여부다. 계절성과 소량 표본을 함께 보고 .net/.ai 데이터를 구분한다. 이 문서는 자동 모니터나 정기 알림을 만들지 않는다.
