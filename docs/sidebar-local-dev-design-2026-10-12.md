# 로컬 개발 DB 연결 및 남은 복구 흐름

- 사용자 지시: 추가 PR/push 없이 로컬 수정과 테스트 환경 제공.
- 비동기 조회: 동시에 조회하지 않기, 연결 실패 표시, 100회 제한 이후 명시적 재확인 제공, 이전 대화/이전 revision 응답 배제.
- 개발 DB/Redis/기존 개발 계산 엔진은 SSH loopback 터널로 연결. 자격증명은 실행 환경에만 전달하고 출력/문서 저장하지 않음.
- 메인 서버는 수정한 로컬 소스로 실행. app.scheduling.enabled=false일 때 예약 작업을 등록하지 않도록 기본값 보존 설정 분리. 로컬에서는 Flyway/DDL/알림 delivery 비활성화. 개발계 서비스 재배포 없음.
- 웹은 localhost:3000, 로컬 API localhost:8080. 사용자는 개발계 기존 로그인으로 테스트. 로컬 작업은 개발 DB에 저장됨.
- 테스트: polling 연결 오류/복구/시간 제한/중첩 방지, 기존 사이드바, 스케줄러 기본 활성/명시적 비활성, 실제 readiness 및 웹 연결.

## 확인 결과

- 웹 사이드바·조회 회귀 테스트 52개 통과, lint와 타입 검사 통과. 조회 응답은 15초 제한으로 연결 문제를 안내하고 다시 확인 가능.
- 서버 관련 테스트 41개 통과 및 실행 JAR 빌드 성공.
- 로컬 `/readyz` 200/UP(DB·Redis 포함), 전체 health 200/UP. 개발 계산 엔진 `/health` 200.
- 테스트 주소: http://localhost:3000/login (개발계 이메일·비밀번호 로그인). 소셜 로그인은 로컬 콜백 별도 설정이 필요하며 검증하지 않음.
- 실제 로그인 이후 자동완성·수정 실행은 사용자가 선택한 테스트 병동에서 확인 필요. 저장은 개발 DB에 반영됨.
- 새 커밋·push·PR 변경 없음. 기존 PR은 그대로 유지.
