# 근무표 사이드바 복구·문구 개선 설계 (2026-10-11)

## 근거와 범위
- 기존 229개 UI 테스트는 통과했지만, 응답 유실 후 RUNNING을 복구하고 완료된 뒤 pending key가 남는 경로가 추가 재현 검사에서 확인됨.
- 컴포넌트가 만든 500자 초과·이전 실행 확인 안내가 오류 필터에서 사라짐. 명시적 로컬 오류 코드와 번역 키로 전달하고 외부 예외는 계속 숨김.
- 일반 생성의 검토 초안(applicable=true, approvable=false)을 대화 저장에서 실패 처리함. GENERATE의 명시된 검토 초안만 저장·반영하고 완전한 그리드·범위·고정 보호를 확인함. ADJUST 필수조건 실패는 허용하지 않음. ACCEPTED/REPAIRED의 승인 결과는 기존 Authoring 판정과 일치시킴.
- 검토 초안은 UI에서 완료로 오인하지 않도록 별도 상태·규칙 확인 안내. 공식 확정은 기존 서버 검증 유지.
- 기능명 자동채우기, 변경 행동 수정, 설명 ~요체, 도구 버튼 ~하기로 통일. 내부 상태·미설명 수치는 사용자 문구/단위로 매핑. 실패 버튼은 실제 돌아가는 동작을 설명함.

## 구현
1. 요청 키와 서버 operation id를 연결해 같은 실행의 terminal 상태(SUCCEEDED/FAILED)만 pending key 해제. RUNNING/RESULT_READY/UNKNOWN은 유지. 조회만으로 로컬 표를 덮어쓰지 않음. 복구 중 상태에 맞는 안내.
2. 신뢰 가능한 로컬 오류 클래스(정해진 키만 허용); 별도 서버 메시지는 통과시키지 않음.
3. 대화 저장의 검토 초안 조건과 완전성 검증, 기존 lock/scope/revision/context 검증 유지. DB와 API shape 변경 없음.
4. 품질·대안·목표 표시 개선, 요청·비교·복구·미반영 문구 통일 및 한/영 번역.
5. 회귀 테스트: 응답 유실/복구 완료/동일 키/미확정 상태/글 길이 안내/초안 허용과 잘못된 후보 거절/이전 표 보존/코드 숨김·단위/비교 결과.

## 제외
모델 변경·LLM API 호출·알고리즘 변경·새 기능 플래그·자동 배포 없음. 기존 기능의 의미가 달라지는 정책 확장은 하지 않음. Flyway migration 없음.
