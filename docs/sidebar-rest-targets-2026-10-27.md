# 개인 휴무 목표의 사이드바 통합

근무표 상단의 독립 개인 휴무 패널을 제거한다. 기존 사이드바의 현재 적용된 제약조건 안에서 근무 조건과 개인별 휴무를 함께 관리한다. 근무표는 그대로 보며 필요한 간호사 한 명의 이번 달 OFF·연차만 수정한다.

| Before | After | Why |
| --- | --- | --- |
| 근무표 위에 중첩 details·선택·월 입력·긴 설명 노출 | 사이드바의 기존 조건 보기 안에서 개인별 휴무 선택 | 근무표와 대화에 별도 설정 영역을 덧붙이지 않는다 |
| 월을 다시 고르고 저장/유지/취소 버튼이 중복 | 근무표의 월 고정, 간호사 선택, OFF/연차 입력, 하단 저장 | 맥락을 유지하고 행동을 명확히 한다 |
| 휴무 충돌 후 일반 설정으로 이동 | 근거에 명시된 간호사의 휴무 목표로 연결 | 사용자가 수정할 값을 찾을 수 있다 |
| 목표 저장과 조건 재조회가 분리 | 저장 후 현재 조건·실행 검증 문맥 갱신, 대화 복귀 | 오래된 확인/제안으로 실행하지 않는다 |

설정과 생성은 별도 동작이다. 저장만으로 생성하거나 표를 바꾸지 않는다. 기존 API·version 검사·null과 0 구분·OFF/연차 별도 집계·명시적 고정과 승인 배정은 유지한다. 연차 지정 시 OFF 목표도 필요하다. 합계가 월 일수를 넘으면 입력 옆에서 차단한다. 저장 중 중복 저장/닫기/대상 이동을 막고, 미저장 입력을 버리는 경우 기존 조건 모달의 확인 절차를 공유한다. 조회/저장 실패는 입력을 보존하고, 저장 성공 후 재조회 실패는 PUT를 반복하지 않고 재조회만 재시도한다.

기존 간호사 상세 화면도 같은 저장 로직을 사용한다. 신규 API/DB/스케줄 정책 변경과 운영 배포는 범위 밖이다. 현재 요청과 기존 develop 반영 지시에 따라 검증 후 develop에 합친다.

검증: 상단 패널 제거, 두 사이드바 경로의 통합, 실제 저장 payload와 표/초안 보존, 0/null/연차 별도 집계, 실패 및 409, 재조회 재시도, 저장 중 차단, 취소와 포커스 복귀, 과거 제안 무효화, 좁은 화면과 키보드. 합성 데이터로 브라우저에서 조건 보기→휴무 수정→저장→대화 복귀를 확인한다.

## 검증 결과

- 근무표/개인 휴무 기능 전체: 84개 파일 1068개 테스트 통과. 최종 문구/타입 수정 후 조건·휴무 편집 33개 집중 검사 재통과.
- TypeScript `tsc -b`, 변경 파일 ESLint/Prettier, 앱 빌드 및 diff 검사 통과.
- 실제 브라우저(합성 데이터만 사용): 현재 조건 → 개인별 휴무 → OFF 수정 → 저장 → 같은 대화/작성 내용 유지 확인. 기존 조건 편집도 정상 표시. 375px 폭에서 입력·저장·복귀 버튼 가로 넘침 없음.
- 목표 저장 후 서버 조건 hash 갱신으로 이전 수정 제안이 비활성화됨을 확인. 셀·고정 배정·대화 초안과 연차 장부 변경 없음. 자동 실행·유료 모델 호출 없음.
- 운영 API/DB/배포 변경 없음. 월 OFF/연차 정책 자체는 동일하며 야간전담 OFF 최소 목표를 안내한다.
