# 실행 실패 안내와 결과 스냅샷

- 연결 종료/시간 초과/서버 혼잡/잘못된 응답을 서버가 구분해 기존 failure.reasonCode로 전달한다. 확정 불가능 판정과 시스템 장애를 혼동하지 않는다.
- 웹은 실패 원인, 표 보존 여부, 다음 행동을 구체적인 ~요 문장으로 안내한다. 알 수 없는 오류는 원인을 확인하지 못했다고 표현한다.
- 현재 실행되는 legacy 사이드바에도 생성/조절 완료 당시 TDutyDoc을 깊은 복사해 턴별로 보관한다. 현재 표를 참조해 과거 결과가 변하지 않도록 한다.
- 완료 메시지 아래 읽기 전용 축소 표와 전체 표 보기 제공. 미리보기는 현재 표를 변경하거나 확정하지 않는다. 실패에는 결과 스냅샷을 만들지 않는다.
- 테스트: 서버 예외 분류와 reason 전달, 웹 문구 매핑, 완료/실패 및 이후 편집에 대한 스냅샷 독립성.
- 로컬 수정 및 검증만 수행. push/PR/develop 반영 없음.

## 검증
- 웹 관련 테스트 93개(실패/스냅샷/레거시 대화 42개 + 대화 사이드바 51개), TypeScript 및 Vite test-mode 빌드 통과.
- 서버 관련 테스트 86개 및 bootJar 통과. 스키마 변경 없음.
- 레거시 대화의 스냅샷은 해당 대화가 유지되는 동안 보관하며, 페이지 재접속 이력 저장은 기존 대화 API 경로에서 담당한다.

## 실제 화면에서 추가 확인한 문제
- 실행 결과 반영으로 로컬 revision이 바뀌는 순간 자동저장이 서버 revision 갱신보다 먼저 실행돼 400 오류를 표시했다. 실행 중 자동저장을 보류하고 refresh 완료 후 동기화하도록 변경한다.
- 결과 미리보기 조회에도 생성 진행 모달이 표시됐다. 내부 busy와 실제 실행 상태를 분리하여 읽기 작업에는 생성 진행을 표시하지 않는다.

- 개발 DB 연결 로컬 테스트: 2026년 10월 복사 병동에서 재생성 완료, 완료 후 오류 없음, 결과 스냅샷 열기 확인. 근무표 미확정.

조절이 성공했어도 바뀐 칸이 0개인 경우에는 완료 카드 아래에 기존 공통 문구 “이번에는 바뀐 근무가 없어요.”를 표시한다. 최적이라는 의미로 해석하지 않으며, 실제 변경이 있거나 적용되지 않은 결과에는 이 안내를 표시하지 않는다.
