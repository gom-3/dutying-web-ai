# 근무표 작성 단계 고정/AI 자동채우기 UX 개선안

## 1. 문제 정의

현재 근무표 만들기 흐름에는 `고정 근무`를 입력하는 단계와 `AI 자동채우기`를 실행하는 단계가 분리되어 있다.

이 구조는 "AI를 돌리기 전에 미리 확정된 근무를 입력한다"는 관점에서는 명확하지만, 실제 사용자 작업 방식과는 어긋나는 부분이 있다.

사용자는 고정을 꼭 AI 실행 전에만 하지 않는다.

- AI를 돌리기 전에 반드시 들어가야 하는 근무를 고정하고 싶을 수 있다.
- AI가 만든 결과 중 마음에 드는 일부 칸을 고정하고 다시 생성하고 싶을 수 있다.
- 직접 몇 칸 짜보다가 마음에 안 들어서 AI에게 새로 맡기고 싶을 수 있다.
- 직접 수정한 칸을 다음 생성에서도 유지하고 싶을 수 있다.

즉, 사용자 입장에서 `고정`은 별도 단계에서 한 번 처리하는 일이 아니라, 근무표를 작성하면서 계속 발생하는 행동이다.

## 2. 핵심 판단

`고정`과 `잠금`을 분리하지 않는다.

사용자 입장에서는 둘 다 결국 같은 의미다.

> AI가 이 칸은 바꾸지 않게 해줘.

따라서 기존처럼 4단계에서는 `고정근무`, 5단계에서는 `잠금`처럼 나누면 개념이 중복된다. 사용자는 "고정과 잠금이 뭐가 다르지?"를 이해해야 하고, 제품은 같은 목적의 기능을 두 곳에서 설명해야 한다.

최종적으로는 기존 `고정 근무` 단계를 없애고, 근무표 작성 화면 안에서 고정, 자동채우기, 다시 생성, 확정을 모두 처리하는 흐름이 더 자연스럽다.

## 3. 추천 단계 구조

기존 흐름:

1. 근무자 확인
2. 제약조건
3. 신청 근무 확정
4. 고정 근무
5. 근무표 작성하기
6. 확정 근무표

추천 흐름:

1. 근무자 확인
2. 제약조건
3. 신청 근무 확정
4. 근무표 작성하기
5. 확정 근무표

기존 4단계 `고정 근무`는 제거한다.  
기존 5단계 `근무표 작성하기` 안에 고정 기능을 흡수한다.

문서에서는 혼선을 줄이기 위해 이 화면을 `근무표 작성 단계`라고 부른다.

## 4. 근무표 작성 단계의 역할

근무표 작성 단계에서 사용자는 다음을 모두 할 수 있어야 한다.

- 직접 근무 입력
- 선택한 칸 고정/고정해제
- 신청근무 확인
- AI 자동채우기
- AI 결과 다시 생성
- 마음에 드는 AI 결과 일부 고정
- 스냅샷 저장/불러오기
- 최종 확정

이 화면은 단순한 자동채우기 실행 화면이 아니라, 사용자가 AI와 함께 근무표를 다듬는 작업 공간이다.

## 5. 셀 상태 정의

근무표 작성 단계의 셀은 다음 상태를 가진다.

### 5.1 신청근무

간호사가 신청했고 관리자가 수락한 근무다.

- 화면 진입 시 자동으로 고정 상태처럼 표시한다.
- AI가 바꾸면 안 된다.
- 이 화면에서는 일반 고정해제 대상이 아니다.
- 변경이 필요하면 신청근무 확정 단계로 돌아가 수정하는 것이 더 명확하다.

### 5.2 사용자 고정

관리자가 근무표 작성 단계에서 직접 고정한 칸이다.

- AI가 바꾸면 안 된다.
- 사용자가 언제든 고정/고정해제할 수 있다.
- AI 실행 전에도 고정할 수 있고, AI 결과를 보고 나서도 고정할 수 있다.

### 5.3 직접 입력

사용자가 직접 값을 넣었지만 아직 고정하지 않은 칸이다.

- 보호 대상이 아니다.
- 다만 사용자 의도가 애매하므로 자동채우기나 다시 생성 전에 확인이 필요할 수 있다.
- 사용자가 유지하고 싶다면 고정해야 한다.

### 5.4 AI 배정

AI가 생성한 칸이다.

- 다시 생성 시 바뀔 수 있다.
- 마음에 들면 사용자가 고정할 수 있다.

### 5.5 빈칸

아직 근무가 배정되지 않은 칸이다.

- 자동채우기의 기본 대상이다.

## 6. AI가 바꾸면 안 되는 것

AI가 항상 유지해야 하는 셀:

- 신청근무
- 사용자 고정 칸

AI가 바꿀 수 있는 셀:

- 빈칸
- AI 배정 칸
- 사용자가 유지하지 않겠다고 선택한 직접 입력/직접 수정 칸
- 고정하지 않은 일반 칸

확인이 필요한 셀:

- 첫 자동채우기 전, 사용자가 직접 입력했지만 고정하지 않은 칸
- AI 생성 이후, 사용자가 직접 수정했지만 고정하지 않은 칸

핵심 원칙:

**직접 입력은 보호 대상이 아니라 확인 대상이다. 보호 대상은 신청근무와 사용자 고정뿐이다.**

## 7. 기본 사용자 흐름

### 7.1 처음 근무표 작성 단계에 들어온 경우

사용자는 화면에서 신청근무가 이미 표시된 상태를 본다.

필요하면 직접 몇 칸을 입력하고, 진짜 유지해야 하는 칸은 고정한다.

그 다음 `자동 채우기`를 누른다.

### 7.2 AI 결과를 받은 경우

AI가 근무표를 채운다.

사용자는 결과를 검토한다.

- 마음에 드는 칸은 고정한다.
- 마음에 들지 않는 칸은 직접 수정한다.
- 전체 방향이 별로면 다시 생성한다.

### 7.3 다시 생성하는 경우

`다시 생성`은 신청근무와 사용자 고정 칸만 유지하고 나머지를 새로 생성한다.

단, 사용자가 직접 수정했지만 고정하지 않은 칸이 있으면 유지할지 버릴지 확인한다.

## 8. 버튼 동작

### 8.1 첫 실행 전: `자동 채우기`

근무표 작성 단계에 처음 들어왔을 때 메인 버튼은 `자동 채우기`로 표시한다.

#### 직접 입력한 칸이 없을 때

바로 실행한다.

동작:

- 신청근무 유지
- 사용자 고정 칸 유지
- 빈칸 AI 채움

#### 직접 입력했지만 고정하지 않은 칸이 있을 때

확인 모달을 띄운다.

문구 예시:

> 직접 입력한 근무 6칸이 있어요.  
> 이 칸을 고정하고 채울까요, 아니면 비우고 새로 생성할까요?

선택지:

- `고정하고 채우기`
- `비우고 새로 생성`

동작:

- `고정하고 채우기`: 직접 입력한 칸을 사용자 고정으로 전환한 뒤, 신청근무와 고정 칸을 유지하고 나머지를 AI가 채움
- `비우고 새로 생성`: 직접 입력한 칸을 비우고, 신청근무와 기존 사용자 고정 칸만 유지한 채 AI가 생성

이유:

첫 자동채우기 전의 직접 입력은 기준점일 수도 있고 실패한 초안일 수도 있다. 제품이 조용히 유지하거나 조용히 삭제하면 둘 중 한 사용자 의도를 놓친다.

### 8.2 AI 실행 후: `다시 생성`

한 번 AI가 생성한 뒤에는 메인 버튼을 `다시 생성`으로 바꾼다.

기본 동작:

- 신청근무 유지
- 사용자 고정 칸 유지
- 나머지 칸 새로 생성

#### AI 이후 직접 수정했지만 고정하지 않은 칸이 있을 때

확인 모달을 띄운다.

문구 예시:

> 직접 수정한 근무 8칸이 있어요.  
> 이 칸을 고정하고 다시 생성할까요?

선택지:

- `고정하고 다시 생성`
- `수정한 칸도 다시 생성`

동작:

- `고정하고 다시 생성`: 직접 수정한 칸을 사용자 고정으로 전환한 뒤, 신청근무와 고정 칸을 유지하고 나머지를 새로 생성
- `수정한 칸도 다시 생성`: 직접 수정한 칸도 포함해, 신청근무와 기존 사용자 고정 칸만 유지하고 새로 생성

이유:

직접 수정한 칸도 의도가 애매하다. 사용자가 마음에 들어서 바꾼 것일 수도 있고, 만져보다가 전체를 다시 뽑고 싶은 것일 수도 있다. 따라서 다시 생성으로 인해 사라질 수 있을 때만 확인한다.

## 9. 보조 액션

메인 버튼 옆 작은 메뉴에는 보조 기능을 둔다.

- `빈칸만 채우기`
- `고정 제외 다시 생성`
- 추후 확장: `선택 영역 다시 생성`

단, 이 메뉴는 보조 기능이다. 기본 흐름은 메인 버튼 하나로 충분히 이해되어야 한다.

## 10. 화면 구성 제안

### 10.1 셀 고정/고정해제

셀을 선택하면 툴바 또는 셀 메뉴에서 `고정`을 누를 수 있게 한다.

추천 액션:

- 선택 칸 고정
- 선택 칸 고정해제
- 선택 범위 고정
- 선택 범위 고정해제

### 10.2 고정 표시

고정된 칸은 핀 아이콘 또는 고정 배지를 표시한다.

신청근무는 별도 색상/아이콘으로 구분한다.

- 신청근무: 신청근무 표시 + 자동 보호
- 사용자 고정: 고정 표시 + 사용자가 해제 가능

### 10.3 고정만 보기

보조 도구로 `고정만 보기`를 제공한다.

사용자는 AI가 절대 바꾸지 않을 칸만 빠르게 확인할 수 있다.

### 10.4 안내 문구

자동채우기 버튼 주변에는 짧은 안내만 둔다.

문구 예시:

> AI가 바꾸면 안 되는 근무는 고정해 주세요.

긴 설명은 튜토리얼이나 도움말로 분리한다.

## 11. 예시 시나리오

### 예시 1. 반드시 들어가야 하는 근무를 먼저 고정하고 자동채우기

상황:

- 사용자가 근무표 작성 단계에 들어온다.
- A간호사 1일 D, B간호사 3일 N을 입력한다.
- 이 두 칸은 꼭 유지해야 하므로 `고정`한다.
- `자동 채우기`를 누른다.

기대 동작:

- 신청근무는 유지된다.
- A간호사 1일 D, B간호사 3일 N은 유지된다.
- 나머지 빈칸은 AI가 채운다.

이유:

사용자가 직접 고정했으므로 AI가 바꾸면 안 되는 의도가 명확하다.

### 예시 2. 직접 몇 칸 짜보다가 마음에 안 들어 AI에게 맡기는 경우

상황:

- 사용자가 A간호사 1일 D, B간호사 3일 N을 직접 입력한다.
- 하지만 고정하지는 않았다.
- 직접 짜보다가 마음에 안 들어 `자동 채우기`를 누른다.

확인 모달:

> 직접 입력한 근무 2칸이 있어요.  
> 이 칸을 고정하고 채울까요, 아니면 비우고 새로 생성할까요?

사용자가 `비우고 새로 생성`을 선택하면:

- 직접 입력한 두 칸은 비워진다.
- 신청근무와 기존 고정 칸만 유지된다.
- AI가 새로 생성한다.

이유:

직접 입력은 실패한 초안일 수 있으므로 무조건 유지하면 안 된다.

### 예시 3. 직접 입력한 칸을 기준으로 AI에게 채우게 하는 경우

상황:

- 사용자가 몇 칸을 직접 입력한다.
- 고정하지 않은 상태로 `자동 채우기`를 누른다.
- 모달에서 `고정하고 채우기`를 선택한다.

기대 동작:

- 직접 입력한 칸은 사용자 고정으로 전환된다.
- 신청근무와 고정 칸은 유지된다.
- 나머지는 AI가 채운다.

이유:

사용자가 "이걸 기준으로 채워줘"라는 의도를 선택으로 명확히 표현했다.

### 예시 4. AI 결과 중 마음에 드는 일부만 고정하고 다시 생성

상황:

- AI가 근무표를 생성한다.
- 사용자가 C간호사 10일 N, D간호사 11일 O가 마음에 든다.
- 두 칸을 고정한다.
- `다시 생성`을 누른다.

기대 동작:

- 신청근무는 유지된다.
- 고정한 두 칸은 유지된다.
- 나머지 AI 결과는 새로 생성된다.

이유:

사용자는 AI 결과 중 좋은 부분을 고정해가며 더 나은 근무표에 접근할 수 있다.

### 예시 5. AI 결과를 직접 수정한 뒤 다시 생성

상황:

- AI 자동채우기를 실행한다.
- 사용자가 몇 칸을 직접 수정한다.
- 다시 생성하고 싶어진다.
- 수정한 칸은 고정하지 않았다.

확인 모달:

> 직접 수정한 근무 8칸이 있어요.  
> 이 칸을 고정하고 다시 생성할까요?

선택지:

- `고정하고 다시 생성`
- `수정한 칸도 다시 생성`

기대 동작:

- `고정하고 다시 생성`: 직접 수정한 칸을 고정으로 전환하고 나머지를 다시 생성
- `수정한 칸도 다시 생성`: 직접 수정한 칸도 버리고 신청근무와 기존 고정 칸만 유지해 다시 생성

이유:

직접 수정한 칸은 유지 의도가 명확하지 않다. 다시 생성 전에 사용자가 선택해야 한다.

## 12. 기대 효과

- 고정과 잠금 개념이 중복되지 않는다.
- 사용자는 고정을 AI 전/후로 나누어 생각하지 않아도 된다.
- 직접 짜보다가 AI에게 넘기는 흐름이 자연스럽다.
- AI 결과 중 좋은 부분만 고정하고 반복 생성할 수 있다.
- 별도 고정근무 단계가 사라져 전체 근무표 만들기 흐름이 짧아진다.
- 모달은 의도가 애매한 직접 입력/수정이 사라질 수 있을 때만 나타나므로 피로도가 낮다.

## 13. 주의할 점

고정 기능을 근무표 작성 화면에 흡수하면 화면의 역할이 커진다. 따라서 UI가 복잡해지지 않게 해야 한다.

주의사항:

- 고정 기능은 셀 선택 시 자연스럽게 노출한다.
- 기본 화면은 자동채우기와 확정 중심으로 단순하게 유지한다.
- 고정만 보기, 일괄 고정해제 같은 기능은 보조 도구로 둔다.
- 신청근무와 사용자 고정은 시각적으로 구분한다.
- 직접 입력한 칸을 자동으로 고정하지 않는다.

## 14. 최종 결론

사용자 입장에서 `고정`은 별도 단계에서 미리 끝내는 일이 아니라, 근무표를 만들면서 계속 발생하는 행동이다.

따라서 기존 4단계 `고정 근무`는 제거하고, 근무표 작성 단계 안에서 고정, 자동채우기, 다시 생성, 확정을 모두 처리하는 방향이 더 좋다.

최종 원칙:

**AI가 바꾸면 안 되는 칸은 사용자가 근무표 작성 화면에서 직접 고정한다. 직접 입력은 보호 대상이 아니라 확인 대상이며, 보호 대상은 신청근무와 사용자 고정뿐이다.**
