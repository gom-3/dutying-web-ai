# 토스 정기결제 심사 경로 보완

## 범위

- 첨부된 토스 정기결제 가이드의 상품·환불·사업자정보·이메일 로그인·상품선택·정기결제 동의·토스 카드등록 경로를 실제 구현과 대조한다.
- 기존 Plus 월 구독, 1회 결제당 1개월, 카드 1회 100만원 상한, Hospital 계좌이체 구분을 유지한다. 이미 게시된 정책과 기존 계약을 임의 수정하지 않는다.
- 대표 상품 금액과 제공량은 서버의 게시된 정책에서 읽는다. 정책 미설정 시 임의 가격을 표시하거나 결제를 열지 않는다.
- 사업자정보는 사용자에게 현 코드 값이 맞음을 확인받았다. 심사 URL은 https://dev.dutying.ai 를 사용한다. 심사용 이메일·비밀번호 계정은 사용자가 준비한다.
- 결제 실패·취소·불확실 상태에서 새 승인이나 중복 청구를 만들지 않도록 SDK·복귀 경로와 서버 상태 검증을 보완한다.
- 심사용 PPT는 실제 화면 원본을 사용한다. URL과 PC 시각이 함께 보이지 않거나 PG 창·로그인 후 단계가 미캡처된 자료는 제출용 완료본으로 표시하지 않는다.
- 회신 메일은 로컬 초안으로 작성하고 확인되지 않은 계정·금액·설정·첨부 완료 사실을 만들지 않는다.

## 초기 관찰

- 2026-10-23 dev 공개 안내 3개 경로는 HTTP 200, 실제 pricing 화면은 요금 불러오기 실패를 표시한다.
- dev `/commercial/offer`: HTTP 503 `POLICY_NOT_CONFIGURED`, `X-App-Version: 5a0632c`. `/readyz`: HTTP 200 `UP`.
- 공개 응답으로 토스 TEST 키 존재 여부를 알 수 없다. 현 작업 호스트의 `dutying-dev-server` SSH alias는 해석되지 않는다. 실행 문서만으로 설정 완료를 판단하지 않는다.

## 검증

정책 변경에 따른 기본 인원·견적 표시, 비정상 응답·잘못된 callback·SDK 실패, 정상 카드 인증 후 첫 청구와 적용, 중복 확인·해지·환불·갱신 경합을 관련 테스트로 확인한다. 가상 PG 자동 테스트와 실제 TEST PG 실행 결과는 분리해 기록한다. DB 구조·비밀 설정·LIVE 결제·외부 배포는 임의로 변경하지 않는다.

## 결과

- 서버 최종 회귀 338개, 프런트 370개, 공개 점검기 6개 테스트 통과. 서버 bootJar 및 프런트 타입 검사·빌드 통과.
- 인원별 금액 계산·최소 인원 오류·390px 모바일 넘침을 실제 컴포넌트의 합성 정책 미리보기에서 확인했다. 미리보기는 결제 불가와 심사 증빙이 아님을 표시했고 종료했다.

- 담당자 전달 문구, 토스 회신 초안 및 실제 공개 화면3개를 포함한9장 PPT 초안을 `../output/toss-review-2026-10-23`에 작성했다.

- PPT는 실제 구매·PG 경로와 URL/PC시각 동시 원본 캡처가 남은 제출 전 초안이다. 완료본이나 실제 거래 성공 증빙으로 취급하지 않는다.
