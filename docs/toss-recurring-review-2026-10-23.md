# 토스 정기결제 심사 경로 보완

## 현재 진행 · 2026-11-22

- 사용자 결정: 토스 계약을 유지하고 결제 도입을 계속한다. 11월 18일의 해지·가입비 환불 요청은 현재 작업 방향이 아니다. 계약팀의 실제 처리 상태를 확인한 것으로 해석하지 않는다.
- 추가로 확인한 메일 근거: 10월 28일 필수질문 답변·심사 계정·결제경로 PPT를 토스에 이미 발송했다. 10월 29일 온보딩팀은 1개월 이내 제공·건당 100만원 이하·D+5 영업일 정산·월 정산한도 1,000만원 등의 조건과 후속 카드사 심사 일정을 안내했다. 해당 MID의 전자결제 계약 완료 통보 메일도 실제 카카오메일에서 확인했다. 과거 문서의 ‘최초 제출 미완료’를 현재 상태로 사용하지 않는다. 로그인 정보는 문서에 옮기지 않는다.
- 현재 우선순위는 재제출이 아니라 상점관리자 `계약·운영 → 이용정보 → 결제·부가서비스 → 이용카드사`의 현재 카드사별 승인 상태 확인이다. 과거 계약 완료 메일만으로 현재 카드사 승인·LIVE 이용 가능·정산 가능 상태까지 단정하지 않는다. 추가 자료는 토스가 보완 또는 변경 안내를 요구한 경우 준비한다.
- 개발계 공개 상품은 `ready=true`, 월 19,900원·기본 50명·추가 1명 990원이며 약관은 `plus-ai-fill-monthly-2026-11-12`다. 실제 Chrome 상품 화면과 로그인 후 테스트 병동의 구독 화면에서 AI 채우기 월 30회·통합 요금 확인/카드 등록 단계를 확인했다.
- 개발계 `/billing`, `/billing/billing-return`, `/billing/payment-return` 직접 접속은 HTTP 404다. 기존 SPA 내부 이동으로 구독 화면은 열리지만 새로고침·공개 신청 링크·카드 인증 후 복귀는 별도 HTTP 진입이므로 정상 경로로 간주하지 않는다.
- 원인: React 라우터에는 `/billing/*`가 있으나 정적 HTML 별칭과 Cloudflare `_redirects`가 이전 `/workspace/*`만 포함한다. 현재 수정은 결제 진입/복귀 HTML 3개와 `/billing/*` 앱 셸 연결을 추가하며 기존 `/workspace` 계약을 보존한다. CI에서 실제 빌드 산출물의 진입/복귀 경로도 검사한다.
- 공개 점검기는 새 약관을 기본으로 검사하고 로그인·결제 진입·PG 복귀 URL을 함께 확인한다. 과거 릴리스는 `--terms-version`으로 정확한 약관 버전을 지정해야 하며 임의 버전을 허용하지 않는다.
- 최신 develop의 Web CI 테스트는 성공했지만 Cloudflare 배포 확인 단계는 실패했다. 배포 연결·정확한 배포 커밋 및 공개 URL 반영을 확인하기 전에는 경로 복구 완료로 표시하지 않는다.
- 수정 반영: [PR #214](https://github.com/gom-3/dutying-web-ai/pull/214), develop `a0a01b8a55fdaae71b8f6cc06758a5c2e23504ef`. PR CI는 4,351개 통과·3개 skip이며 dev CI도 테스트·빌드·경로 산출물 검사는 통과했다. [dev 배포 실행](https://github.com/gom-3/dutying-web-ai/actions/runs/45019775708)은 Cloudflare의 해당 커밋 공개 반영을 확인하지 못해 실패했다. 재조회에서도 결제 진입/복귀 3개 URL은 404다. CI가 검증한 동일 커밋의 배포 ZIP을 확보했으며, 홈페이지에 반영 완료됐다고 표시하지 않는다.
- 현재 화면으로 갱신한 PPT는 내부 변경 검토본이며 이미 제출한 자료를 자동으로 대체하거나 재발송하지 않는다. 추가 제출이 필요하면 경로 수정의 dev 반영 뒤 URL·실제 PC 시계 원본과 현재 유효한 심사 계정을 확인한다. 과거 TEST 승인·환불 성공은 서버의 `docs/toss-dev-test-readiness-2026-10-23.md`에 기록돼 있으며 이번 작업에서 새 카드 등록·결제·환불·메일 발송은 실행하지 않았다.
