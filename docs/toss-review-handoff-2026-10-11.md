## 남은 순서 (사용자·서버 담당자)

역할별 간단 안내와 배포 후 자동 점검 명령은 [dev 다음 작업 안내](toss-dev-next-steps-2026-10-11.md)를 참고하세요. CI/CD는 기존 담당자가 진행합니다.

1. 서버·프런트 브랜치를 리뷰하고 dev에 함께 배포합니다. DBA는 서버 `docs/toss-billing-dba-handoff-2026-10-11.md`대로 선행 스키마를 확인합니다. 신규 DDL은 없습니다.
2. 토스 개발자센터에서 **빌링용 테스트 clientKey/secretKey 및 해당 MID**를 서버 비밀 설정에 넣습니다. 실거래 MID는 `bill_dutyic46q`입니다. secretKey를 프런트 env나 문서에 넣지 마세요.
3. 서버 설정을 아래처럼 맞추고, 실제 활성 Plus 정책·공개 정보 확인 후 `commercial.review-ready`를 true로 바꿉니다. 이 값의 기본값은 false입니다. 배포만으로 결제를 열지 않습니다.
4. 심사용 이메일·비밀번호 계정을 일반 회원가입으로 만들고 가상 간호사만 포함한 병동 OWNER로 둡니다. 소셜 전용 계정 불가. 이메일 재인증이 있으므로 심사 중 코드 확인 가능 방법을 담당자와 조율하세요. 인증을 우회하는 계정은 만들지 않습니다.
5. 테스트 카드 등록 → 첫 결제 → Plus 적용/원장 → 중복 확인 → 해지 → 환불 → 실패/재조회까지 확인합니다. 결제 키가 URL/로그/캡처에 남지 않았는지도 확인합니다.
6. HTML에 실제 화면을 넣고 ‘캡처 포함 HTML 저장’을 누른 뒤 PPT로 변환합니다. 현재는 캡처를 기다리는 초안이며 PG 테스트 성공 증빙이 아닙니다. 로컬 HTML의 브라우저 미리보기는 보안 정책으로 확인하지 못했습니다.
7. 토스 담당자에게 dev URL 심사 허용 여부를 확인하고 URL·테스트 계정·PPT를 회신합니다. 심사 후 운영 도메인·LIVE 키/환경으로 별도 전환합니다. 운영에서 테스트 키와 실고객 데이터를 혼용하지 마세요.

서버 설정 예시(실제 비밀 값은 서버 전용 보안 설정으로 전달):

```yaml
commercial:
  enabled: true
  public-url: https://dev.dutying.ai
  terms-version: plus-monthly-2026-10-11
  review-ready: false # 공개 정보/정책/테스트 환경 준비 확인 후 true
  checkout:
    enabled: true
  payment:
    provider: TOSS
    recurring-enabled: true
    toss:
      merchant-id: <테스트 키의 MID 확인>
      client-key: <test 클라이언트 키>
      secret-key: <test 시크릿 키>
operations:
  enabled: true
  environment: TEST
  financial-terms-approved: true
  secret-key: <기존 암호화 키 유지 또는 최초 보안 생성값>
```

프런트는 `VITE_SERVER_URL`을 같은 dev API, `VITE_APP_PUBLIC_URL`을 `https://dev.dutying.ai`로 맞춥니다. `VITE_SELLER_*`를 사용하면 전달된 공개 사업자정보를 덮어쓸 수 있습니다. 주소 등 필수값이 비어 있으면 구독 시작을 열지 않습니다.

## 운영 환불 담당자

현재 `/admin/operations/page`는 병동 요금·사용량 화면이며 아래 환불 변경안 UI는 연결되어 있지 않습니다. 서버의 직원 세션/승인 API로 검증하는 방법과 남은 UI 제약은 [설정·결제 검증 통합 문서](toss-dev-setup-and-payment-test-2026-10-11.md)의 2절·6절을 따르세요.

온라인 접수는 고객이 결제 → 환불·정산 문의에서 청구서를 선택합니다. 운영 관리에서 `SUBSCRIPTION_REFUND` 변경을 작성·승인할 때 다음 payload를 사용합니다. 유료 기능 전체 사용 여부는 담당자가 확인하고 근거를 변경 사유에 남깁니다.

```json
{
  "invoiceId": "원 청구서 ID",
  "paymentId": "원 승인 이벤트 ID",
  "gross": 19900,
  "policyEvidenceRef": "CUSTOMER_REQUEST:접수 ID",
  "paidFeaturesUnused": true
}
```

메일/전화 접수라면 `policyEvidenceRef`를 `EMAIL:문의 증빙 ID` 또는 `PHONE:상담 증빙 ID`로, `requestedAt`을 실제 접수시각 UTC(`2026-10-11T03:00:00` 예시)로 추가합니다. 과거 계약은 기존 정책을 유지합니다. 환불액은 새 정책의 최소 금액 이상이어야 하며, 법정 권리상 더 유리한 환불은 원결제 잔액 내에서 가능합니다. 요청을 등록하는 것만으로 자동 환불되지는 않습니다. 운영 승인 후 PG 취소 결과까지 대조합니다.
