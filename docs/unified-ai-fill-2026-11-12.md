# AI 채우기 정책 통합

- 기능명: **AI 채우기**. 계량: **AI 채우기 횟수**, 단위 **회**.
- Plus 기본 제공: **월 30회**. 처음 채우기·다시 채우기·수정 요청은 같은 잔액을 사용한다.
- Free/Hospital은 기존 기본 생성 제공량을 통합 제공량으로 사용한다. 이전 기본 조정 제공량을 합산해 추가 지급하지 않는다.
- 추가 상품은 기존 생성 팩의 수량/가격을 사용한 단일 AI 채우기 팩이다. 과거에 구매한 조정 팩의 잔액은 서버에서 보존한다.
- 사용량·사이드바·요금제·최초 결제·병원 계약 화면·추가 문의·약관·AI 작성 화면 용어를 통일한다.

## 실행과 배포

- 웹 실행은 `/schedule/v2/autofill`, 사용량은 `/admin/commercial/v2/scopes/{type}/{ref}/entitlements`, 여러 팀 실행은 `/admin/commercial/v2/wards/{ward}/ai-batches`를 사용한다.
- 이전 실행 API도 요청 형식을 유지하며 통합 차감으로 연결한다. 동일 요청 키의 이전 결과/예약은 재사용하여 이중 차감을 막는다.
- 서버를 먼저 반영한다. 새 경로가 없는 서버로 자동 후퇴해 분리 잔액을 차감하지 않는다.
- 신규 구독 약관 버전은 `plus-ai-fill-monthly-2026-11-12`다. 서버의 `COMMERCIAL_TERMS_VERSION` 명시 설정과 웹 버전을 함께 맞춘다. 기존 주문과 동의 기록은 다시 쓰지 않는다.
- 카드로 중도 증원/추가 팩을 직접 구매하는 기능은 이번 범위에 포함되지 않는다. 기존 견적→문의 접수 흐름을 유지한다.

## 검증 기록

- 상품·결제·사용량 프런트엔드 회귀 498개 통과. 추가로 혼합 차감/구매 잔액 보존/이전 API 재시도/제한 계승을 백엔드 98개 테스트로 검증했다.
- 대화 UI 확대 회귀에서는 261개 통과, 11개 실패. 실패 항목은 기존 확인 단계 버튼/질문에 관한 기대값이다. 새 명령 인식 로직을 이전 인식 로직으로 바꾼 테스트 전용 비교에서도 동일한 11개가 실패했다. 실제 대화 입력·검토 컴포넌트 소스는 이번 작업에서 수정하지 않았다.
- 비교 결과: `/private/tmp/dutying-ai-fill-editor-recheck.json`, `/private/tmp/dutying-ai-fill-previous-parser-tests.json`.
- 이 기록은 운영 배포 완료를 뜻하지 않는다.

## CI 후속 검증

- 이전 확인 단계 기대값 11건을 현재 요청 계약에 맞게 수정했다. 단순 RULE/KNOB 요청은 마지막 적용 동의만 받고, 해석된 우선순위와 월 범위를 보존한다. TEAM 힌트만으로 반복 적용하거나 SOFT를 HARD로 승격하지 않는다.
- 추가 질문이 필요한 GOAL에서는 제안 거절, 답변 재수정, 뒤따르는 답변 초기화, 완료 전 적용 차단을 계속 검증한다. 일본어 명시적 동의·거절도 유지한다.
- 변경한 대화 UI 및 검토 모델 테스트 71건과 타입 검사가 통과했다. 서비스 코드와 사용자 흐름은 변경하지 않았다.
