# 월별 휴무 조건 통합과 검증된 복구 (2026-10-27)

목표: 별도 개인 월 목표 UI/저장 경로를 기존 제약조건으로 통합하고, 원본 설정과 근무표를 보존한 채 우선순위 생성 또는 검증된 예외 후보를 제시한다.

## 데이터와 호환
- 기존 `nurse_monthly_rest_policy` 행은 삭제/수정하지 않는다. 다음 Flyway versioned 데이터 migration이 해당 값을 `SHIFT_COUNT_PER_PERIOD` 일반 규칙으로 복사한다. OFF/연차/0일/해당 월/간호사/일반 EXACT·야간전담 MIN을 보존한다. 복잡한 JSON과 전담 판정을 손실 없이 검증하기 위해 JDBC Java migration을 사용한다. 새 테이블/필수 DTO 필드는 없다.
- 일반 규칙 params의 `monthScope={year,month}`가 적용 월을 결정한다. 월이 없는 기존 규칙은 계속 상시 적용한다. 월이 있는 규칙은 다른 월 생성/조회/벌크 저장에 섞이거나 삭제되지 않는다.
- 기존 개인 정책 API는 호환 어댑터로 유지하되 일반 규칙만 읽고 수정한다. 기존 테이블을 다시 생성 원본으로 읽지 않으며 이중 적용하지 않는다. 권한·버전 검사를 유지한다.
- 기본 월 휴무 목표 대체와 명시적 휴무 배정 허용 의미는 이관된 규칙에서 동일하게 해석한다. 연차 잔액/확정본/고정·승인 배정은 수정하지 않는다.

## 생성과 복구
- 기존 공통 솔버의 필수 조건 및 우선순위 목적함수를 재사용한다. SOFT 조건은 원래 우선순위대로 최적화하고 위반을 표시한다. HARD 조건을 임의로 완화해 성공으로 반환하지 않는다.
- HARD 충돌은 공통 bounded 예외 탐색으로 연결한다. 필수 안전·고정·승인 배정·가용 근무·연차 소비는 보호한다. 허용된 OFF 횟수/운영 조건 예외만 복사한 입력에서 탐색한다.
- 후보는 전체 월 완성, 원본 고정·가용성, 남아 있는 모든 필수 조건을 검사한다. Spring도 원래 규칙으로 독립 재검증하며 실제 위반과 변경점을 응답한다. 명시 동의 전 셀/설정 쓰기 없음. 토큰은 입력·사용자·팀·월과 묶고 만료/변경/중복 확인을 검사한다. 동의 시 검증된 캐시 결과를 재사용한다.
- 시간 초과/내부 오류/미검증 제안은 실행 가능한 수정안으로 표시하지 않는다. 임의의 모순 입력에 항상 해가 있다고 약속하지 않는다.

## 화면
- 별도 휴무 모달/개인 정책 PUT를 제거하고 충돌의 설정 수정은 기존 제약조건 모달을 연다. 이관된 조건과 적용 월을 같은 규칙 편집기로 보여준다. 월별 값은 해당 월에만 저장한다.
- 검증된 후보는 원래 조건 중 무엇이 깨지는지와 함께 기존 동의 카드로 표시한다. 저장/취소/동의 후 같은 근무표 대화와 초안을 유지한다.

## 검증
- migration: OFF9+연차2/0, 중복 OFF 유형, 야간전담, 원본 행·근무표 불변.
- 월별 CRUD: 다른 월/상시/다른 간호사 보존, 구 클라이언트 벌크 저장, 권한·오래된 버전, 구 API 왕복.
- 솔버: OFF 목표와 고정·가능 일수 충돌, 전월 꼬리+11월1일 인원 부족, OFF가 근무로 집계되는 재발, 우선순위·공정성, 실제 전체 후보 검증 및 잘못된 후보 차단.
- Spring/웹: 동의 전 미적용, 위반 누락/입력 변경/만료 거절, 같은 후보 확정, 설정 단일 경로 및 대화 보존. 로컬 검사 후 저장소별 develop 반영. 운영 배포는 별도다.

## 반영 순서와 운영 적용 조건
- LLM → Spring → 웹 순서로 배포한다. 월 스코프 규칙을 필터하는 Spring과 OFF SET을 지원하는 웹이 짝을 이룬다. develop 반영 자체는 배포 완료를 뜻하지 않는다.
- V74 실행 직전에는 이전 Spring 인스턴스의 개인 정책 쓰기를 중단하고 진행 중 요청이 끝난 뒤 이관한다. 이관 중 이전 인스턴스가 구 테이블을 갱신하면 복사 시점 이후 값이 빠질 수 있으므로, 이 변경의 첫 배포에서는 두 버전의 쓰기를 겹치지 않는다. 새 인스턴스의 호환 API는 공통 규칙만 갱신한다.
- 이관 후 `flyway_schema_history` version/success, 원본 행 수·값, 이관 규칙 수·월·간호사·연차 0 및 고정 배정을 확인한다. 구 테이블은 보존하며, 원본과 이관 규칙을 동시에 생성 입력으로 쓰지 않는다.

## 확인된 원인과 로컬 결과
- 별도 정책이 음수 ID의 숨은 HARD 규칙으로 컴파일되어 공통 예외 후보(양수 영속 규칙 ID)에서 제외되었다. 개인 휴무 용량 사전 검사도 검증된 동의 후보 탐색으로 이어지지 않았다. 저장 UI를 옮기는 것만으로는 이 단절을 해결하지 못한다.
- 실제 CP-SAT 회귀: 고정 OFF 10일 + OFF 목표 9일 + 연차 2일 입력의 GENERATE/solve-v2 모두 고정 배정을 보존한 OFF10·연차2 완성 후보를 제시했다. 원본 규칙 재검사에서 OFF 규칙만 위반함을 확인했고, 명시 동의 전 적용 응답 셀은 비어 있다. 연차·최대 연속근무·다른 간호사 목표는 완화하지 않았다. 전월 꼬리/11월1일 충돌 및 OFF 근무 집계 오류 회귀도 통과했다.
- Spring 전체 `test --offline` 통과(4분 3초). 최종 제약조건·이관·동의 집중 검사 89개 통과. Flyway 자체 discovery/baseline73→V74 H2 실행 및 재실행 중복 방지 확인. 운영/개발 DB에는 아직 적용하지 않았다.
- LLM 충돌·월 경계·근무/휴무 43개 통과. 월별 수요·휴무·우선순위·균형 확장 검사 167개 통과, 기존 expected failure 1개. 외부 모델/API 호출 없음.
- 웹 근무표 83개 파일/1,069개 검사: 첫 실행 1,066 통과, 월 조회 인자 기대값 1건 수정 및 시간 초과 2건 개별 재검사 통과(24개). 최종 사이드바 150개, 공통 편집/충돌 화면 59개, API 29개 통과. 타입 검사와 production build 통과.
- 합성 근무표 브라우저 검수: 충돌 안내→공통 제약조건→OFF9를10으로 저장→연차2 유지→같은 대화 복귀→바뀐 조건으로 자동채우기 확인 단계까지 확인했다. 원본 표 자동 변경 없음. 브라우저 하네스는 검수 후 제거했다.
