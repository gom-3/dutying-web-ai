# 병동 참가 요청 앱 구현 정리

## 목적

병동 참가 요청 후에도 화면에 `병동 등록하기`가 계속 노출되어, 사용자가 요청 상태를 알기 어려운 문제가 있다.

앱에서는 기존 API를 사용해 병동 참가 요청 상태를 표시하고, 사용자가 직접 요청을 취소할 수 있도록 처리한다.

## 용어 변경

- 기존 문구: `병동 등록하기`
- 변경 문구: `병동 참가하기`

사용자가 병동을 새로 만드는 흐름이 아니라 기존 병동에 참가 요청을 보내는 흐름이므로, 앱 내 문구는 `병동 참가하기`로 통일한다.

## 사용 API

신규 API 요청 없이, 현재 명세에 있는 기존 API를 사용한다.

| 기능 | Method | Endpoint | 설명 |
| --- | --- | --- | --- |
| 병동 코드 검색 | `GET` | `/wards/search?code={wardCode}` | 입력한 병동 코드로 병동 정보를 조회한다. |
| 병동 참가 요청 | `POST` | `/wards/{wardId}/waiting-nurses` | 현재 로그인한 사용자를 해당 병동의 대기 간호사로 추가한다. |
| 본인 대기 병동 조회 | `GET` | `/accounts/waiting` | 현재 로그인한 사용자가 참가 요청 중인 병동을 조회한다. |
| 참가 요청 취소 | `DELETE` | `/wards/{wardId}/waiting-nurses` | 현재 로그인한 사용자의 해당 병동 참가 요청을 취소한다. |

## 화면 상태

### 참가 요청 없음

대기 중인 병동이 없으면 기존 참가 플로우를 보여준다.

```text
병동 참가하기
```

이 상태에서는 사용자가 병동 코드를 입력하고 참가 요청을 보낼 수 있다.

### 참가 요청중

`GET /accounts/waiting` 응답으로 대기 중인 병동 정보가 내려오면, `병동 참가하기` 버튼 대신 요청중 상태를 보여준다.

```text
참가 요청중

{병동코드}
요청 취소
```

- `{병동코드}`는 `GET /accounts/waiting` 응답의 `code` 값을 사용한다.
- `요청 취소`를 누르면 `DELETE /wards/{wardId}/waiting-nurses`를 호출한다.
- 취소 성공 후에는 다시 `GET /accounts/waiting`을 조회하거나 로컬 상태를 초기화해 `병동 참가하기` 상태로 되돌린다.

## 앱 플로우

1. 병동 참가 화면 진입 시 `GET /accounts/waiting`을 먼저 호출한다.
2. 대기 병동이 있으면 `참가 요청중` UI를 표시한다.
3. 대기 병동이 없으면 `병동 참가하기` UI를 표시한다.
4. 사용자가 병동 코드를 입력하면 `GET /wards/search?code={wardCode}`로 병동 정보를 조회한다.
5. 조회된 `wardId`로 `POST /wards/{wardId}/waiting-nurses`를 호출해 참가 요청을 보낸다.
6. 참가 요청 성공 후 `GET /accounts/waiting`을 다시 호출해 요청중 UI로 전환한다.
7. 사용자가 `요청 취소`를 누르면 `DELETE /wards/{wardId}/waiting-nurses`를 호출한다.
8. 요청 취소 성공 후 다시 `병동 참가하기` UI로 전환한다.

## 상태 처리 기준

### `GET /accounts/waiting` 성공 + 병동 정보 있음

요청중 상태로 처리한다.

사용할 주요 필드:

| 필드 | 사용처 |
| --- | --- |
| `wardId` | 요청 취소 API 호출 |
| `code` | 화면의 `{병동코드}` 표시 |
| `name` | 필요 시 병동명 표시 |
| `hospitalName` | 필요 시 병원명 표시 |

### `GET /accounts/waiting` 결과 없음

참가 요청이 없는 상태로 처리한다.

화면에는 `병동 참가하기`를 표시한다.

### 참가 요청 취소 성공

`DELETE /wards/{wardId}/waiting-nurses`가 성공하면 대기 상태를 제거한다.

이후 화면은 다시 아래 상태가 된다.

```text
병동 참가하기
```

## 주의사항

- 참가 요청을 이미 보낸 상태에서는 `병동 참가하기`가 계속 보이면 안 된다.
- 앱은 `GET /accounts/waiting` 결과를 기준으로 요청중 상태를 복원해야 한다.
- 앱을 재실행하거나 화면을 다시 진입해도 대기 병동이 있으면 `참가 요청중` UI가 보여야 한다.
- 백엔드 신규 API 요청으로 전달하지 않는다. 현재 필요한 API는 명세에 이미 존재한다.
